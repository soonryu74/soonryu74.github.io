# 다시봄(가칭) — 사람 기억 노트 기획안 v0.1

> 작성 서순려 · 2026-09-06 · 브랜치 `claude/people-memory-platform-plan-msibbv`
> 읽기 좋은 버전(기획안): https://claude.ai/code/artifact/2e00875c-bcbf-41fb-af2a-1c6d8b8b9b02

**상대는 모른다. 나만 기억한다. 그래서 무섭지 않다.**

명함 앱은 "OO님이 당신을 등록했습니다"라고 상대에게 알린다. 그 순간 상대는 *기록당했다*고
느낀다. 다시봄은 반대로 간다 — 상대에게 아무것도 보내지 않고, 아무 데도 올리지 않고,
내 기기 안에서만 "다음에 만났을 때 어색하지 않게" 도와준다.

## 1. 요약

- **문제**: 사람을 많이 만나는 사람(교사·영업·자영업·모임장·종교인)은 이름·얼굴·맥락을
  잊는다. 잊은 티가 나는 순간 관계가 식는다. 특히 교사는 1년에 100~300명, 20년이면 수천 명.
- **기존 대안의 한계**: 명함 앱은 *명함 있는 사람*만, *상대에게 알림*이 가고, 데이터가
  *회사 서버*에 쌓인다. 연락처 앱은 메모 칸 하나뿐. CRM은 "관리" 도구라 개인이 쓰기 무겁고
  상대가 알면 불쾌하다.
- **해법**: 만난 직후 30초 기록 → 다시 만나기 전 카드 한 장. 검색은 "지난달 세미나에서
  만난 안경 쓴 분"처럼 *내 기억 방식대로*.
- **핵심 설계 원칙**: **① 상대 알림 없음 ② 서버에 타인 정보 없음(기기 우선) ③ 자동 수집
  없음 ④ 본인이 봐도 괜찮은 메모만** — 이 넷은 기능이 아니라 *약속*이고, 앱 안에 공개한다.
- **수익**: 무료 기본 + 유료(암호화 백업·AI 정리·그룹 무제한). 교사 계정은 무료.
  이 앱 자체가 바이브코딩 강의의 실전 예제가 된다.

## 2. 누가 왜 쓰는가

| 사용자 | 만나는 규모 | 잊어서 생기는 일 | 다시봄이 해주는 것 |
| --- | --- | --- | --- |
| 교사·강사·학원장 | 연 100~300명, 누적 수천 | 졸업생이 찾아왔는데 이름이 안 나옴. 새 학기 첫 주 이름 외우기 고통 | 반·연도별 그룹, 첫 주 이름 익히기 연습, 검색 한 번에 "그때 그 아이" |
| 영업·컨설턴트·프리랜서 | 주 10~30명 | 두 번째 미팅에서 지난 대화 기억 못 해 신뢰 손실 | 미팅 전 카드: 지난 대화·다음에 물어볼 것 |
| 자영업(카페·미용실·공방) | 단골 수백 | 단골 취향·이름을 직원마다 다르게 기억 | 취향 메모, "지난번 주문" |
| 모임장·종교인·동호회 | 회원 수십~수백 | 새 회원 이름·가족 상황 잊음 | 가족·안부 메모, 경조사 기록 |
| 일반인 | 동창회·경조사·이웃 | "누구더라" 반복 | 관계 지도 없이 가벼운 기억 노트 |

공통 심리: **"기억하고 싶은 건 상대를 잘 대하고 싶어서"**다. 관리·추적이 아니다.
이 동기가 제품 톤의 출발점이다.

## 3. 무엇이 사람들을 놀라게 하는가 — 그리고 어떻게 피하는가

"섬뜩함"은 세 가지에서 나온다. 각각을 설계 단계에서 제거한다.

| 놀라는 순간 | 원인 | 다시봄의 선택 |
| --- | --- | --- |
| "내가 등록됐다고 알림이 왔다" | 상대에게 통지 | **통지 기능 자체를 만들지 않는다.** 상대가 앱의 존재를 알 경로가 없다 |
| "내 정보가 어느 회사 서버에 있다더라" | 중앙 저장 | **기기 우선(local-first).** 타인 정보는 사용자 기기와 사용자 *본인 소유* 클라우드(구글 드라이브 앱 폴더 등)에만, 암호화해서. 우리 서버에는 타인 정보를 두지 않는다 |
| "내가 안 준 정보까지 알고 있다" | SNS 크롤링·연락처 자동 매칭·얼굴 인식 | **자동 수집 0.** 사용자가 손으로(또는 말로) 적은 것만. 얼굴 인식·SNS 연동·연락처 스캔은 로드맵에도 없다 |
| "나에 대해 이상한 걸 적어놨다" | 평가·험담·민감정보 | **본인이 봐도 괜찮은 메모 원칙.** 입력 칸 자체가 "특징·대화·다음에 물어볼 것"으로 구성. 건강·종교·정치·성적 지향·주민번호류는 입력 시 차단/경고 |
| "다른 사용자도 나를 검색할 수 있나" | 사용자 간 공유 | **사용자 간 검색·매칭·공유 없음.** 데이터는 사용자별 완전 격리. (팀 공유는 3단계 이후, 그때도 opt-in + 상대 알림 없는 구조로 재검토) |

### 3-1. 앱 안에 공개하는 "약속" 화면 (초안)

> **다시봄이 하지 않는 것**
> 1. 상대에게 알리지 않습니다.
> 2. 여러분이 적은 사람 정보를 우리 서버에 저장하지 않습니다.
> 3. 연락처·SNS·사진에서 아무것도 자동으로 가져오지 않습니다.
> 4. 얼굴을 인식하지 않습니다.
> 5. 다른 사용자가 여러분의 기록을 검색할 수 없습니다.
>
> **다시봄이 하는 것**
> 여러분이 직접 적은 메모를, 여러분 기기 안에서, 다시 만날 때 보여드립니다.

### 3-2. "본인이 봐도 괜찮은가" 원칙

메모를 상대가 어깨 너머로 봤을 때 *"아, 나 기억하려고 적으셨구나"* 로 끝나야 한다.
그래서 입력 칸을 자유 메모 하나로 두지 않고, 다음처럼 *좋은 기억*으로 유도한다.

| 칸 | 예시 | 이유 |
| --- | --- | --- |
| 어디서·언제 | 9/3 노모어매뉴얼 오프라인 모임 | 맥락이 기억의 열쇠 |
| 특징 3개 | 안경, 부산 말투, 캠핑 좋아함 | 얼굴 대신 *단서*로 기억 (사진 없어도 됨) |
| 나눈 이야기 | 노트북LM으로 논문 정리 중 | 다음 만남의 대화 시작점 |
| 다음에 물어볼 것 | 딸 수능 결과 | "기억해줬다"는 감동이 여기서 나옴 |
| 가족·기념일(선택) | 딸 고3 | 안부의 재료 |

없는 칸: 평가·점수·등급·인상. 자유 메모는 있되 기본 접힘.

### 3-3. 사진에 대한 입장

얼굴 사진은 기억에 가장 강력하지만 가장 민감하다. 원칙:

- 사진 첨부는 **선택**이며, 기본은 "특징 3개"로 기억하게 유도한다.
- 사진은 기기 안에 암호화 저장, 얼굴 인식·자동 태깅 없음, 어디로도 전송 안 함.
- 교사용: 학교가 준 학생 사진을 넣더라도 기기 밖으로 나가지 않는다. 졸업 후 N년 자동 정리 제안.

## 4. 핵심 기능 (MVP)

1. **30초 기록** — 만난 직후 위 다섯 칸. 음성으로 말하면 칸에 나눠 넣어줌(4-1 참고).
   명함 사진은 *기기 안에서만* 글자 인식(온디바이스 OCR), 서버 전송 없음.
2. **다시 만나기 전 카드** — 이름 검색 또는 캘린더(선택 연동)에서 만남 감지 →
   "지난번: … / 물어볼 것: …" 카드 한 장. 알림은 *나에게만*.
3. **내 기억 방식대로 검색** — "안경", "부산", "캠핑", "6월 세미나"처럼 단서로 검색.
   이름을 몰라도 찾는다. 이게 연락처 앱과 결정적으로 다른 지점.
4. **그룹** — 학급/기수/모임/거래처 단위. 교사: 2026년 2학년 3반.
5. **이름 익히기 연습(교사 특화)** — 새 학기 첫 주, 특징↔이름 맞추기. 사진이 있으면
   사진↔이름. 본인 기기에서만.
6. **잠금·삭제** — 앱 잠금(생체/PIN), 사람 단위 즉시 삭제, 전체 삭제, "3년 접촉 없음"
   자동 정리 제안. 삭제는 복구 안 됨을 명확히.

### 4-1. AI를 쓰되 타인 정보를 내보내지 않는 방법

말로 한 기록을 다섯 칸으로 정리하는 데 AI가 필요하다. 그러나 "김OO, 부산, 딸 고3"이
외부 API로 나가면 그 자체가 제3자 제공이 된다. 순서대로 채택한다.

| 단계 | 방식 | 타인 정보 외부 전송 |
| --- | --- | --- |
| MVP | 구조화 폼 + 규칙 기반 분리(날짜·장소 자동 추출) | 없음 |
| 2단계 | 온디바이스 모델(브라우저 내장 AI 또는 WebLLM 계열) | 없음 |
| 3단계 | 클라우드 AI는 **이름·연락처를 치환한 뒤** 전송, 사용자 동의 + 사용자 본인 API 키 | 익명화 후 최소 |

## 5. 하지 않을 것 (로드맵에서도 뺀다)

- 상대에게 알림·초대·"당신을 기억하는 사람" 류의 기능
- 공개 프로필, 사용자 간 검색·매칭, 관계 그래프 공개
- 얼굴 인식, SNS 연동, 연락처·통화기록 자동 스캔
- 명함/메모의 서버 저장 (백업은 사용자 소유 클라우드에 암호화)
- 광고 목적 데이터 활용 — 수익은 구독 한 갈래

## 6. 법·윤리 체크 (자문 전 정리, 확정 아님)

- 개인정보보호법은 **개인적·가정적 활동 목적**의 처리에는 대부분 적용되지 않는다
  (제58조 1항). 개인 메모는 이 범주에 가깝다. 다만 **서비스 제공자가 서버에 저장하면**
  제공자는 처리자·수탁자 논쟁에 들어간다 → 기기 우선 구조가 법적으로도 가장 가볍다.
- 교사의 학생 메모는 학교 업무 시스템이 아닌 *개인 기억 보조*로 위치시킨다. 성적·가정형편·
  건강 등 민감 항목은 입력을 막는다. 학교·교육청 지침과 충돌 여부는 베타 교사에게 확인.
- 클라우드 백업을 우리 서버로 제공하려면 종단간 암호화(우리도 못 봄) + 별도 법률 자문 후.
- 출시 전 개인정보 전문가 1회 자문. 이 문서의 법 해석은 자문으로 대체한다.

## 7. 기술 방향

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 형태 | PWA(설치형 웹앱) | 앱스토어 없이 배포, 이 리포(GitHub Pages)에 프로토타입 가능 |
| 저장 | 브라우저 로컬 DB(IndexedDB) + 암호화 | 서버 없음 = 유출 표면 없음 |
| 백업 | 구글 드라이브 앱 전용 폴더 / 파일 내보내기(암호화 zip) | 사용자 소유 저장소 |
| 잠금 | PIN + 기기 생체(WebAuthn) | 분실 대비 |
| OCR·음성 | 브라우저 내장 API 우선 | 기기 밖 전송 없음 |
| 서버 | 없음(MVP). 결제·계정만 최소 | 타인 정보는 절대 서버에 없음 |

Windows/Mac 차이 없음 — 브라우저 기반. 모바일은 홈 화면 추가로 설치.

## 8. 수익 모델

- **무료**: 사람 200명, 그룹 3개, 로컬 저장, 내보내기.
- **유료(월 3,900원 또는 연 29,000원)**: 무제한, 암호화 클라우드 백업, 온디바이스 AI 정리,
  이름 익히기 연습 무제한.
- **교사·강사 인증 시 유료 기능 무료** — 가장 절실한 사용자이자 입소문의 시작점.
- 광고 없음. 데이터 판매 없음. 수익은 구독 한 갈래.
- 부수 효과: 유튜브 "직접 만든 앱" 시연 → 바이브코딩 강의 실전 예제 → 전자책 챕터.

## 10. 기능 추가 전 체크리스트 (앞으로 모든 기능에 적용)

1. 상대가 이 기능의 존재를 알게 되는 경로가 생기는가? → 생기면 만들지 않는다.
2. 타인 정보가 사용자 기기 밖으로 나가는가? → 나가면 익명화·암호화·동의 셋 다 없이는 안 된다.
3. 사용자가 직접 적지 않은 정보를 가져오는가? → 가져오지 않는다.
4. 메모를 본인이 봐도 괜찮은가? → 아니면 입력 칸을 다시 설계한다.
5. 삭제가 한 번에 되는가?
6. 50대도 30초 안에 기록할 수 있는가?
