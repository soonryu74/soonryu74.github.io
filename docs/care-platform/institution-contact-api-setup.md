# 기관 주소·전화 연결 — API 설정 안내

작성: 2026-10-05 · 상태: **미적용.** serviceKey 발급이 필요하다.
3차 지시서 §7-5 에 대한 답이다.

> **왜 아직 못 붙였나** — 평가결과 파일에는 주소·전화가 **없다**(데이터 검수 기록 5절).
> 별도의 OpenAPI 두 곳에 있는데, 둘 다 **활용신청 후 받는 serviceKey** 가 있어야 호출된다.

### ② 국민건강보험공단_장기요양기관 **시설별 상세조회** 서비스

## 2. 🔑 기관기호 연결 — 자릿수가 다르다

| 쪽 | 형식 | 예 |
|---|---|---|
| 평가결과 파일 (우리 DB `ltc_sym`) | **13자**, 하이픈 포함 | `1-11560-00018` |
| OpenAPI `longTermAdminSym` | **11자** | `11156000018` |

**하이픈을 빼면 정확히 11자리가 된다.** 확인한 표본:

| 원본 | 하이픈 제거 | 자릿수 |
|---|---|---|
| `1-11560-00018` | `11156000018` | 11 |
| `2-28200-00749` | `22820000749` | 11 |
| `3-28200-00653` | `32820000653` | 11 |
| `1-46230-00165` | `14623000165` | 11 |

우리 DB 의 27,947행 전부가 13자 고정이고 결측·공백이 0 이므로(데이터 검수 기록 3절), 변환 규칙은 단순하다:

```sql
replace(ltc_sym, '-', '')      -- 1-11560-00018 → 11156000018
```

> **확인하지 못한 것**: 실제로 이 11자리가 API 가 기대하는 값과 **같은 체계인지**는
> 키 없이 호출할 수 없어 검증하지 못했다. **키를 받은 뒤 표본 몇 건으로 먼저 대조**하고,
> 일치하지 않으면 **연락처를 붙이지 않는다.** 이름만 같다고 붙이는 일은 하지 않는다.

## 3. 키를 어디에 두는가 — 정적 사이트의 제약

**모심·곁애는 GitHub Pages 정적 사이트다.** 브라우저에 들어가는 값은 전부 공개된다.
따라서 **serviceKey 를 프런트엔드에 넣으면 안 된다.** 공개 저장소·채팅·로그에도 넣지 않는다.

가능한 방법 세 가지:

| 방법 | 내용 | 장단점 |
|---|---|---|
| **(A) 빌드 시 1회 조회 → 결과만 커밋** (권장) | GitHub Actions 에서 키를 Secret 으로 읽어 기관 21,216건의 주소·전화를 받아 `institutions_raw` 에 채운다. 키는 Actions 안에만 있고 산출물에는 남지 않는다 | 런타임 호출이 없어 트래픽 걱정이 없다. 데이터는 갱신 주기만큼 낡는다 |
| (B) 서버 측 중계 | Supabase Edge Function 에서 키를 환경변수로 읽고 중계한다 | 실시간. 함수 운영·남용 방지(rate limit)가 필요하다 |
| (C) 붙이지 않음 (현행) | 화면에 **기관기호**를 보여주고 공식 사이트에서 조회하도록 안내 | 비용·키 관리 없음. 이용자가 한 단계 더 거친다 |

**(A) 를 권한다.** 일일 10,000회 제한이 있는데 기관이 21,216곳이므로 **하루에 다 받을 수 없다.**
이틀에 나눠 받거나, 평가 최신 건이 있는 기관부터 순차로 채우는 방식이 필요하다.

### (A) 를 쓸 때의 설정

```yaml
# .github/workflows/sync-institution-contacts.yml  (아직 만들지 않았다)
# 저장소 Settings → Secrets and variables → Actions 에 등록:
#   DATA_GO_KR_SERVICE_KEY   — 공공데이터포털 일반 인증키 (Decoding)
#   SUPABASE_SERVICE_ROLE_KEY — 적재용. 절대 프런트엔드에 넣지 않는다
env:
  DATA_GO_KR_SERVICE_KEY: ${{ secrets.DATA_GO_KR_SERVICE_KEY }}
```

`.env.example` 에는 **값 없이 이름과 설명만** 적는다.

## 4. 적용 순서

1. 공공데이터포털에서 ① 활용신청 (자동승인).
2. 받은 키로 **표본 10건**을 호출해 `replace(ltc_sym,'-','')` 가 맞는 기관을 가리키는지 대조한다.
   기관명·시군구가 우리 데이터와 일치해야 한다.
3. 일치하면 `institutions_raw` 에 `adres`·`telno` 열을 **추가 방식으로** 넣고,
   **확실히 연결된 행만** 채운다. 연결되지 않은 행은 비워 둔다.
4. `institutions_eval_latest` 에 같은 열을 더하고, 화면에서는 **값이 있을 때만** 보여준다.
   없으면 지금처럼 "기관기호로 공식 사이트에서 조회" 안내를 유지한다.
5. 출처·조회일을 함께 저장하고 화면에 표시한다.

## 5. 기존 키에 대한 주의

이전 작업에서 공공데이터포털 serviceKey 를 쓴 적이 있다면 **재발급을 권한다.**
공개 저장소에 한 번이라도 올라간 키는 되돌릴 수 없다.
이 저장소의 현재 코드에는 serviceKey 가 들어 있지 않다(전체 검색으로 확인).

## 6. 지금 화면이 하는 일

연락처를 붙이기 전까지, 기관 평가 화면은 이렇게 안내한다:

> 평가 결과 파일에는 **주소·전화번호가 없습니다.** 연락처는 노인장기요양보험에서 **기관기호**로 조회하시면 정확합니다.

그리고 카드마다 기관기호를 표시한다. 이름이 같은 다른 기관이 있어도 정확히 찾을 수 있다.
