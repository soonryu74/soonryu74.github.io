## 5. 기존 DB 27,946 vs 새 파일 27,947 — 행 단위 대조

등급 분포 일치만으로 판단하지 않고, **행 단위 다중집합 비교**를 했다.

- 비교 키: `장기요양기관명` + `관할시군구명` + `평가총점` + `평가일자의 연도`
  (기존 DB 에는 기관기호·평가일자가 없어 두 쪽에 공통으로 존재하는 열만 썼다)
- 점수 표기는 양쪽 모두 뒤의 0 을 제거해 맞췄다.
- 기존 DB 27,946행은 PostgREST 로 전량 받아 비교했다.

**결과**

| | 건수 |
|---|---|
| 기존 DB 행 | 27,946 |
| 새 파일 행 | 27,947 |
| **새 파일에만 있는 행** | **1** |
| **기존 DB 에만 있는 행** | **0** |

새 파일에만 있는 한 행:

| 기관명 | 시군구 | 총점 | 평가연도 | 급여종류 | 평가등급 |
|---|---|---|---|---|---|
| 임마누엘요양원 | 시흥시 | 86.31 | 2025 | 02.입소시설10이상30인미만 | **(빈 값)** |

**해석**: 기존 DB 는 **같은 데이터셋의 더 이전 스냅샷**이다(적재 2026-08-10, 현재 파일은 2026-09-28 수정본). 누락·변형이 아니라 **그 사이에 1행이 추가**된 것이다. 나머지 27,946행은 네 개 열 기준으로 완전히 일치한다.

> 한계: 비교 키에 기관기호·평가일자가 없어 **같은 키를 가진 서로 다른 행의 교체**는 이 방법으로 감지되지 않는다. 다만 양방향 차집합이 (1, 0) 이므로 그런 교체가 있었다면 양쪽에 모두 나타났을 것이다.

## 6. 🔴 기존 DB 에서 발견한 데이터 오류 — 없는 등급을 만들어 넣었다

원자료에 **평가등급이 비어 있는 행이 2건** 있다. 총점은 있다.

| 기관명 | 시군구 | 급여종류 | 평가일자 | 총점 | 원자료 등급 |
|---|---|---|---|---|---|
| 운수사랑요양원 | 남양주시 | 01.입소시설30인이상 | 2025-11-20 | 96.05 | `-` |
| 임마누엘요양원 | 시흥시 | 02.입소시설10이상30인미만 | 2025-02-13 | 86.31 | (빈 값) |

**기존 운영 DB 에서 운수사랑요양원은 등급이 `우수` 로 들어가 있다.** 원자료에 없는 등급이 생성된 것이다.
(임마누엘요양원 시흥시 행은 기존 DB 에 아예 없다 — 5절의 그 1행이다.)

- 기존 DB 등급 분포: 우수 9,470 / 최우수 6,172 / 양호 6,105 / 보통 3,191 / 미흡 3,008 = 27,946
- 원자료 등급 분포: B 9,469 / A 6,172 / C 6,105 / D 3,191 / E 3,008 / `-` 1 / 빈값 1 = 27,947

B 가 한 건 적고 등급 없는 행이 두 건인 것이 이 차이를 설명한다.

**교정**: 새 경로에서는 이 2건을 **‘등급 미제공’** 으로 표시하고 등급을 매기지 않는다. `institutions_eval_latest.grade` 가 `null` 이며, 화면은 총점이 있을 때 `등급 미제공`, 총점도 없을 때만 `미평가` 로 적는다.

## 7. 평가구분·평가일자

원자료 정의를 그대로 쓴다.

| 평가구분 | 건수 | 평가일자 범위 |
|---|---|---|
| 2021년 정기평가 | 4,423 | 2021-04-20 ~ 2022년 중 |
| 2023년 정기평가 | 9,083 | 2023년 |
| 2024년 정기평가 | 9,035 | 2024년 |
| 2025년 정기평가 | 5,406 | ~ 2025-11-28 |

- **이 파일에는 `정기평가` 만 있다.** 수시평가·재평가 구분은 나타나지 않는다.
- **2021년 정기평가는 2021~2022년에 걸쳐 실시됐다**(평가일자 연도로는 2021년 1,140건 + 2022년 3,283건 = 4,423건). 따라서 **평가일자의 연도 ≠ 평가 회차**다. 화면에는 둘 다 표시한다.
- 평가일자 전체 범위: **2021-04-20 ~ 2025-11-28**, 결측 0건.

### 최신 1건 선택 규칙 (정렬·동점 처리)

```sql
select distinct on (ltc_sym, service) *
from institutions_raw
where source_file like 'data.go.kr%' and ltc_sym is not null and btrim(ltc_sym) <> ''
order by ltc_sym, service, eval_date desc nulls last, id desc
```

- 그룹 키: `(장기요양기관기호, 급여종류)` — **이름을 쓰지 않는다.**
- 1순위: `평가일자` 내림차순, `NULL` 은 뒤로.
- 동점(같은 기관기호·급여종류·같은 평가일자): 적재 순서 `id` 내림차순, 즉 **파일에서 뒤에 나온 행**을 택한다. 임의성을 없애기 위한 결정적 규칙이며, 실제로 이 동점 사례가 있는지는 별도로 세지 않았다(결과 건수가 24,486으로 고정되므로 재현 가능하다).

## 8. 동명 기관 표시 — 경고가 아니라 구분 안내

- 판정: 같은 `(이름, 급여종류, 시도, 시군구)` 안에 **서로 다른 기관기호가 2개 이상**이면 해당 행들에 `same_name_warn = true`.
- 규모: **102개 그룹 / 204행.**
- 화면 문구: **"이름이 같은 다른 기관이 있습니다 — … 위의 기관기호로 구분하시고, 계약 전 반드시 어느 기관인지 확인하세요."**
- **이름이 겹친다는 사실 자체를 기관의 문제로 표현하지 않는다.** 위험·주의 기관이라는 의미가 아니며, 이용자가 엉뚱한 기관을 고르지 않도록 돕는 **구분 안내**다. (이전 문구 "동명 기관 주의"는 경고처럼 읽힐 수 있어 바꿨다.)

| 체계 | 영역 | 해당 건수(최신 기준) |

| `pre2025` | 기관운영 · 환경및안전 · 수급자권리보장 · 급여제공과정 · 급여제공결과 (5개) | 19,080 |

- 원자료가 두 체계의 컬럼을 **따로** 제공한다. 2025년 행은 pre2025 컬럼이 비어 있고, 그 이전 행은 2025 컬럼이 비어 있다.
- `area_scheme` 열로 어느 체계인지 구분해 저장하고, 화면에 **"2025년 개편 4개 영역" / "2025년 이전 5개 영역"** 으로 명시한다.
- **결측을 0점으로 채우지 않는다.** 값이 없으면 `자료 없음` 으로 적는다.
- 체계가 다른 점수는 단순 비교할 수 없다고 안내한다.
