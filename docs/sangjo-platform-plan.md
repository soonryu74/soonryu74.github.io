# 상조나침반 기획안 v0.1

> 작성 서순려 · 2026-09-01 · 단계: 시장조사 / 문제정의 / 제품정의
> 아티팩트(읽기 좋은 버전): https://claude.ai/code/artifact/e4df3b90-061e-4087-9e50-19ce2ccea621

11조 원을 맡긴 1,131만 명이 정작 자기 계약이 지금 어떤 상태인지 확인할 곳이 없다.
상조는 금융처럼 돈을 받지만 금융처럼 보이지 않고, 장례처럼 쓰이지만 장례비의 절반도 못 덮는다.
가입자 편에 서서 그 간극을 계산해 보여주는 플랫폼을 만든다.

## 1. 요약

- 시장은 크고 구조적으로 계속 커진다. 선수금 11조 3,544억 원, 계약자 1,131만 명. 사망자는 2024년 35.9만 명 → 2040년 약 53만 명, 화장률 94%.
- 소비자 쪽 인프라만 비어 있다. 계약 정보는 상조회사·은행·공제조합에 흩어져 있고 공정위 공시는 연 1회 표 형태다.
- 분쟁은 한 지점에 몰린다. 상조 피해구제의 66.8%가 해약환급금 지급거부.
- 상조상품은 장례비의 일부만 덮는다. 3일장 총비용 1,173만~2,260만 원 vs 상조 몫 200만~500만 원대.
- 사내·마을 '상조회'는 시스템 밖이다. 총무 1인의 통장과 엑셀로 운영된다.

**제안** — 세 축, 순서 고정. ① 진짜 장례비 계산기 → ② 내 상조 진단 → ③ 상조회 장부.
**설계 원칙** — 어떤 경우에도 회원의 돈을 직접 받지 않는다.

## 3. 문제 진단 — 여섯 개의 구멍

1. **내 계약이 어디에 있는지 나도 모른다** (가입자) — 정보가 상조회사·은행·공제조합에 분산. 정부도 2026년 통합정보시스템 구축을 추진 중이나 조회에 그친다.
2. **분쟁은 전부 해약환급금에서 터진다** (해지하려는 가입자) — 상담 38.2%, 피해구제 66.8%. 양수 사업자의 환급 거부 상담 9개월 637건(전년 260건, +145%). 산식은 공개돼 있는데 계산기가 없다.
3. **'적금인 줄 알았다' 결합상품** (오인 가입자) — 피해 유형의 64.4%가 계약해제 관련, 21.6%가 계약 불이행. 별개 계약이 하나 더 숨어 있다는 사실을 인지하지 못한다.
4. **폐업하면 50%만, 그마저도 놓친다** (폐업 업체 가입자) — 1만 6,162명이 약 66억 원 미수령. 공제조합 청구기한 3년을 안내하지 않은 탓.
5. **상조에 들었어도 장례비 절반 이하만 덮인다** (상주) — 가격 비교가 원리적으로 불가능한 순간에 계약이 이뤄진다.
6. **사내·마을 상조회는 소프트웨어가 없다** (총무·회원) — 회계 불투명, 총무 1인 의존, 동의 없는 임금공제(근로기준법 제43조) 리스크.

## 5. 제품 — 세 개의 축

**A. 진짜 장례비 계산기** (예비 상주·가입 검토자, 로그인 불필요)
- 지역·장례식장 유형·조문객 수·장지 방식 → 총비용 밴드
- 상조가 덮는 부분 / 안 덮는 부분 분리 표시
- 선불제 vs 후불제 총지출 비교, 손익분기 시점
- 공설 장사시설 요금은 공공데이터 갱신, 기준일 명시

**B. 내 상조 진단** (기가입자, 로그인)
- 해약환급금 계산기 — 공정위 고시 산식 구현, 계산 근거 단계별 공개
- 업체 안전도 카드 — 보전비율·지급여력·자본금·감사의견·지배주주 대여·폐업 이력 (공표 수치만, 산식 공개)
- 결합상품 판별기 — 8문항으로 숨은 별도 계약 탐지
- 알림 — 등록취소·폐업·양수도 통지 + 청구기한 3년 카운트다운

**C. 상조회 장부** (사내·마을·동호회 상조회)
- 회원 명부, 회비 납부 현황, 미납 자동 리마인드
- 경조사 접수 → 회칙 지급 규정 자동 적용 → 지급 이력
- 공개 결산(회원 전원 열람), 감사 보고서 자동 생성
- 회칙 템플릿, 임금공제 동의서 양식, 인수인계 팩
- 회비는 상조회 자체 계좌로만 — 우리는 자금을 수취하지 않는다

### 설계 원칙: 자금 미수취
선수금을 직접 받으면 선불식 할부거래업 등록 대상이 되고, 회비를 보관하면 유사수신 논란에 들어간다. 정보와 장부만 다루고 돈은 만지지 않는다. 이것이 규제 리스크를 제거하는 동시에 중립성의 근거가 된다. 광고비로 비교 순위를 바꾸지 않는다.

## 6. 데이터와 기술

| 데이터 | 출처 | 갱신 | 용도 |
| --- | --- | --- | --- |
| 업체별 선수금·보전비율·재무 | 공정위 주요정보 공개 | 연 1회 | 업체 안전도 |
| 해약환급금 산정기준 | 공정위 고시 | 개정 시 | 환급금 계산기 |
| 보전 현황·폐업 공지 | 한국상조공제조합 / 상조보증공제조합 | 수시 | 알림·청구기한 |
| 장례식장·화장·봉안 요금 | e하늘 장사정보시스템 | 수시 | 장례비 계산기 |
| 사망자·장사시설 통계 | 통계청 / 보건복지부 | 연 1회 | 지역별 기준값 |
| 피해 유형 통계 | 한국소비자원 | 연 1회 | 판별 문항 튜닝 |

- **1단계 정적 사이트** — 기존 GitHub Pages 활용. 계산기는 클라이언트 JS, 데이터는 `data/sangjo/*.json`, 갱신은 `scripts/` + Actions. 비용 0원.
- **2단계 Supabase** — 계약 저장·알림 필요 시점에만. Auth + Postgres + RLS, Edge Function으로 폐업 공지 수집·발송.
- **3단계 멀티테넌트** — 상조회 장부는 조직 테넌시와 권한(총무/감사/회원). 결제는 이때 도입.

순서의 핵심: 로그인 없는 계산기로 먼저 신뢰와 검색 유입을 벌고, 그다음 계약 정보를 요청한다.

## 8. 로드맵

1. **Phase 1 (4~6주) 계산기와 백서** — 장례비/환급금/결합상품 판별, 업체 안전도 표(정적). 목표는 매출이 아니라 정확하다는 평판.
2. **Phase 2 (+8주) 내 상조 진단** — 계약 등록, 개인화 환급금 추이, 업체 이벤트 알림, 청구기한 카운트다운. 후불제 견적 연결로 첫 매출.
3. **Phase 3 (+12주) 상조회 장부** — 지인 조직 3~5곳으로 회칙 다양성 흡수 후 일반 공개, 구독 결제.
