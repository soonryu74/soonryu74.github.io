# 교육원 학습관리시스템 사양

> 작성 2026-09-09 · 대상 통합돌봄사이버교육원 · 브랜치 `claude/lifelong-education-j41py9`
> 자체 구축을 전제로 한 사양서입니다. 저장소에 이미 있는 스택을 그대로 씁니다.

## 결론 먼저

**새로 배울 것이 없습니다.** korea-now가 이미 React 19 + Vite + Supabase로 돌아가고 있고, 배포 워크플로도 붙어 있습니다. 같은 구조로 `edu-lms/`를 하나 더 만들면 됩니다.

**MVP는 화면 여섯 개입니다.** 로그인, 내 강의실, 회차 재생, 출석 현황, 관리자 수강생 목록, 관리자 출석 확인.

**영상은 서버에 직접 두지 않습니다.** 스트리밍 서비스에 올리고 링크만 관리합니다. 이유는 아래 계산에 있습니다.

## 재사용하는 스택

| 항목 | 기존 | LMS |
|---|---|---|
| 프런트 | React 19 + Vite + TypeScript | 동일 |
| 라우팅 | react-router-dom 7 | 동일 |
| 백엔드 | Supabase | 동일 프로젝트에 테이블 추가 |
| 배포 | GitHub Actions → `_site/` | 워크플로에 `edu-lms` 추가 |
| 경로 | `/korea-now/` | `/edu/lms/` |

`_config.yml`의 exclude 목록에 `edu-lms`를 넣고, Jekyll 워크플로에서 빌드 결과를 `_site/edu/lms/`에 넣는 방식이 korea-now와 같습니다.

## 화면

### 수강생

| 화면 | 하는 일 |
|---|---|
| 로그인 | 이메일로 링크를 받아 들어옵니다. 비밀번호를 만들지 않습니다 |
| 내 강의실 | 신청한 과정과 진도율, 다음에 들을 회차 |
| 회차 재생 | 영상, 교재 내려받기, 음성만 듣기 |
| 출석 현황 | 회차별 시청 완료 여부와 수료 요건까지 남은 개수 |

로그인에 비밀번호를 두지 않는 이유는 50대 이상 수강생 때문입니다. 비밀번호 찾기 문의가 가장 많은 문의가 됩니다.

### 관리자

| 화면 | 하는 일 |
|---|---|
| 수강생 목록 | 등록, 과정 배정, 납부 확인 표시 |
| 출석 확인 | 과정별 출석표, 기관 단위 회신용 내려받기 |

## 데이터 구조

```
courses        과정 (실무·기본·진입·현장AI·공직AI)
lessons        회차 (course_id, 순서, 제목, 영상 id, 교재 파일, 길이)
students       수강생 (이메일, 성명, 연락처, 소속)
enrollments    수강 등록 (student_id, course_id, 시작일, 납부 확인)
progress       시청 기록 (enrollment_id, lesson_id, 시청 구간, 완료 여부)
completions    수료 (enrollment_id, 출석률, 과제 제출, 수료증 번호)
```

여섯 개면 충분합니다. 처음부터 크게 만들면 안 끝납니다.

## 영상을 어디에 둘 것인가

직접 저장하면 안 되는 이유는 용량입니다.

| | |
|---|---|
| 회차 1개 60분 영상 | 약 700MB |
| 94회차 전체 | 약 65GB |
| Supabase 무료 저장 | 1GB |

저장도 문제지만 대역폭이 더 큽니다. 수강생 50명이 30회차를 보면 월 1TB가 넘습니다.

**스트리밍 서비스에 올리고 링크만 관리합니다.** 1단계 기본과정 8회차는 480분이므로 비용이 월 몇천 원 수준입니다. 과정이 늘어날 때 같이 늘어납니다.

고를 때 볼 것은 두 가지입니다. 도메인 제한을 걸 수 있는가, 재생 진도를 이벤트로 받을 수 있는가. 진도를 못 받으면 출석을 셀 수 없습니다.

## 출석을 어떻게 세는가

사이트에 이미 출석 80퍼센트가 수료 기준으로 적혀 있습니다. 그래서 규칙을 먼저 정해야 합니다.

1. 재생 중 30초마다 시청한 구간을 기록합니다.
2. 한 회차의 90퍼센트 이상을 봤으면 그 회차를 이수한 것으로 처리합니다.
3. 건너뛴 구간은 시청 구간에 넣지 않습니다.
4. 배속 재생은 허용하되 구간 기록은 실제 영상 시간 기준으로 셉니다.
5. 이수한 회차 수가 전체의 80퍼센트를 넘으면 출석 요건을 채운 것으로 봅니다.

이 규칙을 학습 지원 페이지에 그대로 적어 두어야 합니다. 나중에 분쟁이 생기면 그 문장이 기준이 됩니다.

## 단계별로 만들기

### 1차 · 개강에 필요한 최소한

- 이메일 로그인
- 과정과 회차 목록
- 영상 재생과 진도 기록
- 출석 현황 화면
- 관리자 수강생 등록과 출석표

납부는 계좌이체로 받고 관리자가 손으로 확인 표시를 합니다. 수강생이 열 명 남짓일 때는 이게 더 빠릅니다.

### 2차 · 운영이 돌아가기 시작하면

- 과제 제출과 회신
- 수료증 자동 발급
- 기관 담당자용 화면
- 공지사항

### 3차 · 규모가 커지면

- 결제 연동
- 실시간 수업 링크 관리
- 통계 화면

## 신고 서류와의 연결

개설 준비 문서의 확인 목록에 이런 항목이 있습니다.

> 클라우드 서버가 서버 임대계약서를 갈음하는지

이 사양대로 만들면 Supabase와 스트리밍 서비스 두 곳의 계약이 생깁니다. 관할 교육지원청에 물을 때 이 구성을 그대로 설명하시면 됩니다. 자체 서버를 사무실에 두라고 하는 곳이 있으면 그때 다시 판단합니다.

## 만드는 데 걸리는 시간

바이브코딩으로 하루 서너 시간이면 1차는 2주에서 3주입니다. 데이터 구조가 여섯 개뿐이고 화면이 여섯 개뿐이라 그렇습니다.

교안 집필과 병행하시면 됩니다. 서로 막히는 지점이 다릅니다.

## 덧붙임

이 시스템을 만드는 과정 자체가 강의 상품이 됩니다.

대표님의 수익 계획에서 가장 큰 몫이 바이브코딩 강의입니다. "필요한 프로그램을 직접 만든다"는 것을 말로 설명하는 것과, 실제로 운영 중인 학습관리시스템을 열어 보여주는 것은 다릅니다.
