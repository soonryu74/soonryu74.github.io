# Paperling MVP 화면 설계 v0.1

> 작성 서순려 · 2026-10-25 · 기획안: `docs/ai-note-app-plan.md` · 랜딩: `/paperling/`
> 클릭 가능한 와이어프레임: https://claude.ai/artifact/K4TZB6pAQ1AcSLJGHF2Pok

MVP 범위: 사진 → AI 정리 → 서랍 분류 → 노션 저장 + 구글 캘린더 일정 생성. 웹앱(PWA). 디자인 2종.
화면은 **3개 + 설정 1개**로 끝낸다. 화면이 늘어나면 범위가 늘어난 것이다.

## 1. 화면 목록

| 번호 | 화면 | 한 줄 목적 | 진입 |
| --- | --- | --- | --- |
| S1 | 찍기 | 사진을 가장 빨리 올린다 | 앱 홈, 공유 시트 |
| S2 | 확인 | AI 결과를 보고 고치고 서랍을 정한다 | S1 처리 후 |
| S3 | 서랍장 | 저장된 것을 보고, 보낸 곳 상태를 본다 | S2 저장 후, 하단 탭 |
| S4 | 설정 | 연동·디자인·사진 보관 정책 | 상단 톱니 |

## 2. S1 찍기

- 큰 버튼 2개: **카메라로 찍기** / **갤러리에서 고르기**. 그 아래 "최근 3장" 썸네일.
- 여러 장 선택 가능(최대 10장). 한 묶음은 한 노트로 합칠지 따로 둘지 S2에서 결정.
- 업로드 직후 자동 처리: 기울기 보정, 여백 자르기, 밝기 보정. 실패해도 원본으로 진행.
- 처리 중 화면: 사진 위에 "읽는 중 → 정리하는 중 → 서랍 고르는 중" 3단계 문구. 보통 5~10초.
- 무료 잔여 장수 표시("이번 달 20장 중 13장 남음"). 소진 시 프로 안내, 업로드 차단은 하지 않고 대기열.
- PWA 공유 타깃 등록: 폰의 사진 공유 메뉴에서 Paperling 선택 → S1 생략하고 바로 처리.

## 3. S2 확인 (핵심 화면)

좌우 분할(폰에서는 상하). 왼쪽 원본 사진, 오른쪽 정리 결과.

| 영역 | 내용 | 동작 |
| --- | --- | --- |
| 제목 | AI 제안 제목 | 탭하면 수정 |
| 본문 | 텍스트화된 글. 문단·목록 유지 | 단어 탭 → 원본의 해당 부분 하이라이트 + 수정 입력 |
| 말투 | 그대로(기본) / 다듬기 / 요약 | 토글, 원문은 항상 보관 |
| 추출 칩 | 일정("10/28 15:00 치과"), 할 일, 사람, 장소 | 칩 탭 → 수정·삭제. 일정 칩은 "캘린더에 넣기" 체크 기본 ON |
| 서랍 | 일기 / 할 일 / 일정 / 아이디어 / 미분류 | AI 추천이 선택된 상태. 탭으로 변경. 한 노트가 두 서랍에 들어갈 수 있음 |
| 보낼 곳 | 노션 ☑ 구글 캘린더 ☑ | 설정값 기본, 이번만 바꾸기 가능 |
| 저장 | 하단 고정 버튼 | 저장 → S3로 이동, 전송은 백그라운드 |

- 신뢰 장치: 오인식 의심 단어는 점선 밑줄. 사용자가 고친 단어는 다음 처리부터 사용자 사전에 반영.
- 묶음 처리: 여러 장이면 상단에 페이지 점(1/3). "한 노트로 합치기" 토글.
- 되돌리기: 저장 전 모든 수정은 되돌릴 수 있다.

## 4. S3 서랍장

- 상단: 이번 주 요약 한 줄("이번 주 사진 6장, 일정 3개 캘린더에 들어감").
- 서랍 4개 그리드(일기·할 일·일정·아이디어) + 미분류 배지. 각 서랍은 최근 항목 2개 미리보기.
- 노트 카드: 제목, 날짜, 서랍 색 띠, 원본 썸네일, 전송 상태 아이콘(노션 ✓, 캘린더 ✓, 실패 ! → 탭하면 재시도).
- 검색: 텍스트 검색(손글씨 내용 포함). 날짜·서랍 필터.
- 노트 상세: S2와 같은 레이아웃, 읽기 모드. "노션에서 열기" 링크.

## 5. S4 설정

- 연동: 체크박스 한 줄. 노션(연결/해제, 저장 위치 페이지 표시), 구글 캘린더(어느 캘린더에 넣을지).
- 서랍별 보낼 곳 매트릭스(2단계에서 확장. MVP는 전체 공통).
- 디자인: 화이트 노트 / 클래식 플래너 2종. 손글씨 폰트 3종. 미리보기 즉시 반영.
- 사진 보관: 원본 보관(기본) / 처리 후 삭제. 저장 위치 안내(국내).
- 계정: 이메일, 플랜, 이번 달 사용량, 데이터 전체 내보내기(마크다운+사진 zip), 탈퇴.

## 6. 데이터 모델 (수파베이스)

| 테이블 | 핵심 컬럼 |
| --- | --- |
| notes | id, user_id, created_at, note_date, title, raw_text(그대로), clean_text(다듬기), summary, drawers text[], theme, font, status |
| note_images | id, note_id, storage_path, page_no, width, height, keep_original bool |
| entities | id, note_id, kind(event/todo/person/place), text, start_at, end_at, done bool |
| destinations | id, note_id, target(notion/gcal), external_id, status(pending/sent/failed), error, sent_at |
| connections | user_id, target, access_token(암호화), refresh_token, meta(노션 DB id, 캘린더 id) |
| user_dictionary | user_id, wrong, right, count |

RLS: 모든 테이블 user_id = auth.uid(). 토큰은 서버(엣지 함수)에서만 읽는다.

## 7. AI 처리 계약

입력: 사진 1~10장 + 사용자 사전 + 오늘 날짜 + 시간대.
출력(JSON 고정):

```json
{
  "title": "10월 28일 수요일",
  "note_date": "2026-10-28",
  "raw_text": "치과 3시!! ...",
  "blocks": [{"type":"paragraph","text":"..."},{"type":"list","items":["..."]}],
  "entities": [
    {"kind":"event","text":"치과","start_at":"2026-10-28T15:00:00+09:00","confidence":0.92},
    {"kind":"todo","text":"엄마 생신 선물 고르기","confidence":0.88}
  ],
  "drawers": ["일정","할 일","일기"],
  "mood": ["피곤","평온"],
  "uncertain_spans": [{"text":"스카프","alternatives":["스커트"]}]
}
```

규칙: 원문을 바꾸지 않는다(raw_text). 날짜가 없으면 사진 촬영일. 확신 0.7 미만 일정은 캘린더 기본 OFF.
모델은 멀티모달 1회 호출. 한글 손글씨 정확도는 2개 모델로 50장 비교 후 선택.

## 8. 6주 일정

| 주 | 할 일 | 끝나는 기준 |
| --- | --- | --- |
| 1 | 수파베이스 스키마, 로그인(이메일 매직링크), S1 업로드·보정 | 사진이 스토리지에 들어간다 |
| 2 | AI 처리 엣지 함수, JSON 계약, 모델 2종 비교 | 50장 테스트셋 정확도 표 |
| 3 | S2 확인 화면, 오인식 수정, 사용자 사전 | 수정 후 저장이 된다 |
| 4 | 노션 OAuth, 서랍별 DB 자동 생성, 전송·재시도 | 노션에 노트가 생긴다 |
| 5 | 구글 캘린더 OAuth, 일정 생성 확인 흐름, S3 서랍장 | 캘린더에 일정이 생긴다 |
| 6 | S4 설정, 디자인 2종·폰트 3종, PWA 설치·공유 타깃, 베타 초대 | 대기자 30명 초대 |
