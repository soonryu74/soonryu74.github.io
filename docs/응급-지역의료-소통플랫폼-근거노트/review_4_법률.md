### 검토자 4. 의료법·개인정보보호 법률 전문가

> 검토 범위: 보고서 본문과 근거 노트(06·03)만 근거로 함. 웹 검색 없음. 노트에서 조문 원문이 확인되지 않은 부분은 "원문 확인 필요", 검토자의 법률 판단은 "의견"으로 표시함.

**종합 평가**

| 항목 | 점수 | 근거 |
|---|---|---|
| 법적 근거 충분성 | 2/5 | 조문은 많이 나열했으나 제21조의2를 확대 해석했고, 국회만 통과한 법(응급의료법 개정)과 시행 전인 법(제34조 개정)을 현행 근거처럼 썼음 |
| 개인정보 보호 설계 | 3/5 | 민감정보 층과 알림 층을 나눈 구조는 맞음. 다만 개인정보처리자·수탁자 구조, 가명정보의 법적 성격, 2차 이용이 설계되지 않았음 |
| 책임 배분 명확성 | 1/5 | 원격지의사·현지의사 책임(제34조), AI 요약 오류, 시스템 장애에 대한 책임 매트릭스가 없음 |

**동의하는 핵심 설계**

1. **§⑧ 공통 아키텍처 (2)와 요구사항 1 '카카오톡 연계 방식'**: 환자 본문·이미지가 카카오 서버를 거치지 않게 하고 알림톡은 비식별 문구와 딥링크만 보내는 구조. 노트 06 §2에 따르면 카카오톡은 일반채팅에 E2EE가 없고 비밀채팅도 서버에 임시 저장되므로, 안전조치를 입증할 수 있는 현실적인 최소 설계임(의견).
2. **§⑧ 요구사항 4 '구조'**: 상태 판단의 1차 데이터를 LLM 출력이 아니라 구조화 이벤트로 두고, 사람이 모든 출력을 확인하게 한 설계. 감사·입증 책임과 설명 의무에 유리함(의견).
3. **§⑦ P3와 §⑧ 요구사항 2 '보상 설계 원칙'**: 개인 보상의 지급 주체를 공공으로 한정하고 제약사·광고주 후원을 배제함. 제23조의5의 구성요건(의약품공급자·의료기기 업체가 판매촉진 목적으로 주는 이익)에 비추어 해석이 정확함(노트 06 §5).

**반드시 수정할 사항** (우선순위 순)

1. **제21조의2 확대 해석**
   - 문제: 이 조문은 다른 의료기관의 송부 요청에 응하는 경우와 응급환자 이송 시 기록 사본을 보내는 경우를 규율함. 그런데 보고서(§⑧ 요구사항 1)는 이를 근거로 수락 전 단계에서 명부의 1차 그룹 N명에게 요약과 첨부(영상·검사결과)를 동시에 발송함. 이는 특정되지 않은 다수에게 먼저 제공하는 구조이므로 이 조문만으로는 정당화하기 어려움(의견).
   - 근거: 의료법 제21조의2(노트 06 §1). 단서의 "의식이 없거나 응급환자인 경우 / 보호자가 없어 동의를 받을 수 없는 경우"가 각각 독립된 요건인지는 원문 확인 필요. 민감정보 처리에 필요한 '법령상 허용'(개인정보보호법 제23조) 요건과 어떻게 연결되는지도 원문 확인 필요.
   - 수정안:
     - 수락 전 단계에는 비식별 최소 요약만 보냄. 영상은 DICOM 헤더와 화면에 새겨진 식별문자를 제거한 사본만 보냄.
     - 식별정보와 원본 영상은 수락한 1인에게만 엽니다.
     - 읍면 트랙(비응급)은 동의를 원칙으로 함. 동의서에는 제공받는 자(권역 협진망 등록기관 목록 공개), 목적, 항목, 보유기간, 거부권을 적고 민감정보는 별도로 동의받음(제17조·제23조).
     - 응급 예외를 적용한 경우에는 사후 고지 절차를 둠.

2. **개인정보처리자·수탁자 구조 미정의**
   - 문제: P11은 "공공 소유, 민간 위탁"이라고만 함. 요청기관에서 자문기관으로 넘어가는 정보가 제3자 제공인지 위탁인지, 운영기관(시도·국립중앙의료원 등)의 지위가 무엇인지, SI·클라우드·LLM이 몇 단계 재위탁인지 정해져 있지 않음.
   - 근거: 개인정보보호법 제17조·제26조(위탁 문서화, 공개, 감독, 재위탁 시 위탁자 동의). 조문 세부는 원문 확인 필요.
   - 수정안(의견):
     - 기관 간 제공은 '각 의료기관이 개인정보처리자, 의료기관 간 제공은 제3자 제공'으로 정리함.
     - 운영기관은 모든 참여 의료기관의 수탁자로, 민간 개발·운영사와 LLM은 재수탁자로 둠.
     - 참여협약, 위탁계약, 재위탁 동의를 표준 문서로 만듦.
     - 의사 명부와 성과 데이터는 운영기관이 처리자가 되는 별도 처리로 분리함.

3. **"비식별 LLM 투입" 전제의 법적 오류**
   - 문제: 토큰화한 뒤 다시 원 레코드에 결합하는 구조이므로 이 데이터는 가명정보, 즉 여전히 개인정보임. 가명정보 특례(제28조의2)는 통계·연구·공익 기록보존 목적에만 적용되므로 진료 지원 요약에는 쓸 수 없음. 따라서 LLM 처리는 위탁으로 보아야 하고, 해외 API를 쓰면 국외이전(제28조의8)이 됨. 또 §⑧ 요구사항 4의 "수정률이 모델 개선 데이터"라는 문구는 목적 외 이용(제18조)에 해당함.
   - 근거: 개인정보보호법 제2조·제18조·제28조의2·제28조의8(원문 확인 필요). 노트 06 §4의 Gaps는 개인정보위 안내서가 외부 LLM 호출을 위탁으로 보는지 제3자 제공으로 보는지 확인하지 못했음.
   - 수정안:
     - 국내 처리만 허용함(해외 API 금지를 계약에 명시).
     - LLM 사업자와 수탁 계약을 맺어 학습 이용 금지, 입력·출력 보관 금지(무보관), 감사권을 둠.
     - 모델 개선은 가명처리 절차와 별도 심의를 거친 경우로만 한정함.
     - 근거 문구를 "비식별"에서 "가명처리 후 위탁 처리"로 바꿈.

4. **책임 배분 공백**
   - 문제:
     - 현행 제34조에는 원격의료 시설·장비 요건, "원격지의사는 대면진료와 같은 책임", "명백한 과실 근거가 없으면 현지의사 책임" 조항이 있는 것으로 알고 있으나(원문 확인 필요), 보고서는 이 조항들을 다루지 않음.
     - 읍면 트랙은 현장에 의사가 없음(보건지소 간호사 보조). 이 경우 의사-의사 협진이 아니라 비대면진료(제34조의2)에 가까워 책임 주체가 비게 됨(의견).
     - §⑧ 요구사항 2는 개정 응급의료법에 포함된 "형사책임 경감"이 원격 자문 의사에게도 유리하다고 썼음. 경감 대상이 원격 자문 의사까지 포함된다는 근거가 없으므로 과장임.
   - 수정안: 아래 사고 유형별로 책임 매트릭스를 만들어 이용약관과 참여협약에 반영함.

     | 사고 유형 | 1차 책임 주체 |
     |---|---|
     | 자문 내용 오류 | 원격지의사 |
     | 정보 누락 | 요청자 |
     | AI 요약 오류 | 확인·서명한 의사, 운영자는 결함 책임 |
     | 알림·에스컬레이션 장애 | 운영자, 공공 운영이면 국가배상 검토 |

     - 원 대화와 AI 요약을 함께 보존하고, EMR에 첨부할 때 "AI 초안/의사 확인" 표시를 붙임.
     - 읍면 트랙은 2026.12 시행규칙이 나오기 전까지 보건소 의사(공보의) 경유를 필수로 함.
     - 원격 자문이 의료배상책임보험의 보장 범위에 들어가는지 확인함.

5. **"불가(사유)" 기록과 응급의료 거부 금지의 충돌**
   - 문제: 개정 응급의료법은 상황실이 수용기관을 지정하고 수용 거부 사유를 법으로 정함(§②, §⑧ 요구사항 2). 이 상황에서 플랫폼의 거절 로그가 진료거부를 입증하는 증거로 쓰일 수 있음. 그러면 의사들이 참여를 꺼리게 될 수 있음(의견).
   - 근거: 응급의료법상 정당한 사유 없는 응급의료 거부·기피 금지와 벌칙(원문 확인 필요). 개정 조문의 시행일은 미확인(보고서 §⑪).
   - 수정안:
     - "자발적 자문 가능 여부" 응답과 "지정 후 수용 결정"을 법적으로 구분된 이벤트로 설계함.
     - 거절 로그를 어디에 쓸 수 있는지(품질관리 한정 여부)를 운영규정과 복지부 유권해석으로 확정함.

6. **보상·과금과 알선 금지(제27조 제3항)의 경계**
   - 문제:
     - 보고서는 Pulsara의 "의뢰측 무료·수용측 과금(ED 볼륨 과금)" 모델을 "직접 이식 가능"하다고 했음(§① 5, §⑥). 그러나 수용 건수에 연동해 의료기관이 운영사에 돈을 내는 구조는 국내에서 환자 소개·알선의 대가로 해석될 위험이 높음(의견). 노트 03에 따르면 닥터나우는 알선 수수료가 불법이라 수수료 매출을 낼 수 없었고, 환자 소개 수수료를 받은 의사가 실형을 받은 사례가 있음.
     - 국립대병원·공공의료기관 소속 의사가 개인 수당을 받으면 청탁금지법 예외(법령상 정당한 권원) 해당 여부와 겸직 허가가 문제됨(원문 확인 필요).
     - 응급의료기금 제21조의 보조사업 항목으로 개인에게 직접 지급할 수 있는지, 그리고 회송료·배정지원금과 이중 지급이 되는지(보조금법)도 검토되지 않았음.
   - 수정안:
     - 운영사 보수는 정액 위탁 운영비로만 지급하고, 수용 건수·환자 수에 연동한 과금은 금지함.
     - 요청 측(의뢰 의사·기관)에는 어떤 경제적 이익도 주지 않음.
     - 개인 보상은 조례·고시에 근거 조항을 두고, 소속기관을 거쳐 지급하는 방식과 직접 지급 방식 각각의 적법성을 확인함.
     - 제27조 제3항에 대해 복지부 유권해석을 받는 것을 0단계 산출물에 추가함.

7. **법적 근거 표기의 과장**
   - BLUF와 §① 9의 수정 필요 사항:
     - **응급의료법 개정**: "2026.10.1 국회 통과"이며 공포·시행 전임. 현행 근거로 쓰면 안 됨.
     - **제34조 비대면협진**: 2026.12 시행 전에는 현행 제34조(원격의료)가 근거임.
     - **AI 기본법 고영향 AI**: 보건의료 분야라고 자동으로 해당되지 않고 '영향의 중대성' 요건도 충족해야 함(원문 확인 필요). 기능을 요약·분류로 한정한다고 고영향 AI 의무 전체가 충족되지는 않음. 투명성 고지는 여러 의무 중 하나일 뿐임.
     - **디지털의료제품법**: "의료기기 비해당"은 단정할 수 없고 식약처 질의 결과에 달림. 특히 '긴급도 플래그'는 분류(triage) 기능으로 볼 여지가 있음(의견).
     - **과징금**: 상한은 2023년부터 전체 매출액 3%(위반과 관련 없는 매출 제외)임. 공공기관에 매출이 없을 때 적용하는 정액 상한은 원문 확인 필요.

8. **카카오 채널의 잔여 위험**
   - 환자에게 보내는 결과 알림톡은 발신 채널 이름만으로 건강정보가 추정될 수 있음(예: 정신건강·중독 센터 채널). 발신 채널은 중립적인 이름으로 일원화해야 함.
   - 보건소 주민 봇(§⑧ 요구사항 3)은 "개인정보 없는 조회"를 전제로 함. 그러나 주민이 자유 입력란에 병력을 쓸 것이므로 다음이 필요함: 입력 자제 안내, 오픈빌더 스킬서버 로그 마스킹, 보관기간, 처리방침 고지.
   - 딥링크 토큰은 1회용·짧은 유효시간으로 하고, 사례 ID를 추측할 수 없게 해야 함.

**누락된 사항**

- **유출 사고 대응**: 통지·신고 기한(72시간, 민감정보 1명 이상, 원문 확인 필요)과 대응 매뉴얼. 경북대병원 사례에서 처분 사유가 된 부분임.
- **보존기간 매트릭스**:

  | 기록 | 보존기간 |
  |---|---|
  | 진료기록 원본(EMR 측, 의료법 시행규칙) | 10년 |
  | 접속기록(안전성 확보조치 기준, 민감정보 처리) | 2년 이상 |
  | 정산 근거 | 5년 |
  | 플랫폼 사본 | EMR 이관 확인 후 파기 |

  모든 기간은 원문 확인 필요. 플랫폼이 진료기록 원본을 보관하게 되면 전자의무기록 보관 시설·장비 기준이 적용될 수 있으므로(원문 확인 필요), 원본은 EMR로 지정해야 함.
- **E2EE와 입증 책임의 충돌**: Matrix E2EE를 쓰면 운영자가 대화를 복호화할 수 없어 감사·분쟁 때 증거를 내놓을 수 없음. 사례 기록은 서버 측 암호화로 보관해야 함.
- **보건소 회신의 법적 근거**: 전원 결과를 보건소에 회신하는 폐쇄루프(§⑧ 요구사항 2)는 제3자 제공임. 동의를 받거나 법령 근거를 확보해야 함.
- **공공기관 의무**: 개인정보 영향평가(제33조) 의무 대상인지 판단, 개인정보 손해배상 책임보장(보험) 가입.
- **의사 측 권리 보호**: 의사 명부·응답시간·거절률은 의사 개인정보이므로 감시·보상에 쓰는 데 대한 고지·동의가 필요함.
- **특수 정보주체**: 14세 미만·의사무능력자의 동의 주체, 정보주체의 열람·삭제 요청 처리 절차.

**파일럿 착수 전 선결 조건**

- [ ] 처리자·수탁자·재수탁자 구조도와 참여협약·위탁계약 표준안 확정
- [ ] 개인정보 영향평가 완료(위험 시나리오: 수락 전 다수 공유, LLM 처리, 카카오 알림)
- [ ] 응급/비응급 동의 흐름, 사후 고지, 법정대리인 절차 확정
- [ ] 복지부 유권해석: 제21조의2 적용 범위, 제27조 제3항(보상·과금), 거절 로그 활용 범위
- [ ] 식약처 의료기기 해당 여부 회신, AI 기본법 고영향 해당 여부 확인
- [ ] LLM 국내 처리 확인, 학습 금지·무보관 계약
- [ ] 책임 매트릭스와 이용약관, 배상책임보험(의료·개인정보) 확인
- [ ] 보존기간 매트릭스, 접속기록 점검 주기, 유출 대응 매뉴얼 마련
- [ ] 개인 보상의 조례·고시 근거, 청탁금지법·겸직 검토, 이중 수령 방지 규칙
- [ ] 개정 응급의료법·의료법 제34조의 공포일·시행일·시행규칙 원문 확인
