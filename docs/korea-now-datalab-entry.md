## 1) 문제점 또는 현안사항

- **방한 외국인은 '언제 가야 하는지'를 알 방법이 없다.**
  - 기존 관광 정보 서비스는 '무엇을 보는가'에 치중, '언제 가면 덜 붐비는가'는 다루지 않음
  - 실시간 혼잡도는 서울시가 121개 지점에 한해 제공하나, 전국 단위 정보는 부재
  - 실시간 정보는 '이미 현장 근처에 온 사람'에게만 쓸모 있음. 여행 일정을 **짜는 단계**에서
    필요한 것은 '어느 요일에 넣을 것인가'에 대한 답임

- **휴관일 정보가 여행 일정과 따로 논다.**
  - 국립·공립 시설 상당수가 월요일 또는 화요일 휴관이나, 외국인 대상 안내는 영문 표기가
    누락되거나 갱신이 늦음
  - 한산한 날을 골랐는데 그날이 휴관일이면 **헛걸음**이 됨. 일정을 되돌릴 수 없는
    단기 체류 외국인에게는 손실이 큼

- **개인·소규모 사업자가 이 문제를 풀기 어려웠다.**
  - 필요한 데이터가 데이터랩·공공데이터포털·지자체 포털에 흩어져 있고 형식이 제각각
  - 요금·휴관일 등 현장 정보는 아예 개방 데이터로 존재하지 않아 직접 수집해야 함

## 2) 현안사항 해결을 위한 데이터 활용 방안

- **데이터랩 기초지자체 방문자수에서 '외국인'만 분리 활용**
  - `touDivCd=3`(외국인) 값만 추출 — SK텔레콤 이동통신 기반 추정치
  - 내국인 방문 패턴과 외국인 방문 패턴은 다르므로, 외국인 대상 서비스에는 외국인 값만 써야 함
  - 12주(2026.5.18~8.9) 구간을 잡아 단기 변동과 공휴일 영향을 평균으로 흡수

- **시군구 × 요일 지수화**
  - 시군구별로 요일 평균을 낸 뒤 전체 평균을 100으로 하는 지수로 환산
  - 절대 인원수는 시군구 규모에 좌우되므로, '그 동네 기준으로 몇 % 붐비는가'로 바꿔야 비교 가능
  - 예) 종로구 = 월 99 · **화 84** · 수 99 · 목 97 · 금 106 · 토 110 · 일 105

- **휴관일 데이터와의 교차 — 이 응모작의 핵심**
  - 데이터랩 지수만 보면 종로구의 최적일은 화요일(84)
  - 그러나 **경복궁·종묘는 화요일이 휴관**이므로 그날 방문은 불가능
  - 따라서 휴관일을 먼저 제외한 뒤 남은 요일 중 최저 지수일을 선택하는 방식으로 설계
  - 더 한산하지만 휴관이라 갈 수 없는 날이 있으면, 그 사실을 화면에 별도 문구로 안내
    (예: "Tuesday is quieter still — but Gyeongbokgung Palace is closed that day.")

- **시간 축이 다른 세 데이터를 역할별로 분리**

  | 데이터 | 시간 해상도 | 맡은 질문 |
  |---|---|---|
  | 데이터랩 방문자수 | 요일(12주 평균) | 여행 일정을 짤 때 — **어느 요일에 넣을까** |
  | 관광지 집중률 예측 | 일(향후 30일) | 그 주에 — **어느 날이 나을까** |
  | 서울 실시간 도시데이터 | 분(현재) | 지금 — **바로 갈까 말까** |

  - 하나의 데이터로 세 질문을 모두 답하려 하지 않고, 각 층이 자기 질문만 맡도록 구성

## 3) 데이터 활용을 통한 사업 개선 및 적용 사례

- **서비스 개발 및 공개**
  - 서비스명: Korea Now (https://soonryu74.github.io/korea-now/)
  - 방한 외국인 대상 **영문 전용** 무료 웹앱. 회원가입·설치 없이 브라우저에서 즉시 이용
  - 휴대폰 홈 화면에 설치 가능(PWA), 오프라인에서도 기본 정보 열람 가능
    — 해외 유심·로밍 환경을 고려한 설계

- **데이터 파이프라인 구축** (전 과정 자동화, 소스 공개)
  - `scripts/fetch-visitors.mjs` — 데이터랩 API에서 지정 구간을 주 단위로 내려받음
  - `scripts/gen-rhythm.mjs` — 외국인 값만 추출해 시군구×요일 지수로 요약
  - 산출물을 빌드 시점에 정적 파일로 구워 넣어, **이용자 접속 시 API를 호출하지 않음**
    → 공공 API 일 1,000건 제한을 소모하지 않고, 화면 표시 속도 확보

- **화면 적용**
  - 관광지 상세에 '가장 한산한 요일' 카드 신설 — 7개 요일 막대그래프, 휴관일은 빗금 처리
  - 데이터 출처·집계 구간·**시군구 단위 값이라는 한계**를 카드 하단에 명시
    → 과장 없이 '경향'으로 제시. 이용자가 스스로 판단할 근거를 함께 제공

- **검색 노출 확보**
  - 관광지 55곳을 각각 독립된 주소의 정적 페이지로 생성 (자바스크립트 없이도 본문 노출)
  - 각 페이지의 검색결과 설명문에 요일 정보를 포함
    예) "Tuesday is usually the quietest day to visit; Saturday is the busiest."
  - 사이트맵 57건 · robots.txt 게시 → 검색을 통해 데이터랩 분석 결과가 외국인에게 직접 닿음

- **데이터 공백 보완**
  - 개방 데이터에 없는 55곳의 입장료·휴관일·카드결제·영어안내 수준을 직접 확인해 정리
  - 확인 시점(`2026-09`)을 함께 기록해 갱신 주기를 관리

## 4) 추진성과 및 기대효과

**정량 성과**

- 데이터랩 원자료 **67,657건** 처리 → **22개 시군구** 요일 지수 산출
- 전국 관광지 **55곳 100% 매칭** (서울 28곳의 시군구 코드를 보완해 누락 0)
- 요일 간 외국인 방문자 격차 **중앙값 22%**, 20% 이상인 곳 **28곳**
  → 요일만 바꿔도 체감 혼잡을 20% 이상 낮출 수 있는 관광지가 절반을 넘음
- **휴관일과 최한산일이 충돌하는 관광지 2곳**(경복궁·종묘)을 사전에 식별해 오안내 차단
- 검색 노출 페이지 **0건 → 57건**
- 서비스 이용자 `[9/29 집계]`

**정성 성과 및 기대효과**

- **외래객 분산 효과**: 주말(토 110~143)에 쏠린 방문을 평일로 유도. 데이터랩이 관측한
  쏠림을 그대로 이용자에게 되돌려 주는 구조이므로, 이용자가 늘수록 분산 효과가 커짐
- **헛걸음 방지**: 휴관일 교차 검증으로 단기 체류 외국인의 일정 손실을 예방
- **재현 가능성**: 코드와 수집 절차를 공개해, 동일 방식으로 다른 지역·업종이
  자기 데이터를 얹을 수 있음. 지자체 관광과·소규모 여행사도 같은 파이프라인 사용 가능
- **확산 경로 보유**: 운영 중인 AI 활용 교육 유튜브 채널(구독자 약 1만)을 통해
  데이터랩 활용 방법 자체를 교육 콘텐츠로 공개 예정 → 데이터 활용 문화 확산에 기여

**한계와 후속 계획**

- 시군구 단위 값이므로 개별 관광지 혼잡도와 일치하지 않음 — 화면에 명시하고 '경향'으로만 제시
- 데이터랩 방문자 데이터는 약 1개월 지연 반영 → 월 1회 갱신 주기로 운영
- 후속: 성/연령별 방문 현황을 더해 연령대별 추천 요일 제공, 중심-연관 관광지 데이터로
  하루 동선 자동 구성 기능 추가 예정
