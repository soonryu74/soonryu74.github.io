## 평가항목 대응
| 항목 | 제안서에서 보여줄 증거 |
|---|---|
| 데이터 활용 | 정보원 자체 공개 API 2종(중앙부처·지자체)을 핵심 입력으로 사용, 필드명까지 명시 |
| AI 혁신성 | 공고 문장 → 조건 JSON 추출(사람 승인), 쉬운말·다국어 재작성, 자연어 질문 구조화. 판정은 규칙 |
| 구체성 | 단계별 일정, 스크립트·데모 경로, 보유 기술(국민 곁에 ON) 재사용 |
| 독창성 | 검색형(복지로)·질문형(복지니)·급여형(복지멤버십) 위에 푸시+준비 층 |
| 사업화 | B2C/B2B/B2G 가설 3개, 타 기관 API 확장 |
| ESG | 사각지대·고령자·다문화 접근성, 근거 공개·감사 로그 |

## 예상 질문과 답
| 질문 | 답 |
|---|---|
| 복지멤버십이랑 뭐가 다른가 | 멤버십은 공적자료 기반 공공급여 안내. 본 제안은 공개 API 전체(지자체 소규모 사업 포함)+마감 관리+서류 준비. 멤버십 가입 유도 링크를 넣어 보완 관계로 설계 |
| 소득을 모르는데 어떻게 판정하나 | 구간 자가신고 → "현재 입력 기준 해당 가능"으로만 표기. 확정은 신청 기관 |
| LLM 환각은 | 판정은 규칙 엔진, AI는 초안·설명. 근거 문장 표시, 사람 승인, 감사 로그 (이미 구현 경험) |
| 구조화 정확도는 | 제출 전 샘플 200건 시험 수치 제시. 실패 사유를 정보원에 피드백하는 루프 자체가 가치 |
| 개인정보는 | 프로필 최소 5항목, 브라우저 저장 우선, 알림 신청 시 연락처만 |
| 수익은 | 가설 단계임을 명시. 소상공인 유료·B2B 화이트라벨·B2G 홍보 도구 |
