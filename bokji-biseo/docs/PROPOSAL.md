# 아이디어 제안서 (초안) — 먼저 찾아오는 복지 비서

> 2026 사회보장 데이터 활용 AI 혁신 아이디어 경진대회 (한국사회보장정보원·대구가톨릭대 공동주최, 보건복지부 후원)
> 공모 분야: **① 서비스 혁신** (부분적으로 ② 복지행정·민원 개선 포함)
> 작성일 2026-11-01 · 공식 제안서 양식(wma.co.kr/ax)에 옮겨 적는 원고. [미검증] 표시는 원문 재확인 필요.

## 1. 제안 요약 (한 문단)

복지로에는 5,300여 건의 복지서비스가 등록돼 있지만, 국민은 **"내가 받을 수 있는 게 생겼다"는 사실을 스스로 검색해야 알 수 있습니다.** 먼저 찾아오는 복지 비서는 한국사회보장정보원의 **중앙부처·지자체 복지서비스 공개 API**를 매일 읽어, AI가 각 서비스의 지원대상·선정기준 문장을 구조화된 조건으로 바꾸고, 사용자가 한 번 적어 둔 최소 프로필(거주 시군구·연령대·가구유형·소득구간·사업자 여부)과 대조해 **새로 생긴 것·바뀐 것·마감이 다가온 것**을 알려줍니다. 알림에서 끝나지 않고 **쉬운말 요약, 필요 서류 체크리스트, 신청 경로**까지 한 장으로 만들어 줍니다. 검색형 포털 위에 **"먼저 알려주고 신청까지 데려다주는" 층**을 얹는 제안입니다.

## 2. 문제 정의

| 현상 | 왜 생기나 |
|---|---|
| 받을 수 있는 서비스를 몰라서 못 받는다 (신청주의) | 복지로·정부24는 **사용자가 검색어를 알아야** 찾아진다. 지자체 소규모 사업(예: 소상공인 공공요금 지원, 청년 월세 특별지원 지역분)은 이름조차 모른다 |
| 알아도 마감을 놓친다 | 접수기간이 짧은 지자체 사업이 많고, 변경·추가 공고를 추적해 주는 도구가 없다 |
| 안내문이 어렵다 | "기준 중위소득 100% 이하 가구 중 ○○인 자" 식의 문장은 60대·다문화 가구가 바로 이해하기 어렵다 |
| 신청 단계에서 포기한다 | 어떤 서류를 어디서 떼야 하는지 흩어져 있다 |

기존 장치와의 관계 (정직하게):
- **복지멤버십(맞춤형 급여 안내)**: 공공급여 중심으로 가입자에게 안내. 가입 절차와 공적자료 연계가 전제이며, 지자체 소규모 사업·민간 서비스·마감 관리·서류 준비는 범위 밖 [미검증: 안내 범위는 공고문 기준 재확인].
- **복지니(복지로 챗봇)**: 묻는 사람에게 답하는 **풀(pull) 방식**. 본 제안은 **푸시(push) + 준비** 방식으로 보완 관계.

## 3. 아이디어 내용

### 3-1. 서비스 흐름

```
① 수집  복지로 공개 API(중앙부처·지자체) 일 1회 → 신규/변경 감지(서비스 ID·수정일 비교)
② 구조화  AI가 "지원대상·선정기준·신청방법" 문장을 조건 JSON으로 추출
          (연령·거주지·가구유형·소득 기준·사업자 요건·접수기간) → 사람 검수 → 규칙 등록
③ 매칭  규칙 엔진이 사용자 프로필과 대조 (판정은 규칙, AI는 추출·설명만)
④ 알림  "새로 생김 / 조건 바뀜 / 마감 D-7" 카카오 알림톡·이메일·앱 푸시
⑤ 준비  쉬운말 요약(60대·다문화 눈높이, 다국어) + 필요 서류 체크리스트 + 온라인 신청 가능 여부·링크
⑥ 되먹임  "신청했어요 / 해당 없어요" 피드백 → 규칙 보정, 정보원에 데이터 품질 리포트 제공
```

### 3-2. 활용하는 사회보장 데이터

| 데이터 | 제공 | 쓰임 |
|---|---|---|
| 중앙부처복지서비스 목록·상세 API (data.go.kr 15090532, `B554287/NationalWelfareInformationsV001`) | 한국사회보장정보원 | 서비스 ID·생애주기·가구유형·관심주제·나이·온라인신청여부 필터로 1차 후보 추출, 상세의 지원대상·선정기준·신청방법 텍스트 구조화 |
| 지자체복지서비스 목록·상세 API (data.go.kr 15108347) | 한국사회보장정보원 | 시군구 단위 사업·접수기간·소관부서 |
| 사회복지시설·사회서비스 제공기관 정보 (서울 열린데이터광장 등 정보원 제공분) | 한국사회보장정보원 | 신청·상담 가능한 가까운 창구 안내 (2단계) |
| 기준 중위소득 고시 등 공개 기준표 | 보건복지부 | 소득구간 자가신고를 기준 % 판정으로 변환 |

수급이력·소득재산 같은 비공개 정보는 쓰지 않습니다. 사용자의 소득은 **구간 자가신고**로 받고, 결과는 "현재 입력 기준 해당 가능"으로만 표기합니다.

### 3-3. AI가 하는 일 / 하지 않는 일

| AI가 하는 일 | 규칙·사람이 하는 일 |
|---|---|
| 지원대상·선정기준 문장 → 조건 JSON 초안 추출 (쪽·문장 인용 포함) | 추출 초안 검수·승인 (담당자 또는 운영자) |
| 안내문을 쉬운말·다국어로 재작성 | 해당 여부 판정 (감사 가능한 규칙 엔진) |
| 사용자 자연어 질문("가게 하는데 전기요금 지원 있나요?")을 프로필·관심주제로 구조화 | 최종 신청 여부 결정은 사용자 |

환각 방지: 판정 근거(어느 서비스의 어느 문장)를 결과마다 표시하고, LLM 컨텍스트와 모델명을 감사 로그로 남깁니다. 이 방식은 제안자가 2026년 공공 AI 대전환 챌린지 출품작(국민 곁에 ON)에서 이미 구현해 운용한 구조입니다.

### 3-4. 대상 사용자 (우선순위)

1. **1인 사업자·소상공인·프리랜서** — 지자체 지원사업이 가장 많이 흩어져 있고 마감이 짧은 집단
2. **직장인 가구** — 출산·육아·주거·돌봄 서비스가 생애주기마다 바뀌는데 추적할 시간이 없는 집단
3. **고령자·다문화 가구** — 쉬운말·음성·다국어 안내로 접근성 보강 (ESG)

## 4. 차별성 (독창성)

| 기존 | 먼저 찾아오는 복지 비서 |
|---|---|
| 검색해야 나온다 (복지로·정부24) | **조건이 맞는 게 생기면 먼저 알린다** |
| 공공급여 중심 안내 (복지멤버십) | 지자체 소규모 사업·민간 서비스까지 **공개 API 전체** |
| 묻고 답하기 (복지니) | 알림 → 쉬운말 → 서류 체크리스트 → 신청 링크까지 **한 장** |
| AI가 판정 | **규칙이 판정, AI는 추출·설명** → 근거 공개, 감사 가능 |
| 사람이 공고를 읽고 규칙 입력 | **AI가 공고 문장에서 조건 초안을 뽑고 사람이 승인** → 5,300건 확장 가능 |

하지 않는 주장: 세계 최초, 수급 자격 확정, 정부 채택.

## 5. 구체성 — 구현 계획

| 단계 | 기간 | 내용 | 산출물 |
|---|---|---|---|
| 0 | 제출 전 | 중앙부처 API 수집 스크립트, 샘플 200건 구조화 시험 | `scripts/fetch_bokjiro.py`, 구조화 정확도 표 |
| 1 | 본선 전(~12/2) | 웹 데모: 프로필 입력 → 해당 후보 → 쉬운말 카드 → 서류 체크리스트 | 심사위원 체험용 데모 페이지 |
| 2 | 1개월 | 지자체 API 결합, 변경 감지·알림(이메일) 자동화, 피드백 수집 | 파일럿 30명 |
| 3 | 3개월 | 카카오 알림톡, 다국어·음성, 시설 데이터로 창구 안내 | 지표: 1인당 발견 서비스 수, 신청 연결률 |

기술: Python(수집·규칙 엔진), LLM API(구조화·쉬운말, 교체 가능), 정적 웹 + 서버리스 함수. 개인정보는 최소 수집·브라우저 저장 우선, 알림 신청 시에만 연락처 보관.

보유 기술(이미 작동 중): 지침 PDF → 규칙 초안 추출 → 담당자 승인 → 판정 → 쉬운말/다국어 안내장 생성 (국민 곁에 ON, Streamlit). 본 제안은 그 입력을 PDF에서 **정보원 공개 API**로 바꾸고 출력을 **개인 알림**으로 바꾸는 것입니다.

## 6. 기대효과

| 대상 | 효과 | 측정 지표(파일럿) |
|---|---|---|
| 국민 | 몰라서 못 받던 서비스 발견, 마감 놓침 감소 | 1인당 발견 건수, 알림→신청 연결률 |
| 복지 행정 | 중복·반복 민원 감소, 공고 문장 품질 피드백 | 구조화 실패 사유 리포트 건수 |
| 정보원 | 공개 API 활용 사례 확대, 데이터 품질 개선 루프 | API 호출·활용 서비스 수 |

## 7. 발전·사업화 가능성 (가설, 검증 전)

- **B2C 무료** 기본 + 소상공인·프리랜서용 유료(사업자 지원사업·세제 일정 결합, 월 구독)
- **B2B**: 세무·노무 사무소가 고객에게 "받을 수 있는 지원" 안내하는 화이트라벨 도구, 기업 임직원 복지 안내
- **B2G**: 지자체 신규 사업 홍보 도구(대상자에게 직접 도달), 공고문 쉬운말 변환 서비스
- 확장: 중소벤처기업부 기업마당, 고용24 등 타 기관 공개 API를 같은 구조화 파이프라인에 연결

## 8. ESG 혁신

- **S**: 정보 격차로 생기는 복지 사각지대 축소, 고령자·다문화 가구 쉬운말·다국어·음성 안내
- **G**: 판정 근거·AI 사용 범위·모델명 공개, 민감정보 미수집, 감사 로그
- **E**: 종이 안내문·방문 민원 감소(정성)

## 9. 한계와 정직한 고지

- 공개 API의 지원대상 문장이 비정형이라 구조화 정확도는 사람 검수에 의존. 정확도 수치는 제출 전 샘플 시험으로 채움.
- 복지멤버십과의 정확한 범위 차이는 공고문으로 재확인 필요 [미검증].
- 소득은 자가신고라 최종 자격은 신청 기관이 판정. 화면에 상시 고지.
