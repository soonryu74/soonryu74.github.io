## [의료기기·개인정보 전문 변호사] 심사 의견

> AI 역할극 의견이며 법률 자문이 아닙니다. 조문 번호는 제 기억에 의존하므로 확인이 필요합니다.

### 1. 이 계획에서 가장 위험한 것 3가지

**① 앱 이름·문맥이 합쳐지면 "장애 보정용 소프트웨어"로 읽힙니다.**
r3 §1은 Apple HAF 허가 트리거를 "청각장애 대상 + 증폭"으로, 식약처 SW 판단요소를 "①의료행위 보조 여부"로 정리했습니다. 그런데 CLAUDE.md §2는 대상을 "난청 어르신"으로 명시하고, §4는 숫자 강조 이유를 "병원·은행에서 사고가 남"이라 적으며, test_protocol.md 과제 2는 "하루 세 번, 식후 30분" 복약 문장의 정확 되말하기를 통과 기준으로 둡니다. 여기에 "들리게"라는 이름(=들리도록 만든다)이 얹히면, 개별 문구는 안전해도 **사용목적 전체가 "난청 보정·복약 오류 방지"** 로 해석될 여지가 생깁니다. 의료기기가 아닌 제품을 의료기기처럼 오인시키는 표시·광고는 의료기기법(제26조 제7항으로 기억)이 별도로 금지합니다. r1 §5의 "치매 48% 감소" 수치가 영상 제목에 들어가는 순간 이 위험은 현실이 됩니다.

**② 서버 경유 요약 = 민감정보 처리·국외이전.**
CLAUDE.md §5는 AI를 "Claude/OpenAI API 서버리스 경유"로 잡았습니다. 병원 대화 요약이 이 경로를 타면 진단·투약 내용(건강정보=민감정보, 개인정보보호법 제23조)과 의사·은행원 등 제3자의 발화가 해외 사업자 서버로 갑니다. "비저장"이어도 전송 자체가 "처리"이고(r3 §2), 운영자 개인이 개인정보처리자가 되어 처리방침·별도 동의·국외이전 고지 의무를 전부 집니다. 1인 운영 무료 앱이 감당할 무게가 아닙니다.

**③ "온디바이스·비저장" 약속이 실제로 지켜지지 않을 가능성.**
r2 §6은 Chrome `processLocally`를 "유일한 무료 경로"로 보되 설치 UX는 **미확인**이라 했고, r3 §5는 60대+ 삼성 92%, 기본 브라우저가 삼성 인터넷이라 합니다. 온디바이스 실패 시 Web Speech API 기본 경로는 브라우저 제조사 서버입니다. 화면엔 "저장 안 함"이라 써 놓고 음성이 외부로 나가면 처리방침 불일치이자 표시광고법상 기만 소지입니다. 아울러 r2 CER 5.9~21%, r4 소음 WER 19~34%인데 "48만 5천 원"을 틀리게 띄워 이체 사고가 나면 면책 문구 없이는 민사 분쟁을 막을 근거가 없습니다.

### 2. 스펙에서 반드시 바꿔야 할 것 3가지

1. **요약을 온디바이스 규칙 기반으로.** v1 요약은 "강조된 숫자·날짜·금액 항목 나열"로 한정(LLM 미사용). 저장 화면 문구: "이 요약을 이 폰에만 저장할까요? 다른 곳으로 보내지 않습니다. **[저장 안 함]**(기본) [이 폰에 저장]". 저장 시 `localStorage`, [지우기] 버튼 상시 노출.
2. **시작 전 고정 안내 + 듣는 중 표시.** [듣기 시작] 바로 아래 24px: "말을 글자로 바꿔 화면에만 보여줍니다. 저장하지 않습니다. 글자·숫자가 틀릴 수 있으니 돈과 약은 말로 다시 확인하세요." 인식 중 상단 32px 고정: "● 듣는 중 · 저장 안 함". 온디바이스 불가 판정 시 시작 전에 "이 브라우저에서는 소리가 브라우저 회사 서버로 전송됩니다. 계속할까요?" 를 띄우고 처리방침에 동일 문장을 넣을 것.
3. **표현 규칙을 코드 옆 문서로 고정.** 앱 이름 옆 태그라인 "말을 큰 글자로" 상시 병기. 금지어: 난청·청각장애·보청기·청력·증폭·치매·사고 방지·복약 오류. 허용: "잘 안 들릴 때 눈으로 확인", "자꾸 되물으실 때". 유튜브 제목·썸네일·설명란·앱 첫 화면·CLAUDE.md §2·§4에 동일 적용("난청 어르신" → "귀가 어두우신 어르신", "사고가 남" → "숫자를 눈으로 확인").

### 3. 빼야 할 것 1가지

**v1의 서버리스 경유 AI 요약.** 서버가 없으면 운영자는 개인정보처리자 지위에서 사실상 벗어나고, 처리방침은 한 문단이면 됩니다. 법적 부담의 8할이 이 한 줄에서 사라집니다.

### 4. 다른 전문가들과 의견이 갈릴 만한 지점

**"난청" 키워드 사용 범위.** 마케팅·유튜브 쪽은 검색 유입을 위해 제목에 "난청 부모님"을 넣고 싶어 할 것이고, "소보로도 고령층·청각장애인을 내걸지만 규제받지 않는다"(r2 §5)고 반박할 것입니다. 제 입장: 소보로는 범용 STT이고 이름이 기능을 주장하지 않습니다. 우리는 "들리게"+병원+약+숫자로 위험이 **누적**됩니다. 타협안: 통계·교육 콘텐츠("65세 이상 38%", r1 §5)에서는 허용, 앱 이름·첫 화면·스토어 설명·영상 제목처럼 **앱 기능과 붙는 자리**에서는 금지.

### 5. 노인 테스트 설계 수정 요구 2가지

1. **"구두 고지"를 서면 동의로.** 녹음이 없어도 관찰 메모·상품권 지급·유튜브 출연 여부는 문서로 남겨야 합니다. 모집 조건의 "난청 자각·보청기 착용"은 건강정보이므로 **기록하지 말고** 자기보고로 구두 확인만 하십시오. 80세+ 저시력 쌍은 본인 동의에 보호자 입회, 요양보호사 쌍은 센터 승인 추가. 상품권은 건당 5만 원 이하로 하여 주민번호 수집을 피하십시오. 온디바이스가 안 되는 기기에서는 참여자에게 "소리가 외부 서버로 갈 수 있음"을 먼저 알리십시오.
2. **"녹음 아님" 인지 측정 추가.** 자막을 읽는 어르신이 앱 사용자가 아니라는 점이 이 앱의 특수성입니다. 과제 4 뒤에 어르신에게 "이거 녹음되는 거예요?"를 묻고 "아니요, 화면에만"이라 답하는지를 6/6 통과 기준으로 넣으십시오. 아울러 사/팔 오인식이 나왔을 때 대화 상대가 말로 재확인하는지를 기록하면 면책 문구의 실효성 근거가 됩니다.

### 6. 한 줄 판정

**조건부 진행** — v1을 "서버 없음·온디바이스 실패 시 사전 고지·표현 규칙 문서화" 세 조건으로 묶으면 규제·개인정보 위험이 관리 가능한 수준으로 내려갑니다.
