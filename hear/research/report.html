귀가 어두우신 부모님과 대화하는 앱, 만들 것인가

2026년 9월 6일 · 노모어매뉴얼 대표님 보고용 · 작성 Claude Code

구성: 글로벌 시장 조사 4건 → 전문가 패널 5인 심사 → 노인 테스트 설계 → v1 스펙·일정

먼저 밝혀둘 두 가지. ① 노인 실사용 테스트는 실행하지 못했습니다. 제가 사람을 모집할 수 없어 설계안과 통과 기준으로 대체했고, 실행은 대표님 몫입니다. ② "전문가 토론"은 AI 역할극 패널입니다. 실제 전문가의 자문이 아니며, 특히 법률 의견은 반드시 변호사 확인이 필요합니다.

결론 조건부 진행

만들 가치는 있습니다. 시장에 빈자리가 실제로 있고, 근거도 있습니다. 다만 초안 그대로는 안 되고, 패널 5인이 공통으로 요구한 세 가지를 바꾼 뒤에 착수해야 합니다.

  1. 서버 경유 AI 요약을 v1에서 뺀다. 5인 전원 일치. 비저장 약속·개인정보·비용·오류 누적, 네 가지 이유가 한 기능에 몰려 있습니다. 대신 숫자·날짜·금액이 나온 문장을 원문 그대로 모아 보여주기(기기 안에서, 규칙 기반)로 바꿉니다.
  2. 폰을 "상대방이 들고 어르신이 건너다본다"는 장면을 버린다. 4인이 지적. 그 거리에서는 40px도 읽기 임계선입니다. 탁자 모드(폰을 눕히면 자막이 어르신 쪽으로 180° 돌아감)와 기본 글자 40px로 바꿉니다.
  3. 흘러가는 자막 대신 한 문장 고정. 버튼을 누르는 동안 듣고, 손을 떼면 그 문장이 2줄로 고정되어 다음 문장까지 남습니다. 확정된 글자만 보여주고, 미확정 글자는 그리지 않습니다.

착수 시점은 전략 패널의 "보류" 의견을 받아들여 크게보기 완료 정의 4개 통과 후로 둡니다. 그 전까지는 코드 없이 할 수 있는 두 가지, ① "갤럭시·아이폰에 이미 있는 무료 자막 켜기" 영상 1편 ② 그 무료 자막으로 6쌍 사전 테스트를 먼저 합니다. 사전 테스트에서 숫자 오독·거리·자세 문제가 실제로 관찰되지 않으면 앱을 만들지 않고 콘텐츠로 끝냅니다.

3-1. 개인정보·통신비밀

  • 통신비밀보호법은 타인 간 대화 녹음을 금합니다. 보호자가 그 자리에서 함께 대화하는 당사자는 해당 없음(판례). 병원·은행에서는 직원이 보이는 상태로 쓰면 당사자 요건을 채웁니다.
  • 저장 없는 실시간 전사가 "녹음"인지는 명문 해석 미확인. 클라우드 STT는 서버 전송이므로 개인정보 "처리"에는 해당합니다. 서버가 없으면 운영자는 사실상 개인정보처리자 부담에서 벗어납니다. 이것이 AI 요약을 빼는 법적 이유입니다.
  • 온디바이스가 안 되는 기기에서 Web Speech 기본 경로는 브라우저 제조사 서버입니다. "저장 안 함"이라 써 놓고 음성이 나가면 표시 불일치. 시작 전 사전 고지 모달이 필요합니다.
  • 은행 창구에서 폰을 세우면 "촬영 금지"로 제지당할 수 있습니다(현장 패널). 탁자 모드가 이 문제도 완화합니다.

5장전문가 패널 5인 심사 AI 역할극

각자 조사 4건과 인수인계서, 테스트 설계안을 읽고 독립적으로 의견을 냈습니다. 판정은 조건부 진행 4, 보류 1.

이비인후과 전문의·청능사 조건부 진행

  • 자막 오류가 청각 오류보다 위험하다. 안 들리면 되묻지만, 화면에 찍힌 숫자는 되묻지 않고 믿는다.
  • 폰이 얼굴을 가린다. 난청 노인은 입 모양으로 고주파 자음을 보완한다. 자막이 독순을 빼앗는 구조.
  • 24px는 건너편 폰에서 임계 아래. 상대방 모드 40/56/72px 기본 56, 어르신 손에 들 때 32/40/56 기본 40.
  • 숫자는 확정 결과만 표시, 한글 수사("세 번", "스무 알")를 아라비아로 병기하는 수사 사전 필요. 문장 확정 후 "읽는 중…"으로 화자를 멈추게 할 것.

빼라: AI 요약. 원문 ASR 오류 위에 재생성 오류가 겹친다. 갈리는 지점: 읽는 순간의 폰은 어르신 손에 있어야 한다(설치·시작은 보호자).

접근성 UX 연구자 조건부 진행

  • 마이크와 화면이 반대를 본다. 마이크는 화자 50cm 이내, 화면은 어르신 쪽. 초안은 둘을 동시에 만족 못 한다.
  • 미확정 글자 처리가 스펙에 없다. 읽던 글자가 바뀌면 노인은 처음부터 다시 읽는다. 깜빡임 금지 조항에도 걸릴 수 있다.
  • 틀렸을 때 복구 경로가 없다. [다시 말해주세요] 버튼(≥19mm, 어르신이 누름), 숫자 병기, 마지막 숫자 문장 상단 고정.
  • 표시 규칙 명문화: 고정 2줄, 구문 단위 줄바꿈, 흘림 금지, 확정 줄 최소 3초 유지, 새 문장은 페이지 교체. "어르신께 보여주기" 모드 = 180° 뒤집기 + 가로 전체화면 + 버튼 숨김.

빼라: AI 요약(전문이 서버로 나가야 함). 갈리는 지점: 미확정 글자는 기본 비표시. "멈춘 화면"보다 "바뀌는 글자"가 더 큰 이탈을 부른다. 테스트에서 A/B로 확인.

의료기기·개인정보 변호사 조건부 진행

  • 이름·문맥이 합쳐지면 "장애 보정 SW"로 읽힌다. 「들리게」 + 병원 + 약 + 숫자 강조 = 사용목적이 누적된다. 의료기기 오인 표시·광고는 별도 금지 조항.
  • 서버 경유 요약 = 민감정보(건강정보) 국외이전. 1인 운영 무료 앱이 질 무게가 아니다.
  • "온디바이스·비저장" 약속이 안 지켜질 수 있다. 온디바이스 실패 시 브라우저 제조사 서버로 간다. 사전 고지 모달 필수.
  • 시작 화면 고정 문구: "말을 글자로 바꿔 화면에만 보여줍니다. 저장하지 않습니다. 글자·숫자가 틀릴 수 있으니 돈과 약은 말로 다시 확인하세요."

빼라: 서버리스 경유 AI 요약. 서버가 없으면 법적 부담의 8할이 사라진다. 갈리는 지점: "난청" 키워드는 통계·교육 콘텐츠에선 허용, 앱 이름·첫 화면·영상 제목처럼 기능과 붙는 자리에선 금지.

요양보호사·복지관 현장 실무자 조건부 진행

  • "상대가 들고 어르신이 본다"는 현장과 다르다. 어르신은 폰이 아니라 사람 얼굴을 본다. 폰을 얼굴 20cm까지 갖다 대고, "내가 귀머거리냐"며 밀어내는 분이 열에 셋(추정).
  • 요양보호사가 근무 중 폰을 꺼내는 건 비현실적. 민원·규정·양손이 찼음. 요양보호사 다수가 60대라 본인도 노안.
  • 숫자를 크게 강조할수록 틀렸을 때 사고가 커진다. 화면을 사람 말보다 믿는다.
  • 연속 인식 → 한 문장 푸시투토크. 우리가 원래 난청 어르신께 말하는 방식(짧게, 끄덕임 기다리기)과 같다. 탁자 모드: 폰을 둘 사이에 눕히면 자막이 어르신 쪽으로 돌고, 상대 쪽 위 한 줄에 같은 글.

빼라: 종료 요약. 요약이 필요한 사람은 그 자리에 없던 가족인데 비저장이라 전달 못 한다. 갈리는 지점: v1 사용자는 자녀·배우자. 요양보호사는 채널이지 사용자가 아니다. 치매 동반 1쌍 테스트 추가.

시니어 제품 전략가·크리에이터 비즈니스 보류

  • 범위 확산. 인수인계서가 스스로 1위 리스크로 명시한 것을 지금 어기고 있다. 미완성 앱 2개 = 미완성 시리즈 2개. 구독자 1만 채널에서 "만드는 과정"을 두 번 끊으면 신뢰 손실.
  • 차별점이 30초 안에 설명되지 않는다. 첫 댓글은 "갤럭시 설정 켜면 되는데요?"다. 한 문장으로 못 만들면 영상이 안 돈다.
  • 퍼널이 없다. 비저장·로그인 없음·종료 후 연결점 0. "좋은 일 한 번"으로 끝난다.
  • 종료 화면 하단 링크 1개: "갤럭시·아이폰에 이미 있는 무료 자막 켜는 법" → 채널 영상. 경쟁사 기능을 앱 안에서 먼저 안내하는 게 "이미 있는 것을 닿게"와 일치하고 유일한 퍼널 연결점.

빼라: LLM 요약. 갈리는 지점: 크게보기 완료 전 코드 한 줄도 쓰지 않는다. 단 콘텐츠는 지금 시작. 테스트에 Live Transcribe 비교군 추가, 차이가 수치로 안 나오면 앱 대신 콘텐츠로 전환.

6장노인 테스트 설계 미실행

제가 실행할 수 없는 부분입니다. 아래는 초안에 패널 요구를 반영한 수정본이며, 실행 주체는 대표님입니다. 목적은 "설명 없이 30초 안에 켜고, 어르신이 숫자를 읽을 수 있는가"입니다.

6-1. 두 단계로 나눈다

0단계 (지금, 코드 없음): 갤럭시 Live Transcribe / 아이폰 Live Captions만으로 6쌍 시행. 아래 관찰 항목 중 숫자 오독·읽기 거리·폰 자세·거부 신호가 실제로 나오는지 본다. 안 나오면 앱을 만들지 않는다. 나오면 그 항목이 v1의 존재 이유가 된다.

1단계 (v1 완성 후): 같은 6쌍 + 치매 동반 1쌍, 같은 문장으로 무료 자막 vs v1 교차 시행.

6-3. 절차 (설명 없이, 카카오톡으로 링크 전송)

  1. 카카오톡 안에서 링크 열기 → [듣기 시작]까지 30초 이내. 인앱 브라우저→크롬 전환 시간 포함해 측정.
  2. 같은 문장을 자막 없이 1회 → 자막 있고 1회. 대화 상대가 외워서 평소대로 말한다(종이 보고 읽기 금지). 되묻기는 관찰자가 아니라 상대가 "확인차 한 번만요"로.
    • "다음 진료는 10월 14일 오후 3시예요"
    • "이 약은 하루 세 번, 식후 30분에 드세요"
    • "이체 금액이 48만 5천 원 맞으세요?" + 삼/사/팔, 십/이십, 일/칠 세트 각 1문장
    • "요즘 잠은 잘 주무세요?"
  3. 의도적 오인식 1회(사→팔로 조작된 자막)를 넣어 누가, 몇 초 만에 알아채고 어떻게 복구하는지 본다.
  4. 글자 크기 변경을 스스로 찾는지, 폰을 어르신이 집어 드는지 관찰.
  5. 종료 화면(숫자 모아보기) 읽고 "오늘 약속이 언제였죠?" 답하기.
  6. 어르신께 "이거 녹음되는 거예요?" → "아니요, 화면에만"이라 답하는지.

6-5. 윤리·동의 (법률 패널 반영)

  • 녹음·녹화 없음. 관찰 메모만. 참여·상품권·유튜브 출연 여부는 서면 동의.
  • 청력·보청기·질환은 건강정보이므로 기록하지 않고 구두 자기보고만. 80세+ 쌍은 보호자 입회, 요양보호사 쌍은 센터 승인.
  • 상품권 건당 5만 원 이하(주민번호 수집 회피).
  • 온디바이스가 안 되는 기기는 "소리가 외부 서버로 갈 수 있음"을 먼저 알린다.

골격. 푸시투토크, 고정 2줄 표시, 40/56/72px, 탁자 모드 180° 회전. 크게보기 토큰 재사용.

음성인식 경로 분기. 온디바이스 판정 → 크롬 열기 → 사전 고지 모달 → iOS 안내 → 텍스트 폴백. 기기 4종 실기.

한글 수사 사전(하나·둘·세 번·스무·닷새·만·천) → 아라비아 병기. 확정 결과만 강조. 상단 고정. 탭해서 고치기.

Day 7–8

종료 화면: 숫자 문장 모아보기 + 확인 질문 + [저장 안 함] 기본 + [이 폰에 저장] + [지우기]. WORDS.md 작성.

Day 9–10

자동 검증: 대비 7:1, 터치 타겟 ≥19mm, 200% 확대, 깜빡임 없음. 텍스트 폴백 회귀.

Day 11–12

PWA, 홈 화면 추가, 서브도메인 배포.

Day 13–14

1단계 테스트 7쌍 (6장). 통과 못 한 지표는 기능 추가가 아니라 뺄 것부터 찾는다.

완료 정의

  1. 자녀가 설명 없이 카카오톡 링크에서 30초 안에 첫 자막을 띄운다 (5/6쌍)
  2. 어르신이 탁자 모드에서 숫자 문장 3개를 정확히 읽는다 (5/6쌍)
  3. 모든 텍스트 대비 7:1, 터치 타겟 19mm 이상이 스크립트로 검증된다
  4. 음성 미지원 브라우저에서 텍스트 입력으로 정상 동작한다
  5. 서버 호출이 0건임을 네트워크 로그로 확인한다
  6. 어르신 6/6이 "녹음 아니고 화면에만"이라고 답한다
