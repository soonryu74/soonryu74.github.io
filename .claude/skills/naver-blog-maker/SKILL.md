# 네이버 블로그 메이커 (naver-blog-maker)

주제 한 줄과 메모를 받아 **글 초안, 이미지, 복사용 미리보기**를 한 번에 만든다.
발행은 자동화하지 않는다. 네이버 블로그는 공식 글쓰기 통로가 없고, 자동 로그인은 계정 제재 위험이 있다.

## 결과물

`_naver-blog/<날짜>-<영문-주제>/` 폴더 하나 (밑줄로 시작해 사이트에는 올라가지 않는다)

| 파일 | 내용 |
|---|---|
| `post.json` | 글 원본. 고칠 때는 이 파일만 고친다 |
| `images/cover.jpg` | 대표 이미지 (AI 배경 + 코드로 얹은 제목) |
| `images/*.png` | 정리 그림 (순서도, 항목 정리) |
| `preview.html` | 제목·본문·해시태그 복사 버튼이 있는 미리보기 |

## 작업 순서

1. **재료 확인** — 주제, 메모, 직접 찍은 사진·캡처가 있는지. 없는 사실은 지어내지 않는다. 확인이 안 되는 기능·가격·날짜는 사용자에게 묻거나 뺀다.
2. **`post.json` 작성** — 아래 글 공식과 형식을 따른다. `assets/sample-post.json`을 틀로 쓴다.
3. **생성** — `node .claude/skills/naver-blog-maker/assets/build.mjs <post.json 경로>`
4. **눈으로 확인** — 만든 이미지를 직접 열어 글자 넘침, 배경 속 엉뚱한 글자를 본다. 배경이 마음에 안 들면 `--regen`.
5. **전달** — `preview.html`과 이미지를 사용자에게 보낸다.

실행 옵션: `--no-ai` AI 배경 없이 그라데이션 배경 / `--regen` AI 배경 새로 만들기.
AI 배경은 Gemini 이미지 모델을 쓴다. 내 컴퓨터에서 돌릴 때는 `GEMINI_API_KEY` 환경변수가 필요하다 (맥·윈도우 동일). 없으면 자동으로 그라데이션 배경이 된다.

## 글 공식

| 자리 | 규칙 |
|---|---|
| 제목 | 질문 또는 결과 + 주제어 + 시리즈 번호(①②③). 30자 안팎 |
| 맨 위 | 대표 이미지 → 요약 한 문단(무엇을, 누구에게, 얻는 것) |
| 큰 소제목 `h2` | 3~4개. 첫 번째는 독자의 고민을 묻는 질문 |
| 작은 소제목 `h3` | `이름 \| 한 줄 설명` 형식. 항목마다 색이 자동으로 바뀐다 |
| 문단 `p` | 2~3문장. 한 소제목에 2~3문단 |
| 굵은 결론 `bold` | 소제목마다 마지막에 한 줄. 그 부분의 요점 |
| 이미지 | 대표 1 + 정리 그림 1~2 + 직접 찍은 사진·캡처 자리(`photo`) 1 이상 |
| 맺음 `closing` | 가운데 정렬 2~3줄. 권유로 끝낸다 |
| 해시태그 | 10~12개. 주제어, 대상 독자, 도구 이름 |

### 제목과 말투 (이 블로그 전용)

- 금지어: 기본기, 총정리, 사용법, 기초, 완벽 정리
- 넣으면 좋은 말: 숨겨진, 자동화, 꿀조합, 이거면 끝, 몰랐죠?, 무료. 사실일 때만 쓴다.
- 과장·낚시 금지. "무조건", "100%", "월 천만 원" 같은 표현을 쓰지 않는다.
- 따뜻한 선생님 말투. "어렵지 않아요", "여러분도 할 수 있어요".
- 전문용어는 쉬운 비유로 풀고, 영어는 한글 발음을 같이 적는다. 예: 클로드 코드(Claude Code)
- 맥과 윈도우에서 방법이 다르면 둘을 나란히 적는다.
- 50대도 따라 할 수 있는 순서로 쓴다.

## post.json 형식

```json
{
  "brand": "블로그 이름 (이미지에 찍힌다. 비워도 됨)",
  "title": "글 제목",
  "images": [
    { "id": "cover", "kind": "cover", "kicker": "한 줄 문구", "title1": "큰 제목 1줄", "title2": "큰 제목 2줄",
      "pill_title": "상자 제목", "pill_sub": "상자 설명", "tags": "키워드 · 키워드",
      "bg_prompt": "배경 그림 설명 (영어, 글자 없는 장면)" },
    { "id": "flow", "kind": "steps", "title": "...", "subtitle": "...", "items": [{ "label": "단계 이름", "desc": "설명" }] },
    { "id": "parts", "kind": "list", "title": "...", "subtitle": "...", "items": [{ "label": "꼬리표", "title": "항목", "desc": "설명" }] }
  ],
  "blocks": [
    { "type": "image", "id": "cover", "caption": "사진 설명" },
    { "type": "p", "text": "문단. **굵게** 가능" },
    { "type": "h2", "text": "큰 소제목" },
    { "type": "h3", "text": "이름 | 한 줄 설명" },
    { "type": "bold", "text": "굵은 한 줄 결론" },
    { "type": "bullets", "items": ["항목"] },
    { "type": "photo", "note": "직접 넣을 사진 설명", "caption": "사진 설명" },
    { "type": "cta", "text": "안내 문구", "url": "https://..." },
    { "type": "closing", "lines": ["맺음 1", "맺음 2"] }
  ],
  "hashtags": ["태그"]
}
```

이미지 글자 수 기준: 대표 이미지 큰 제목은 한 줄 10자 이내, `steps`는 5단계 이하가 보기 좋고 단계 이름은 7자 이내, `list`는 3~5개.

## 지킬 것

- AI 그림에 글자를 넣지 않는다. 글자는 전부 `build.mjs`가 얹는다.
- 남의 글을 베끼지 않는다. 형식만 참고하고 내용은 사용자의 자료로 쓴다.
- 글마다 사용자의 실제 경험·사진이 들어갈 자리(`photo`)를 남긴다.
- 발행 버튼은 사용자가 누른다.
