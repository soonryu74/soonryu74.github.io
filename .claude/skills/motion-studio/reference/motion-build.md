# ⑦ 장면 코드 · 굽기 전 확인 · 굽기

입력: 확정 캔버스(`canvas/확정/`) + 기획서 §5 효과 계획 + §6 글꼴 + §7 녹음.
영상마다 **그 영상만의 장면 코드(`scenes.py`)**를 새로 짠다. 장면 템플릿을 고르는 방식이 아니다 — 그래야 영상이 뻔해지지 않는다.

## 1. 작업 폴더 (영상 한 편)
```
<작업 폴더>/
├ 기획서.md
├ canvas/처음/   스킬이 처음 올린 아트보드 (비교 기준)
├ canvas/확정/   검수 끝난 아트보드 + canvas.json
├ 재료/          그림 (캔버스 번호와 같은 이름 <번호>.png …)
├ fonts/         유저가 받아 넣은 글꼴
├ voice/         raw/ 녹음 원본 · 01.wav … 자른 것
├ sf2/           (배경음 사운드폰트 — 다른 곳에 있으면 환경변수 SF2)
├ scenes.py        이 영상의 장면 코드
└ out/           _sheet.jpg 점검 모음 · mix.wav 소리 · 완성 mp4
```
`scenes.py`는 작업 폴더에서 돈다 — canvas.py가 `fonts/` · `재료/`를 작업 폴더에서 찾는다.

## 2. 장면 코드 만드는 법
`examples/scenes_example.py`를 먼저 읽는다 — 구조를 보여 주는 뼈대다. 복사해 값만 바꾸는 틀이 아니다.
맨 위 `SKILL` 경로는 이 스킬이 실제로 설치된 곳으로 적는다(스킬을 불렀을 때 보이는 기본 폴더 · 또는 환경변수 `MOTION_SKILL`).
1. 아트보드마다 `canvas.read_board()` → `(root, els)`. 요소 = 그 장면이 «다 나왔을 때» 모습(위치 · 크기 · 글자 · 색 · 그림).
2. 장면 함수 `sN(lt, root, els)` = **그리기 → 찍기**. 기획서 §5의 찍는 법 · 등장 · 머무는 동안 · 강조대로. 요소의 마지막 모습(자리 · 크기 · 글자 · 색)은 아트보드 그대로(바닥 3) — 카메라는 그 화면을 찍는 방법이다.
   - 그리기: 요소 = `canvas.layer(e)` · 등장 = `appear.put(img, e, k, how)`(fade · up/down/left/right · pop · zoom · wipe · `off` 깊이 층) · `appear.type_text` · `appear.lines`.
   - 강조 = `core/fx.py`(효과 32개 — reference/effects.md «캔버스 요소에 거는 법»: `canvas.box(e)` · `canvas.pic(e)`).
   - 찍기 = `camera.keys` · `camera.on` · `camera.drift` · `camera.defocus` … → `camera.shoot(img, c, (W, H))` (reference/camera.md).
   - 머무는 동안 · β 등장 · 퇴장 = `core/motion.py`(둥실 · 숨쉬기 · 맥박 · 밑줄 · 형광펜 · 흐림→또렷 · 돌며 · 뒤집혀 · 터지기 · 흩어지기).
   - **키트** = `K = kit.load('<기획서 §2-B 키트>')`. 장면 경계 편집은 `EDIT = K.cuts([들어오는 장면의 세기 …])`(키트 안에서 세기대로 · 같은 것 연달아 안 나오게) → `frame(t)`에서 `K.edit(이름, a, b, u, **옵션)`. 메모로 정한 편집은 그 칸만 손으로 바꾼다.
   - **화면 겹** = `frame(t)` 끝에서 `K.finish(img, t)` 한 번(전환 중에도 같은 겹이 걸리게).
   - **PLAN** = 기획서 §5를 장면마다 dict 로 옮긴다 — `{'level': 1~3, 'camera': [...], 'enter': [...], 'emph': [...], 'kick': '이름' 또는 None, 'borrow': '이유'(키트 밖일 때)}`. `--check`가 이걸 본다. 이름은 effects-index · kits.md 에 쓰인 이름 그대로.
   - **킥이 시간 조작이면** `reference/time.md` + `examples/rewind_example.py` — 원본 시간에 A · B 갈래를 그리고 `timewarp.Warp` 지도로 화면 · 소리를 함께 바꾼다.
   - **요소가 차례로 튀어나오고 멈추는 것만으로 장면을 채우지 않는다** — 그건 등장이지 연출이 아니다.
   - 재료에 없는 움직임이 내용에 맞으면 scenes.py 안에서 새로 짠다. 좋으면 camera.py · appear.py · fx.py에 보탠다.
2-B. **굽기 속도** — 프레임마다 화면 전체를 다시 그리면 느리다.
   - 다 나와서 더 안 바뀌는 바탕 · 크게 흐린 화면은 `bake.memo(키, 그리는 함수)`로 한 번만 그리고 다시 쓴다(본보기 참고). 카메라만 움직이는 구간이 가장 큰 덕을 본다.
   - 움직임 흐림(`shoot(mblur=…)`)은 빠르게 옮겨 가는 순간에만 · 기울기 없는 카메라가 가장 빠르다.
3. 장면 길이 = 대사 길이 + 0.7초 이상(대사가 있을 때) · 대사 없는 장면은 다 읽히고 지루하지 않을 만큼(지난 영상 감 2~4초).
4. 소리 `build_audio(path)`: `audio.bgm(sections, DUR, palette)` + 효과음(`audio.new_track` 에 `whoosh` · `hit` · `chime` · `tick` · `mallet`) + 대사 → `audio.mixdown(DUR, path, bgm, sfx, voices)`.
   - 무드: sting · intro · calm · groove · bouncy · build · drop · main · tense · outro — 장면 흐름에 맞춰 구간을 나눈다(훅 짧게 치고 · 설명에서 쌓고 · 결과에서 터지고 · 마무리 …는 지난 영상의 감).
   - 사운드폰트가 없으면 `bgm`이 안내를 띄우고 멈춘다 → 배경음 없이 진행하거나 받게 한다(check.py).
5. 끝에 `bake.cli(sys.modules[__name__], out='out/<제목>.mp4', audio=build_audio)`.

## 3. 굽기 전 확인 — 유저 개입은 여기 한 번
1. `python3 scenes.py --sheet` → `out/_sheet.jpg` (장면마다 세 장) · `python3 scenes.py --check` → `out/_check.md` 점검 보고 + `out/_motion.jpg` 움직임 시간 띠.
2. **Claude가 먼저 본다**: 글자 넘침 · 겹침 · 잘림 · 빈 화면 · 요소 모습이 아트보드와 다른 곳 · 움직임이 메모대로인지. 고칠 게 있으면 고치고 다시 모음. 의심 가는 순간은 `--still 4.2 4.4`로 한 장씩.
   - **점검 보고** — 문제로 세는 것: 이유 없는 키트 밖 · 세기 3 연달아 / 40% 넘음 · 같은 편집 연달아 · 한 장면 강조 둘 이상 · 같은 등장 절반 넘게 · 내려앉기가 세기 3 밖 · 킥 둘 이상 · 멈춘 구간(2.5초) · 카메라가 거의 안 움직이는 장면이 절반 넘음. 빌림은 따로 칸에 보이기만 한다(벌점 아님). «카메라 실제» 칸은 굽기 엔진이 찍은 카메라를 재서 채운다(PLAN 이 아니라 실제 움직임 · SCENES 와 PLAN 장면 수가 같아야 잰다). «문제 0»이 목표지만 이유가 있으면 기획서 §8에 적고 넘어간다. 그 밖의 칸은 PLAN 을 믿으므로 PLAN 이 실제 코드와 같은지도 본다.
   - **움직임 시간 띠** — 같은 리듬(요소 등장 → 정지)이 되풀이되거나 강조가 장면마다 있으면 다시 짠다. 카메라 · 편집을 하나도 안 쓴 영상은 통과가 아니다.
3. 유저에게 모음 한 장과 한 줄: «장면 N개, 약 M초예요. 굽기 진행할까요?»

## 4. 굽기
- 움직임 · 타이밍을 먼저 보고 싶으면 `python3 scenes.py --draft` → `out/<제목>_draft.mp4`(초당 프레임 절반 · 낮은 화질 · 절반 시간).
- `python3 scenes.py --bake` → `out/<제목>.mp4`. 굽기는 컴퓨터 코어 수만큼 나눠 돈다(환경변수 `MOTION_WORKERS`로 바꿀 수 있다).
- 굽기 명령은 한 번에 오래 걸린다 — 기다리며 다른 단계를 되풀이하지 않는다(점검 모음을 다시 뽑거나 프레임을 뜯어 보지 않는다).
- 길이 제한은 없다. 길면 굽는 데 오래 걸리므로 «part 1/2/3으로 나눠 굽기»를 권한다:
  `--part 1/3` → `--part 2/3` → `--part 3/3` → `--join 3` (조각마다 따로 돌려 한 번 명령이 오래 걸리지 않게).
- 완성 파일을 유저에게 전한다(폴더 연결이면 작업 폴더 `out/` · 클라우드면 파일로 보낸다). 기획서 «지금 단계» = 완성.
- 결과 영상은 유저가 먼저 본다 — 굽고 나서 프레임을 뜯어 따로 분석하지 않는다.

## 5. 썸네일 (요청할 때만)
같은 캔버스에 썸네일 아트보드(`Thumb.dc.html` · 1280×720 또는 1080×1920)를 하나 더해 그린다. 필요하면 `canvas.py board`로 PNG를 만든다.
