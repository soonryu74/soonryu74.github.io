# motion-studio

> **첫 1초에 손가락을 멈추게 하고, 끝까지 눈을 못 떼게 만든다. 가진 기술은 아끼지 않는다.**

쓰는 사람은 디테일을 직접 고치기 어려운 사람이다. 목표는 **최소한의 노력으로 최대의 결과물** — 대부분 스킬이 알아서 하고, 유저 개입은 캔버스 검수와 굽기 전 확인 한 번뿐이다(굽고 나서 보며 짚는 피드백은 원할 때만).
«내용 → 바로 완성 영상»은 유저 의도가 들어갈 틈이 없다. 그래서 그 사이에 **눈으로 보고 손으로 고치는 캔버스 초안**을 둔다.

## 설계 사상 — 스킬은 바닥, 모델이 천장
이 스킬은 품질이 이 아래로 떨어지지 않게 받쳐 준다. 얼마나 잘 만드느냐는 모델이 정한다.

**바닥 — 무엇이 있어도 지킨다**
1. 원문에 없는 사실 · 숫자를 지어내지 않는다
2. 폰에서 읽힌다 (핵심 글자 크기 · 안전 영역)
3. 캔버스에서 확정한 모습(요소의 자리 · 크기 · 글자 · 색)이 영상에 그대로 나온다 — 카메라는 그 화면을 찍는 방법
4. 굽기 전 확인은 한 번 · 유저 개입은 최소
5. 유저 메모가 스킬의 판단보다 먼저

**천장을 막지 않는다**
- reference의 표 · 기본값 · 효과 사전 · 샘플 코드는 출발점이지 메뉴가 아니다. 상한 대신 목적으로 판단하고(«피곤하지 않게 · 효과가 내용을 덮지 않게»), 더 나은 움직임은 새로 만들고, 엔진이 못 그리면 엔진을 늘린다.
- 영상은 «요소가 나타나는 것»이 아니라 «찍고 잇는 것»이다 — 장면마다 찍는 법(카메라)과 잇는 법(편집)을 정한다. 키트 · 카메라 크기의 기준은 `kits.md` · `camera.md`.

## Pipeline overview
```
① 시작 카드 (intro.html)
② 기획서.md 정리                      ← 이어 가기 문서 · 압축 뒤엔 이것부터 읽는다
②-B 표현 기획 — 콘셉트 · 훅 · 보여 주는 방법 · 시각 방향 · 키트 · 킥
③ 캔버스 초안 (아트보드 한 장 = 장면 하나)
   ⏸ 확인 1 — 유저 검수 · 수정 · 메모 → «검수 끝»
④ 캔버스 다시 읽기 → 고친 것 · 메모 정리 → 효과 계획 (세기 지도)
⑤ 글꼴 받기 (없는 것만)
⑥ 나레이션 원고 → 녹음 받기 → 정리          (선택)
⑦ 장면 코드 → 점검 모음 · 점검 보고(Claude 먼저 확인)
   ⏸ 확인 2 — «굽기 진행할까요?»
   → 굽기 → mp4 + 피드백뷰어.html
⑧ 피드백 (선택 · 몇 번이든) — [피드백] 붙여 넣기 → 자리 찾기 → «제가 이해한 것» ⏸ OK → 고침 → 다시 굽기
```
**만화 페이지 길 (β) — `comic.md`**: 유저가 완성된 만화 페이지를 주고 motion-studio 로 보여 달라고 하면 ②~④ 캔버스 대신 — 칸 찾기 → ⏸ 칸 확인 그림 → 장면 프롬프트를 읽고 컷 연출표 → ⏸ 확인 2(연출표 · «굽기 진행할까요?») → 굽기. 페이지가 곧 캔버스다(그림은 고치지 않는다). 컷별 수정은 유저 말 → 연출표 그 줄만.

**이어 갈 때(압축 · 새 세션)**: 작업 폴더의 `기획서.md`를 열고 «0. 지금 단계»에서 다시 시작한다. 상태는 기억이 아니라 파일로 확인한다.
**reference는 그 단계에서만 읽는다** — 처음부터 전부 읽지 않는다.

## 처음 쓰는 경우 — 점검 (한 번)
`python3 <스킬>/scripts/check.py <작업 폴더> --fix --fonts "<캔버스에 쓸 글꼴들>"` — ffmpeg · 패키지 · 사운드폰트 · 글꼴을 보고 **빠진 것은 묻지 않고 받아 쓴다**(클라우드 기본 · 글꼴 = Google Fonts 원본 → 작업 폴더 `fonts/`). 받기가 실패한 것만 유저에게 요청한다(무엇이 · 왜 · 어디에 넣으면 되는지). ⛔ 유저가 자기 터미널에서 굽는 로컬 굽기는 예외 — 자동 받기 없이 점검 안내만. 그래도 없으면 배경음 없이 · 글꼴은 Pretendard 로 진행한다.

## ① 시작 카드
`intro.html`을 읽어 **그대로** show_widget으로 띄운다(새로 만들거나 문구를 고치지 않는다). 한 줄: «고르고 «시작»을 눌러 주세요.»
받는 것: 내용(글 또는 문서 위치) · 비율(9:16 / 16:9) · 나레이션(넣기 / 안 넣기) · 디자인 분위기(또는 **참조 이미지로** — 첨부 · 폴더 `style/`) · 액션 분위기(배경음도 같은 분위기) · 굽기 위치(내 컴퓨터 / 클라우드). 건너뛰면 9:16 · 나레이션 없음 · 내용 보고 정하기 · 내 컴퓨터.
**내 컴퓨터에서 굽기**면 ⑦ 굽기 때 `cd` 한 줄 + 실행 한 줄을 준다(설치 안내는 시작 카드 아래 · 빠진 것은 check.py 가 알려 준다 · motion-build §4). ★굽기가 끝나는 걸 스킬은 못 보므로 **명령과 함께 미리** 알린다: «다 구워지면 작업 폴더에 `피드백뷰어.html` 이 같이 생겨요 — 보면서 고칠 곳을 메모하고 «목록 복사»로 붙여 넣어 주세요.»
작업 폴더는 묻지 않는다 — 스킬을 부를 때 이미 정해져 있다.
- **연결된 컴퓨터 폴더가 있으면** 그 폴더가 작업 폴더다.
- **없으면** 클라우드 작업 공간에 영상별 폴더를 만든다. 내용 · 그림 · 녹음 · 글꼴은 대화창 첨부로 받고, 결과는 파일로 보낸다. 시작 카드 직후 한 줄 안내: «지금은 클라우드에서 작업해요. 세션이 끝나면 중간 파일(기획서 · 녹음 등)이 사라지니, 이어서 작업하려면 컴퓨터 폴더를 연결해 쓰시는 걸 추천해요. 캔버스는 그대로 남아요.»

## ② 기획서.md — `plan-format.md`
내용(문서 · 딸린 그림까지)을 읽어 **한 줄 요약 · 전할 것 · 원문 사실 · 그림 재료**를 먼저 적는다 — 장면을 나누기 전에 «무엇을 전할지»를 고정한다.
**넣을 영상이 있으면** `video.md` — 영상도 그림과 같은 재료다. 쓸 구간을 골라 §3-V에 적는다. 긴 영상 · 긴 자막은 줄여서 읽는다(video.md §2-A). 유저에게 묻지 않고 ②-B로 간다.
**폰으로 찍은 행사 · 모임 영상을 «쇼츠로 이쁘게»처럼 영상이 주인공이면** `video-shorts.md` — 정보가 없을 때만 두 가지(무슨 자리 · 언제 · 어디 + 사진 / 인물 이름표)를 한 번에 묻는다.
**행사 · 여행 · 전시 사진 여러 장을 «쇼츠로»처럼 사진이 주인공이면** `photo-shorts.md` — ★중복만 빼고 최대한 많이 쓴다(쌓기 · 박자 넘기기 · 몽타주 · 모아 마무리). 보여 주는 방식 하나로 **원테이크 줌**(`onetake.md` — 사진 속 색 점으로 빨려 들어가 그 색 공간으로 · ★설계도 먼저 · 바탕색은 줌인으로만 바뀐다).
**긴 화면 녹화(사용법 · 시연)를 설명 영상으로** `rec-cut.md` — 컷 표 하나(원본 시각으로 · 들어내기 · 배속 · 멈춤 · 짚기 · 빨리 감기 배지 · 컷 안 카메라 · 개인 정보 가리기 · 대사 자막) · 컷 표 초안을 먼저 확인받는다.
**껍데기** — 다 만든 영상(어떤 영상이든)을 1:1 · 4:5 창에 넣고 위아래 띠(타이틀 · 칩 · 한 줄 · 진행 막대 · 정보 줄)를 씌운 9:16 · `scripts/wrap.py` (onetake.md §4) · 글은 받은 것만.

## ②-B 표현 기획 — `concept.md` · `kits.md`
«보는 사람이 멈춰서 끝까지 보게 만드는 화면»을 정한다. 건너뛰면 «제목 + 카드»가 되풀이되는 설명서 영상이 된다.
콘셉트 → 훅 → 보여 주는 장치 → 시각 방향 → 키트 하나 · 킥 하나(킥을 고를 때 `time.md` 장치 목록도 본다). **스타일 참조 이미지가 있으면** `style-ref.md`. **동화 · 손그림 · 손글씨처럼 손맛이 맞는 내용이면**(참조 이미지가 없어도) `style-ref.md` §5-B · §5-C 를 보고, 선이 그어지고 글자가 써지는 장면을 쓸지 정한다 — 맞는 장면에만 · 손맛은 결만.
concept.md §6 자기 점검을 통과해야 ③으로 간다. 결과는 기획서 §2-B · §3에. 유저에게 묻지 않는다.

## ③ 캔버스 초안 — `canvas-rules.md`
장면 하나 = 전할 것 하나 · 첫 장면 = 훅 · 마지막 = 마무리 한 마디. 아트보드 = 장면이 «다 나왔을 때» 화면(영상 해상도 그대로).
**UI가 아니라 영상 프레임이고, 움직일 화면의 마지막 모습이다**(§2-A · §2-B). 엔진이 그대로 따라 그리게 짓는다(§4). 영상 자리 · 선 그림 SVG · 원본 남기기도 canvas-rules.md대로.
**🎬 노트** — 스킬도 노트로 설명한다(영상 구간 타임코드 · 지금 처리 · 고치는 법) · 글자 크기 40 · 장면마다 «지금: …» + **«바꿀 수 있는 다른 효과» A/B/C…** — 유저는 «화면 2는 B로»(또는 노트 줄에 ✔)로 고른다(§8-B · 엔진에 있는 효과만) · 영상에 안 나오는 참고 · 예시 판은 영상 줄 아래 다른 줄(§2 · §8). 고쳐 올릴 때는 직전에 그 판을 다시 읽는다(§6).
선 · 글자를 «그리듯 · 쓰듯» 보여 줄 장면은 캔버스에 시각 꼬리표(`data-t`)와 손맛(`data-hand`)을 달아 둔다 — 장면 코드는 `motion.draw(img, e, lt)` 한 줄(style-ref.md §5-B · §5-C). **손맛을 단 보드는 올리기 전에 `scripts/handline.py`** — 안 돌리면 캔버스엔 매끈한 벡터 선이 보인다.
**올린 뒤 화면으로 본다** — `scripts/textcheck.py canvas/처음`으로 글자를 화면에서 재고, 상자 안 한글이 처지거나 뜬 곳을 고친 다음 넘긴다(§6-B). 좌표만 맞추고 넘기지 않는다.

**⏸ 확인 1** — 캔버스를 열어 두고 넘기는 한 줄(§7). 유저가 «검수 끝»이라고 할 때까지 다음으로 가지 않는다. 말로 고쳐 달라고 하면 그 아트보드만 고친다.

## ④ 정리 · 효과 계획 — `review-voice.md` §④ · `effects-index.md`
캔버스를 다시 읽어 고친 것 · 메모를 정리하고(글자 화면 점검 다시 · textcheck), 장면마다 **세기 → 찍는 법 → 등장 · 머무는 동안 → 강조 → 편집 → 소리**를 정한다 — 유저 메모가 먼저. 재료는 `effects-index.md` 한 장만 읽고, 고른 것만 상세 문서(`camera` · `effects` · `time`)에서 본다. 결과는 기획서 §5에. 다시 묻지 않는다(메모 뜻이 애매할 때만 한 줄).

## ⑤ 글꼴 — `review-voice.md` §⑤
쓰인 글꼴 중 없는 것만 한 번에 요청한다.

## ⑥ 나레이션 (넣기일 때만) — `review-voice.md` §⑥
원고는 문장 단위 · 녹음용 메시지에는 **대사만**. 녹음이 오면 정리해 길이를 기획서 §7에 적는다.

## ⑦ 장면 코드 · 확인 · 굽기 — `motion-build.md`
샘플(`examples/`)로 구조를 본 뒤 **이 영상만의 `scenes.py`**를 새로 짠다(샘플은 틀이 아니라 수준의 기준). 영상을 넣으면 `video.md` · 시간 조작이면 `time.md`.
점검 모음 · 점검 보고를 **Claude가 먼저** 보고 고친다(motion-build §3).

**⏸ 확인 2** — 점검 모음 한 장과 한 줄: «장면 N개, 약 M초예요. 굽기 진행할까요?» 유저 개입은 이 한 번.
승인되면 굽는다 — 시작 카드의 굽기 위치대로(내 컴퓨터면 실행 줄을 주고 유저가 돌린다 · 클라우드면 여기서) · 길면 조각 굽기(motion-build.md). 완성 mp4를 전하고 기획서를 «완성»으로. 결과는 유저가 먼저 본다 — 굽기 끝에 작업 폴더에 `피드백뷰어.html` 이 생긴다(터미널 끝에도 크게 찍힌다). 클라우드 굽기면 완성을 전할 때 · 내 컴퓨터 굽기면 **굽기 명령을 줄 때** 한 줄로 알려 준다. 썸네일은 요청할 때만 · 오프닝 · 엔딩은 묻지 않는다.

**소리 — `sound.md`** — 효과음 81가지 · 묶음 7개(영상마다 묶음 하나 · 키트 `K.sounds` 가 출발점) · 긴 소리(함성 · 웅성웅성 · 비 · 바람 …) · 배경음 13장르(영상마다 새 곡 · 키트 `K.music` 이 출발점 · 내용 · 액션 분위기로 고른다). 기획서 §5 «소리» 칸에 장르 · 묶음.

**배경음만 새로** — «배경음만 바꿔 줘» → motion-studio 영상이면 `python3 scenes.py --rebgm [장르]`(화면은 다시 굽지 않는다 · 효과음 · 나레이션 그대로 · `out/<제목>_새배경음.mp4`) · 다른 영상이면 `scripts/rebgm.py 영상.mp4 --style 장르`(sound.md §4). 내 컴퓨터 작업이면 명령 한 줄을 준다.
굽기 · `--audio` 때 `out/소리지도.json`(작곡된 음표 · 효과음 시각 · 대사)이 같이 생긴다 — 피아노 롤 · 소리 지도 화면을 진짜 값으로 그릴 때 · 미리 보기 `scripts/soundmap.py` (sound.md §6).

**자막 · 받아쓰기 — `transcribe.md`** — 자막 파일 없는 영상의 말소리를 글로(`scripts/transcribe.py 영상.mp4` → `확인표.md`). **⏸ 확인표를 유저에게** — Claude 는 소리를 못 듣는다 · 뜻이 이상한 줄엔 ★짐작을 달아 보이고 고친 뒤에 `apply` → `burn`(영상 + 아래 자막 · `자막.srt`). 받아쓰기로 내용을 읽어 영상 넣기 · 쇼츠 기획에도 쓴다(video.md §2-A). 처음 한 번 모델 받기(`--fetch` · 약 560MB).

## ⑧ 굽기 뒤 피드백 — `feedback.md`
`[피드백]` 으로 시작하는 붙여 넣기(뷰어 «목록 복사»)가 오면 이 단계. 유저는 대충 짚는다 — **정확한 자리 · 뜻은 스킬이 찾는다**(`scripts/feedback.py sheet` 앞뒤 프레임 시트 · `loud` 소리 크기). 자막이 있으면 뷰어에 대사 줄이 뜨고 메모마다 `대사: 「…」` 가 붙어 온다 — 그 대사의 자막 시각이 자리 찾기의 단서(굽은 영상 시각 자막을 `out/자막.srt` 에 · feedback.md).
**⏸ «제가 이해한 것» 표**(정확한 타임코드 · 찾은 화면 · 고칠 방법 · ★ = 스킬이 정한 것)를 먼저 보이고 OK 뒤에만 고친다. 범위 들어내기는 기계적으로 자르지 않는다(화면이 바뀌는 순간 · 대사 · 표시 이음).
**고치는 곳** — 시간 · 무엇(타이밍 · 길이 · 빼기 · 글귀 · 소리) = 장면 코드 / 모양(위치 · 글꼴 · 크기 · 새로 얹는 글자) = 캔버스(판 다시 읽기 · 판에 없던 것은 작은 보드 + `motion.draw`). 고친 뒤 전후 스틸 + 새 타임코드표 → 굽기.

## Abort conditions — 멈추고 알린다
- 내용이 비었거나 문서를 열 수 없을 때 → 무엇이 필요한지 한 줄로 묻는다.
- Artifact 도구(Claude Design 캔버스)를 쓸 수 없을 때 → 캔버스 없이는 이 스킬의 흐름이 안 된다고 알리고 멈춘다(만화 페이지 길은 캔버스가 필요 없다).
- 녹음 문장 수가 다시 받아도 안 맞을 때 → 빠진 문장을 짚어 알린다.
- 굽기 중 디스크 · 시간 문제 → 조각 굽기(part)로 바꾸자고 알린다.

## Scope boundary
**이 스킬은 내용 → 기획서 → 캔버스 초안 → 검수 반영 → (선택) 나레이션 → 모션 그래픽 mp4 → (선택) 보고 짚은 피드백 반영 · (요청 시) 썸네일을 한다.**
유저가 준 영상은 자르고 · 넣고 · 위에 얹는다(영상 속 사람 · 사물을 새로 그리거나 바꾸지 않는다).
완성된 만화 페이지는 카메라 · 소리 · 빛 한 겹으로 보여 준다(그림 · 말풍선을 고치거나 떼어 내지 않는다).
**그림을 새로 생성하지 않는다(AI 이미지 · 영상 생성 ⛔) · 녹음을 대신하거나 음성을 합성하지 않는다 · 업로드 · 오프닝/엔딩은 하지 않는다 · 효과음 · 배경음은 코드로 만들고(sf2 악기 · 합성) 소리 파일을 받아 오지 않는다 · 받아쓰기는 확인표를 거친다(확인 안 한 자막은 «자동 자막»).**
