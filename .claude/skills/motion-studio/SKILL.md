# motion-studio

> **첫 1초에 손가락을 멈추게 하고, 끝까지 눈을 못 떼게 만든다. 가진 기술은 아끼지 않는다.**

쓰는 사람은 디테일을 직접 고치거나 조절하기 어려운 사람이다. 목표는 **최소한의 노력으로 최대의 결과물** — 대부분 스킬이 알아서 하고, 유저 개입은 캔버스 검수와 굽기 전 확인 한 번뿐이다.
«내용 → 바로 완성 영상»은 유저 의도가 들어갈 틈이 없고 고치는 왕복이 길다. 그래서 그 사이에 **눈으로 보고 손으로 고치는 캔버스 초안**을 둔다.

## 설계 사상 — 스킬은 바닥, 모델이 천장
이 스킬은 품질이 이 아래로 떨어지지 않게 받쳐 준다(절차 · 엔진 · 확인 · 최소선). 얼마나 잘 만드느냐는 모델이 정한다. 모델이 좋아지면 결과도 그대로 좋아져야 한다.

**바닥 — 무엇이 있어도 지킨다**
1. 원문에 없는 사실 · 숫자를 지어내지 않는다
2. 폰에서 읽힌다 (핵심 글자 크기 · 안전 영역)
3. 캔버스에서 확정한 모습(요소의 자리 · 크기 · 글자 · 색)이 영상에 그대로 나온다 — 카메라는 그 화면을 찍는 방법
4. 굽기 전 확인은 한 번 · 유저 개입은 최소
5. 유저 메모가 스킬의 판단보다 먼저

**천장을 막지 않는다**
- 횟수 · 개수 상한 대신 목적으로 판단한다(«보는 사람이 피곤하지 않게 · 효과가 내용을 덮지 않게»).
- reference의 표 · 기본값은 출발점 예시다. 내용에 더 맞는 게 있으면 넘어간다.
- 효과 사전 · 본보기 코드는 검증된 재료지 메뉴가 아니다. 더 나은 움직임은 새로 만들어 쓰고, 좋으면 엔진에 보탠다.
- 디자인이 먼저다. 엔진이 못 그리면 엔진을 늘린다.
- 영상은 «요소가 나타나는 것»이 아니라 «찍고 잇는 것»이다 — 장면마다 찍는 법(카메라)과 잇는 법(편집)을 정한다.
- **영상끼리는 키트로 다르게, 한 영상 안은 키트 안에서 변주** — 재료가 많아도 산만해지지 않게 하는 장치다. ★키트는 일관성을 지키는 최소한의 바닥이지 제한이 아니다 — 내용에 더 맞는 움직임은 키트 밖에서 가져와 쓰고 이유만 적는다(빌림은 벌점이 아니다).
- **카메라는 «화면이 바뀔 만큼»** — 장면마다 크게 움직이는 카메라를 하나 이상. 1.05배 · 몇 % 흐르기는 움직임으로 느껴지지 않는다. 장면 끝 화면은 전체 · 요소 가운데 · 이유 있는 삼분할 중 하나.

## Pipeline overview
```
① 시작 카드 (intro.html)
② 기획서.md 정리                      ← 이어 가기 문서 · 압축 뒤엔 이것부터 읽는다
②-B 표현 기획 — 콘셉트 · 훅 시안 · 보여 주는 방법 · 시각 방향 · 키트 · 킥 장치
③ 캔버스 초안 (아트보드 한 장 = 장면 하나)
   ⏸ 확인 1 — 유저 검수 · 수정 · 메모 → «검수 끝»
④ 캔버스 다시 읽기 → 고친 것 · 메모 정리 → 효과 계획 (세기 지도)
⑤ 글꼴 받기 (없는 것만)
⑥ 나레이션 원고 → 녹음 받기 → 정리          (선택)
⑦ 장면 코드 → 점검 모음 · 점검 보고(Claude 먼저 확인)
   ⏸ 확인 2 — «굽기 진행할까요?»
   → 굽기 → mp4
```
**이어 갈 때(압축 · 새 세션)**: 작업 폴더의 `기획서.md`를 열고 «0. 지금 단계»에서 다시 시작한다. 상태는 기억이 아니라 파일로 확인한다.

## 처음 쓰는 경우 — 점검 (한 번)
`python3 <스킬>/scripts/check.py <작업 폴더>` — ffmpeg · 패키지 · 사운드폰트 · 기본 글꼴을 본다. ✗ 항목은 나온 안내대로 해결한다.
배경음 사운드폰트(GeneralUser-GS.sf2)는 용량 때문에 스킬에 없다 — 클라우드 작업 공간이면 Claude가 직통 주소(`raw.githubusercontent.com/…` · paths.py `SF2_URL`)로 먼저 직접 받는다. 컴퓨터 폴더면 받는 법을 안내하고, 그래도 없으면 배경음 없이 진행한다(굽기는 된다).

## ① 시작 카드
`intro.html`을 읽어 **그대로** show_widget으로 띄운다(새로 만들거나 문구를 고치지 않는다). 한 줄: «고르고 «시작»을 눌러 주세요.»
받는 것: 내용(글 또는 문서 위치) · 비율(9:16 / 16:9) · 나레이션(넣기 / 안 넣기) · 디자인 분위기 · 액션 분위기(배경음도 같은 분위기). 건너뛰면 9:16 · 나레이션 없음 · 내용 보고 정하기.
작업 폴더는 묻지 않는다 — 스킬을 부를 때 이미 정해져 있다.
- **연결된 컴퓨터 폴더가 있으면** 그 폴더가 작업 폴더다.
- **없으면** 클라우드 작업 공간에 영상별 폴더를 만든다. 내용 · 그림 · 녹음 · 글꼴은 대화창 첨부로 받고, 결과는 파일로 보낸다. 시작 카드 직후 한 줄 안내: «지금은 클라우드에서 작업해요. 세션이 끝나면 중간 파일(기획서 · 녹음 등)이 사라지니, 이어서 작업하려면 컴퓨터 폴더를 연결해 쓰시는 걸 추천해요. 캔버스는 그대로 남아요.»

## ② 기획서.md
`reference/plan-format.md`의 틀로 작업 폴더에 `기획서.md`를 만든다. 내용(또는 문서)을 읽어 **한 줄 요약 · 전할 것 · 원문 사실 · 그림 재료**를 먼저 적는다 — 장면을 나누기 전에 «무엇을 전할지»를 고정하기 위해서다.
문서 위치를 받았으면 그 문서를, 그림 · 결과물이 딸려 있으면 그것까지 연다. 이 단계에서는 유저에게 묻지 않고 바로 ②-B로 간다.

## ②-B 표현 기획 — «어떻게 보여 줄까»
`reference/concept.md`를 읽고 따른다. ②가 «무엇을 전할지»라면 여기는 «보는 사람이 멈춰서 끝까지 보게 만드는 화면»이다. 이 단계를 건너뛰면 «제목 + 카드»가 되풀이되는 설명서 영상이 된다.
- 한 줄 콘셉트 → 훅 시안 2~3개 중 가장 센 것 → 전할 것마다 보여 주는 장치(같은 틀 연달아 ⛔) → 이름 붙일 수 있는 시각 방향(무난한 기본값 ⛔ · 제목은 디스플레이 글꼴).
- **키트 하나 · 킥 장치 하나**(`reference/kits.md` · concept.md §5-B) — 같은 출발점에서 갈라지는 이야기면 시간 조작(되감기 등 · `reference/time.md`)이 가장 센 킥이다.
- 넘기기 전 자기 점검(concept.md §6)을 통과해야 ③으로 간다. 결과는 기획서 §2-B · §3에. 유저에게 묻지 않는다.

## ③ 캔버스 초안
`reference/canvas-rules.md`를 읽고 따른다. 핵심:
- 장면 하나 = 전할 것 하나 · 첫 장면 = 훅 · 마지막 = 마무리 한 마디. 아트보드 = 장면이 «다 나왔을 때» 화면, 크기는 영상 해상도 그대로.
- **UI가 아니라 영상 프레임이다**(canvas-rules.md §2-A) — 캔버스의 웹 · 앱 감각(무난한 카드 · 기본 글꼴 · 단색 바탕)을 따르지 않는다. 크기 대비 크게 · 제목은 표정 있는 글꼴 · 바탕과 깊이도 연출.
- **움직임을 생각하고 짓는다**(canvas-rules.md §2-B) — 따로 나올 것은 따로 떼고, 보는 순서 = 등장 순서, 들어올 길을 비우고, 장면 사이를 잇는다. 캔버스는 포스터가 아니라 움직일 화면의 마지막 모습이다.
- 엔진이 그대로 따라 그리게 적는다(canvas-rules.md §4 — 모든 요소 absolute + px 좌표 · 그라데이션 · 그림자 · 회전 · 흐림 · 글자 테두리도 읽는다 · 글꼴 · 그림은 캔버스에 올림 · 그림은 `재료/<번호>`로도 복사).
- 올린 아트보드 원본은 `canvas/처음/`에 남긴다. 기획서 §3 · §4를 채운다.

**⏸ 확인 1** — 캔버스를 열어 두고 넘기는 한 줄(canvas-rules.md §7). 유저가 «검수 끝»이라고 할 때까지 다음으로 가지 않는다. 말로 고쳐 달라고 하면 캔버스를 다시 읽고 그 아트보드만 고친다.

## ④ 정리 · 효과 계획
`reference/review-voice.md` §④를 따른다. 캔버스를 다시 읽어 `canvas/확정/`에 두고, 메모를 장면에 매기고(`canvas.py notes`), 고친 것을 정리한다.
그다음 장면마다 **세기(1~3) → 찍는 법(카메라) → 등장 · 머무는 동안 → 강조(있을 때만) → 다음 장면으로 편집 → 소리**를 정한다 — 유저 메모가 먼저, 나머지는 키트 안에서 내용을 보고. 재료 목록은 `reference/effects-index.md` 한 장만 읽고, 고른 것의 쓰는 법만 상세 문서에서 본다. 세기 3은 봉우리에만. 결과는 기획서 §5에. 유저에게 다시 묻지 않고 넘어간다(메모 뜻이 애매할 때만 한 줄).

## ⑤ 글꼴
`reference/review-voice.md` §⑤. `canvas.py fonts`로 쓰인 글꼴을 보고, 없는 것만 한 번에 요청한다(폴더 연결: `fonts/`에 넣어 달라고 · 클라우드: 첨부해 달라고).

## ⑥ 나레이션 (넣기일 때만)
`reference/review-voice.md` §⑥. 원고는 문장 단위로 끊어 쓰고, 녹음용 메시지에는 **대사만** 준다. 녹음이 오면 `scripts/core/voice.py`로 앞뒤 빈 소리를 자르고(한 파일이면 문장 수에 맞춰 나눈다) 길이를 기획서 §7에 적는다.

## ⑦ 장면 코드 · 확인 · 굽기
`reference/motion-build.md`를 읽고, `examples/scenes_example.py`로 구조를 본 뒤 **이 영상만의 `scenes.py`**를 작업 폴더에 새로 짠다(본보기는 틀이 아니라 수준의 기준).
- 장면 = 그리기(canvas · appear · motion · fx) → 찍기(camera). 경계 편집은 키트가 세기대로 고르고(`K.cuts`) · 화면 겹은 `K.finish`. 기획서 §5는 `PLAN`으로 옮긴다. 요소 모습은 아트보드 그대로(바닥 3). 재료에 없는 움직임은 새로 짠다.
- 킥이 시간 조작이면 `examples/rewind_example.py` 구조(원본 시간에 A · B 갈래 → `timewarp` 지도).
- `python3 scenes.py --sheet` · `--check` → 점검 모음 · 점검 보고 · 움직임 시간 띠를 **Claude가 먼저** 보고 넘침 · 겹침 · 빈 화면 · 메모 반영 · 세기 몰림 · 같은 등장 반복 · 카메라가 거의 안 움직이는 장면 · 멈춘 구간을 고친다(motion-build §3).

**⏸ 확인 2** — 점검 모음 한 장과 한 줄: «장면 N개, 약 M초예요. 굽기 진행할까요?» 유저 개입은 이 한 번.
- 승인되면 `python3 scenes.py --bake`. 길이 제한은 없다 — 길면 굽는 데 오래 걸리니 «part 1/2/3으로 나눠 굽기»(`--part 1/3` … `--join 3`)를 권한다.
- 완성 mp4를 전하고(폴더면 `out/` · 클라우드면 파일로) 기획서를 «완성»으로. 결과는 유저가 먼저 본다.
- 썸네일은 유저가 요청할 때만 — 같은 캔버스에 썸네일 아트보드를 하나 더 그린다. 오프닝 · 엔딩은 묻지 않는다.

## Abort conditions — 멈추고 알린다
- 내용이 비었거나 문서를 열 수 없을 때 → 무엇이 필요한지 한 줄로 묻는다.
- Artifact 도구(Claude Design 캔버스)를 쓸 수 없을 때 → 캔버스 없이는 이 스킬의 흐름이 안 된다고 알리고 멈춘다.
- 녹음 문장 수가 다시 받아도 안 맞을 때 → 빠진 문장을 짚어 알린다.
- 굽기 중 디스크 · 시간 문제 → 조각 굽기(part)로 바꾸자고 알린다.

## Scope boundary
**이 스킬은 내용 → 기획서 → 캔버스 초안 → 검수 반영 → (선택) 나레이션 → 모션 그래픽 mp4 · (요청 시) 썸네일을 한다.**
**그림을 새로 생성하지 않는다(AI 이미지 · 영상 생성 ⛔) · 녹음을 대신하거나 음성을 합성하지 않는다 · 업로드 · 오프닝/엔딩은 하지 않는다.**
