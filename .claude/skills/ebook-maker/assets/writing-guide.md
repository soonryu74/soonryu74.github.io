# 원고(book.md) 문법 + 작성 가이드

## 1. 파일 구조

```
---                      ← front matter (책 정보)
title: 책 제목
subtitle: 한 줄 약속 (표지 lede + meta description)
series: 무료 공개 이북   ← 표지 kick 왼쪽 (선택)
chapter: 챕터 1          ← 표지 kick 오른쪽 (선택)
author: 저자
brand: 브랜드            ← 모든 쪽 하단 왼쪽
theme: auto              ← auto | default | estate | ai | money | health | edu | life | law | mind
pdf: index.pdf           ← 있으면 PDF 버튼 생성
toc_note: 차례 아래 안내문 (선택)
---

== cover                 ← 쪽 시작. "== 유형 [인자]"
svg: hero                ← 필드는 "키: 값" 한 줄
                         ← 나머지 줄은 본문(마크다운)
== toc
== open 1
title: 절 제목
sub: 절 부제
== body
h: 쪽 제목
문단…
```

## 2. 쪽 유형과 필드

| 유형 | 인자 | 필드 | 본문 |
|---|---|---|---|
| `cover` | — | `kick:` `title:` `lede:` `img:`/`svg:` | 추가 문단(선택) |
| `toc` | — | `h:`(기본 "이 책에서") | 안내문 1~2줄(선택) |
| `open` | 절 번호 | `title:` `sub:` `img:`/`svg:` | — |
| `body` | — | `h:` `img:`/`svg:` `svgtext:` `caption:` `note:` `src:` | 문단·인용·표·목록·코드 |
| `steps` | — | `h:` `note:` `img:`/`svg:` | 소개 문단 + `1. **제목** — 설명` 줄들 |
| `check` | — | `h:` `note:` | 소개 문단 + `- 항목` 줄들 |
| `quote` | — | `by:` | 인용문 1~2문장 |
| `video` | 유튜브 ID | `h:` `len:` `v:`(인자 대신) `note:` | 영상 아래 보충 문단(선택) |
| `close` | — | `kick:` `title:` `cta:` `url:` `img:`/`svg:` | 맺음 문단 |
| `raw` | — | — | HTML 그대로 |

- `label:` 어느 쪽에나 — 쪽 이동 드롭다운에 보일 이름(기본: 현재 절 제목).
- `img: img/파일.webp` + `alt:` / `svg: 내장이름` + `svgtext: 라벨1|라벨2|라벨3` / `svgfile: img/내그림.svg`(인라인 삽입, CSS 변수 사용 가능).
- `note:` 는 쪽 맨 아래 포인트색 메모 한 줄. `src:` 는 출처(작게).

## 3. 본문 마크업

| 쓰기 | 결과 |
|---|---|
| 빈 줄로 나눈 글 | 문단 `<p>` |
| `**굵게**` | 핵심어 강조 |
| `==형광==` | 포인트색 형광 |
| `` `코드` `` | 인라인 코드 |
| `[글](https://…)` | 링크(새 창) |
| `> 문장` | 인용 상자(포인트색 왼쪽선) |
| `- 항목` / `1. 항목` | 목록 |
| `\| 머리 \| 머리 \|` 표 | 표(첫 줄 머리글, `|---|` 줄은 무시) |
| ```` ``` ```` 블록 | 코드 블록 |
| `$ 출력 = f(입력)` | 수식 한 줄(가운데, 모노) |

## 4. 작성 원칙 ⭐ (포맷보다 중요)

### 독자
30~40대 직장인과 50대 입문자가 **같이** 읽는다. 둘 다 이해되게:
- 전문용어 → 생활 비유 먼저, 용어는 괄호로. 예) "API(에이피아이, 프로그램끼리 주고받는 창구)"
- 영어는 한글 발음 병기. 예) "Playwright(플레이라이트)"
- 명령·클릭은 Windows / Mac 을 둘 다 적는다.

### 톤
- 따뜻한 선생님 말투. "어렵지 않아요", "여러분도 할 수 있어요".
- 정직·신중. 과장, 자극적 표현, "이것만 하면 무조건" 금지. 한계와 주의점을 숨기지 않는다.
- 말 걸듯 쓴다. "이 책을 만들면서 계속 한 가지 생각을 했습니다…" 정의 나열 금지.

### 한 쪽의 규칙
1. **한 쪽 = 한 메시지.** 문단 2~4개, 문단당 2~3문장, 전체 450자 이내(build 가 520자 넘으면 경고).
2. 핵심어만 `**굵게**`. 한 쪽에 3개 이하.
3. 글만 2~3쪽 → 그림(svg/img)·단계·체크·인용 쪽 1쪽. 리듬을 바꾼다.
4. 쪽 제목(`h:`)은 궁금하게 한 줄. "월요일 아침의 두 시간", "빌리는 쪽과 가진 쪽".
5. `note:` 는 "이 쪽에서 남길 한 문장".

### 책의 구조 공식 (20~30쪽 기준)
```
표지(1) → 차례(1)
→ 절 1: 오프너(1) → 본문 2~3 → 단계/체크 1 → 영상 1
→ 절 2: …
→ (절 5~7개)
→ 맺음(1): 다음 챕터 안내 + CTA
```
10~15쪽이면 절 3개, 40쪽 이상이면 절 8~10개. 절마다 영상이 없으면 마지막 절 끝에 하나.

### 제목 공식 (책·절·쪽 제목)
- 금지: 기본기, 총정리, 사용법, 기초, 완벽 정리
- 권장: 숨겨진, 자동화, 꿀조합, 이거면 끝, 몰랐죠?, 무료 — 단, **실제로 그 내용일 때만**. 낚시 금지.
- 부제(subtitle)는 "누가, 무엇을, 얼마나" 가 들어간 정직한 약속 한 줄.

### 저작권
- 남의 강의·책·블로그 본문을 옮겨 적지 않는다. 읽고 **내 말로 다시 쓴 요약·정리**만.
- 이미지는 직접 만든 것, 내장 SVG, 라이선스 확인된 것만. 출처는 `src:`.

## 5. 예시
`example/book.md` 가 모든 쪽 유형을 한 번씩 쓴 14쪽짜리 예시다. 새 책은 이 파일을 복사해 시작하면 된다.
