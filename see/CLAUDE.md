## 1. 배경 — 누가, 왜 만드는가

**만드는 사람**: 유튜브 채널 「노모어매뉴얼」 운영자. 구독자 약 1만 명. 20년 영어 입시 교육 경력, AI 개발 경험 소량. AI 활용법을 30~60대에게 가르치는 채널.

**핵심 발견 (5건의 시장 조사에서 반복 확인됨)**:
> **기술은 이미 무료로 다 있는데, 아무도 안 가르친다.**

- 애플·구글의 접근성 기능은 무료로 다 있지만 아무도 모릅니다.
- 전용 하드웨어 시장은 무너졌습니다. OrCam(약 590만 원 기기)은 2024년 저시력 사업부를 폐쇄하며 **"LLM의 이미지 처리 발전으로 전용 제품이 불필요해졌다"**고 공식 인정했습니다.
- 세계 1위 AAC 기업 Tobii Dynavox조차 **"신규 진단자의 2%에만 도달한다"**고 실적발표에서 밝혔습니다. → **병목은 제품이 아니라 유통·교육 채널**입니다.

**따라서 이 앱들의 역할**:
- 앱 자체로 돈을 벌지 않습니다. **무료**입니다.
- 목적은 ① 유튜브 콘텐츠 소재(만드는 과정을 공개 제작) ② 교육 상품의 리드 확보 ③ 신뢰 구축입니다.
- **"기능으로 애플·구글과 경쟁하지 않는다"**가 대원칙입니다. 우리는 **쓰는 법을 가르치는 쪽**입니다.

## 3. 제품 스펙 — ① 크게보기 (1순위)

### 3-1. 왜 이게 1순위인가
- **타깃이 이미 구독자 본인**입니다. 설득이 필요 없습니다.
- 노안은 40대 이상 거의 전부라 시장이 가장 큽니다. (전 세계 미교정 노안 8억 2,600만 명, 미충족률 45%)
- 핵심 통찰: **"AI를 못 쓰는 진짜 이유가 어려워서가 아니라 화면이 안 보여서다."** 기존 AI 강의는 전부 "잘 보이는 사람"을 전제로 만들어져 있습니다.

### 3-2. 화면 구성 (이게 전부입니다)

```
┌─────────────────────────────┐
│  [가]  [가]  [가]            │  ← 글자 크기 3단계 (항상 상단 고정)
│  보통   크게   더크게          │
├─────────────────────────────┤
│                             │
│   (질문 입력 / 답변 영역)      │  ← 본문 24pt 기본
│                             │
├─────────────────────────────┤
│  [ 🎤 말하기 ]  [ 🔊 읽어주기 ] │  ← 버튼 2개. 끝.
└─────────────────────────────┘
```

### 3-3. 기능 목록 (이 순서대로 구현)

| # | 기능 | 필수 | 비고 |
|---|---|:---:|---|
| 1 | 글자 크기 3단계 토글 (24 / 32 / 40px) | ✅ | 첫 화면에 항상 보임. 설정 메뉴에 숨기지 말 것 |
| 2 | 고대비 본문 렌더링 (7:1 이상) | ✅ | 회색 글씨 절대 금지 |
| 3 | **읽어주기** — 화면 텍스트를 음성으로 | ✅ | Web Speech API `SpeechSynthesis` (ko-KR) |
| 4 | **말하기** — 음성으로 질문 입력 | ✅ | Web Speech API `SpeechRecognition` (ko-KR, Chrome) |
| 5 | AI 답변 **자동 3줄 요약** | ✅ | 긴 답변은 노안에게 물리적으로 안 읽힘 |
| 6 | 사진 속 글자 읽어주기 (약봉지·고지서) | ⬜ | v2. OCR 또는 멀티모달 |
| 7 | 다크/라이트 전환 | ⬜ | v2 |

> **기능 5번이 이 앱의 정체성입니다.** ChatGPT 답변이 길어서 안 읽히는 문제를 푸는 게 핵심입니다. "짧게 답해줘" 프롬프트를 시스템 레벨에 넣으십시오.

### 3-4. 절대 넣지 말 것
- 로그인 / 회원가입 (v1에서는)
- 설정 화면 (글자 크기 3단계 외에는 설정할 게 없어야 함)
- 온보딩 튜토리얼 (첫 화면에서 바로 쓸 수 있어야 함)
- 사이드바, 햄버거 메뉴, 탭 네비게이션

## 5. 기술 스택 (제안)

```
프론트: 단일 HTML + Vanilla JS  (v1)
        또는 Next.js (App Router)  (v2 이후)
스타일: CSS 변수 기반 토큰. 프레임워크 없이 시작 권장
음성:   Web Speech API
        - SpeechSynthesis (읽어주기) → 브라우저 내장, 무료
        - SpeechRecognition (말하기) → Chrome에서 ko-KR 지원
AI:     Claude API 또는 OpenAI API (서버리스 함수 경유)
배포:   Vercel 또는 Netlify (둘 다 이 세션에 MCP 연결되어 있음)
형태:   PWA — "홈 화면에 추가"로 앱처럼 쓰게. 시니어에게 설치 장벽이 가장 큼
```

### 개발 시작 시 반드시 먼저 검증할 것
1. **Web Speech API의 한국어 지원 실태** — `SpeechSynthesis`는 OS에 설치된 음성에 의존하므로 기기별 편차가 큽니다. Android/iOS/Windows/Mac 각각에서 ko-KR 음성이 있는지 확인 후 없을 때의 폴백을 설계하십시오.
2. **`SpeechRecognition`은 Safari/iOS 지원이 불안정**합니다. 미지원 시 텍스트 입력으로 자연스럽게 폴백해야 합니다.
3. API 키는 **절대 클라이언트에 노출하지 마십시오.** 서버리스 함수를 경유합니다.

### 반드시 알아야 할 원리
- **"크게만 하면 된다"는 틀렸습니다.** 대비와 줄간격을 안 건드리면 크기만 키워봐야 소용없습니다. 이게 이 앱의 존재 이유입니다.
- **"조명은 무조건 밝게"도 틀렸습니다.** 램프 색온도는 읽기 성능에 유의한 차이가 없었고(p=0.74), 저시력자는 오히려 더 어두운 조도를 선호합니다. 개인 편차가 ±1,300 lux 수준입니다. → **다크 모드를 "선택지"로 제공**하되 강요하지 마십시오.
- 일반 인쇄물의 글자 크기는 정상 시력의 읽기 임계값(시각 0.2°) **바로 위 경계선**에 걸쳐 있습니다. 노안이 오면 임계값이 올라가 신문·약봉지·스마트폰이 **한꺼번에** 임계 아래로 떨어집니다.

### 구현 팁
```css
:root {
  --fs-body: 24px;        /* 3단계 토글로 24 / 32 / 40 */
  --lh: 1.6;              /* 1.5 이상 필수 */
  --ink: #12161c;         /* 배경 #fff 대비 약 16:1 */
  --ink-2: #3d4754;       /* 최소 4.5:1 유지. 이보다 밝게 가지 말 것 */
}
body { font-size: var(--fs-body); line-height: var(--lh); }
p + p { margin-top: calc(var(--fs-body) * 2); }
```
- 색상 대비는 눈으로 판단하지 말고 **계산해서 검증**하십시오. 자동 테스트에 넣는 것을 권장합니다.
- `localStorage`는 글자 크기 기억 정도에만 쓰고, **반드시 try/catch로 감싸십시오.** 없어도 정상 동작해야 합니다.

## 8. 사이트 구조 (확정됨)

```
nomoremanual.com           ← 본체. AI 교육·강의·유튜브 허브
├── see.nomoremanual.com   ← 크게보기 (1순위)
├── hear.nomoremanual.com  ← 들리게
└── aac.nomoremanual.com   ← AI 마우스
(별도 도메인)               ← 선교 콘텐츠. 절대 위와 섞지 않음
```

**서브도메인을 택한 근거**: Google Search Central 공식 문서 —
> "Google Search는 사이트 이름(Site Names)을 도메인 수준과 **서브도메인 수준에서는 지원하지만, 서브디렉토리 수준에서는 지원하지 않는다.**"

즉 `see.nomoremanual.com`은 검색 결과에서 독자적 사이트 이름을 가질 수 있지만 `nomoremanual.com/see`는 불가능합니다. 브랜드는 나누되 도메인 신뢰는 잇는 유일한 방법입니다.

4. 음성 기능 미지원 브라우저에서도 텍스트로 정상 동작한다
