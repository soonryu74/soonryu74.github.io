# 건강·감염병 콘텐츠 검수 흐름

## 상태

`draft` 초안 → `in_review` 검수 요청 → `approved` 승인 → `published` 게시 → `expired` 만료 / `archived` 보관

## 누가 무엇을 하나

| 단계 | 담당 | 화면 | 기록 |
|---|---|---|---|
| 초안 작성 | 작성자 | (본문 편집기 준비 중, 지금은 DB 직접 입력) | `author_id`, `change_reason` |
| 검수 요청 | 작성자·관리자 | `/admin/content` | 감사로그 |
| 승인·반려 | 검수자 (수의사 등 자격자) | `/admin/content` | `reviewer_id`, `reviewer_credential`, `reviewed_at`, `expires_at` |
| 게시 | 관리자만 | `/admin/content` | 감사로그 |
| 만료 | 자동(기한) 또는 관리자 | `/admin/content` | 감사로그 |

## DB 가 강제하는 것

- 검수자와 검토일 없이는 `approved`·`published` 가 될 수 없다 (check 제약).
- 승인되고 기한이 남은 버전만 비로그인·일반 사용자에게 보인다 (RLS). 기한이 지나면 자동으로 숨는다.
- 검수자는 승인·반려까지만, 게시는 관리자만 (RLS).

## 글이 갖춰야 할 것

- 동물의 신호와 사람의 신호를 나눠 쓴다.
- "사람이 의료기관에 갈 때"와 "반려동물이 동물병원에 갈 때"를 나눠 쓴다.
- 진단명 추정, 약 이름, 용량, 치료법을 쓰지 않는다. 행동만 쓴다.
- 질병관리청·농림축산검역본부 등 공식 원문 링크를 단다.
- 검토 기한은 기본 180일.

## 현재 상태

SFTS, 공수병, 개 브루셀라증, 톡소포자충증 4건이 `in_review` 초안으로 들어 있다. 검수자가 지정되지 않아 실제 서비스에서는 공개되지 않는다.

## 정정·회수

오류 신고가 들어오면 관리자가 해당 글을 `expired` 로 내리고, 새 버전을 만들어 다시 검수한다. 변경 사유는 `change_reason` 에 남긴다.
