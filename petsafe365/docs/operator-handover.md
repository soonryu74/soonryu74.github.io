# 포우플레이 아틀리에 운영 인수인계서

2026년 11월 27일 기준 · 앱 이름(코드 폴더): `petsafe365`

## 한눈에 보기

넘겨받는 것은 앱 코드 한 폴더(`petsafe365`)이고, 운영자 본인 계정 세 곳에 새로 올리면 운영을 시작할 수 있습니다. 처음 해 보는 분도 따라 하면 2~3시간 안에 끝납니다.

| 계정 | 하는 일 | 쉬운 비유 |
| --- | --- | --- |
| GitHub | 코드 보관 | 설계도 보관함 |
| Supabase | 상품·회원 정보 저장, 로그인 | 데이터 창고 |
| Vercel | 앱을 인터넷 주소로 띄움 | 가게 간판과 매장 |

진행 순서는 다섯 단계입니다.

1. 코드를 내 GitHub 저장소로 옮깁니다.
2. Supabase에 데이터 창고를 만듭니다.
3. 내 컴퓨터에서 한 번 켜 봅니다.
4. Vercel로 인터넷에 올립니다.
5. 로그인 주소를 등록하고 관리자를 지정합니다.

지금은 **가게 모드**로 운영합니다. 첫 화면은 용품 가게 "포우플레이 아틀리에"이고, 상품 20종과 출시 알림 신청이 열려 있습니다. 안전 앱 기능(오늘 할 일, 긴급 도움, 지도, 신고)은 꺼 두었습니다. Vercel 환경변수 `NEXT_PUBLIC_SAFETY_APP` 값을 `on`으로 넣어 다시 배포하면 켜집니다. 결제, 지도 표시, 광고는 아직 꺼져 있거나 만들어지지 않았습니다.

## 1단계. 코드 받기

앱 코드는 지금 `soonryu74/soonryu74.github.io` 저장소의 `petsafe365` 폴더에, 작업용 가지 `ccr-ffe15702-oqfx50` 위에 있습니다. 이 폴더만 떼어 내 저장소로 옮깁니다.

1. GitHub에서 오른쪽 위 **+** → **New repository**를 누릅니다. 이름은 `petsafe365`, 공개 범위는 **Private**, 나머지는 비워 둡니다.
2. 터미널(맥) 또는 PowerShell(윈도우)에 아래를 한 줄씩 입력합니다. 두 운영체제 모두 같은 명령입니다. `내계정`은 본인 GitHub 아이디로 바꿉니다.

```bash
git clone https://github.com/soonryu74/soonryu74.github.io.git
cd soonryu74.github.io
git checkout ccr-ffe15702-oqfx50
git subtree split --prefix=petsafe365 -b petsafe365-only
git push https://github.com/내계정/petsafe365.git petsafe365-only:main
```

3. GitHub의 내 `petsafe365` 저장소를 새로고침합니다. `src`, `supabase`, `README.md`가 보이면 성공입니다.
4. 이후 작업용으로 내 저장소를 다시 받아 둡니다.

```bash
cd ..
git clone https://github.com/내계정/petsafe365.git
cd petsafe365
```

앞으로의 명령은 모두 이 `petsafe365` 폴더 안에서 입력합니다.

## 2단계. 데이터 창고 만들기

Supabase에 프로젝트를 만들고, 코드에 들어 있는 설계 파일 다섯 개를 순서대로 적용합니다.

1. <https://supabase.com/dashboard> → **New project**. 이름은 `petsafe365`, 지역은 **Northeast Asia (Seoul)** 를 고릅니다. 데이터베이스 비밀번호는 안전한 곳에 적어 둡니다.
2. 왼쪽 메뉴 **SQL Editor**를 엽니다.
3. 내 컴퓨터의 `supabase/migrations` 폴더에서 아래 파일을 순서대로 열어, 내용 전체를 복사해 붙이고 **Run**을 누릅니다. 파일 하나가 끝난 뒤 다음 파일을 실행합니다.

| 순서 | 파일 | 하는 일 |
| --- | --- | --- |
| 1 | `20261126000001_init.sql` | 표 28개와 접근 권한 규칙 |
| 2 | `20261126000002_storage.sql` | 비공개 문서 저장소 |
| 3 | `20261126000003_harden_functions.sql` | 내부 함수 권한 강화 |
| 4 | `20261127000004_waitlist.sql` | 출시 알림 신청 |
| 5 | `20261127000005_product_images.sql` | 상품 사진과 상품코드 |

4. **Project Settings → API**에서 값 세 개를 확인합니다.

| 값 | 어디에 쓰나 | 주의 |
| --- | --- | --- |
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` | 공개돼도 되는 값 |
| Publishable key (`sb_publishable_`로 시작) | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 공개돼도 되는 값 |
| Secret key (`service_role`) | `SUPABASE_SERVICE_ROLE_KEY` | 비밀번호와 같습니다. 누구에게도 보내지 않고 코드에도 적지 않습니다 |

적용이 끝나면 **Advisors → Security**를 열어 빨간 경고가 없는지 확인합니다.

## 3단계. 내 컴퓨터에서 켜 보기

인터넷에 올리기 전에 내 컴퓨터에서 먼저 확인합니다. 문제가 생겨도 아무에게도 보이지 않아 안전합니다.

1. 필요한 부품을 설치합니다. 두 운영체제 모두 같습니다.

```bash
npm install
```

2. 키를 넣을 파일을 만듭니다. 이 명령만 운영체제마다 다릅니다.

| 운영체제 | 명령 |
| --- | --- |
| 맥 (터미널) | `cp .env.example .env.local` |
| 윈도우 (PowerShell) | `Copy-Item .env.example .env.local` |

3. `.env.local`을 메모장이나 편집기로 열어 2단계에서 확인한 값 세 개를 등호(=) 뒤에 붙여 넣습니다. 이 파일은 GitHub에 올라가지 않게 설정돼 있습니다.
4. 초기 데이터를 넣습니다. 상품 21건(카탈로그 20종과 세트), 약관 초안 6건, 공식 연락처 6건, 할 일 템플릿 9건, 감염병 초안 4건, 예시 시설 5건이 들어갑니다.

```bash
npm run seed
```

5. 앱을 켭니다.

```bash
npm run dev
```

6. 브라우저에서 `http://localhost:3000` 을 엽니다. 맨 위에 주황색 "예시 모드" 띠가 **없으면** 데이터 창고에 연결된 것입니다. 띠가 보이면 3번의 값이 비어 있는 것이니 다시 확인합니다.

끄려면 명령 창에서 `Ctrl + C`를 누릅니다.

코드를 고친 뒤에는 아래 검사를 돌려 봅니다. 넷 다 통과해야 올릴 수 있습니다.

```bash
npm run check
```

## 4단계. 인터넷에 올리기

Vercel이 내 GitHub 저장소를 가져가 인터넷 주소를 만들어 줍니다. 이후에는 코드를 GitHub에 올릴 때마다 자동으로 다시 배포됩니다.

1. <https://vercel.com/new> 에서 내 `petsafe365` 저장소 옆 **Import**를 누릅니다.
2. Framework가 **Next.js**로 잡혀 있는지 확인합니다. 1단계에서 폴더만 떼어 왔으므로 Root Directory는 건드리지 않습니다.
3. **Environment Variables**를 펼쳐 세 줄을 넣습니다.

| Key | Value |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | 2단계의 Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 2단계의 Publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | 2단계의 Secret key. 탈퇴 처리에 씁니다 |

4. **Deploy**를 누릅니다. 1~2분 뒤 `이름.vercel.app` 주소가 나옵니다.
5. 그 주소를 열어 주황색 "예시 모드" 띠가 없는지, 상품 사진이 보이는지 확인합니다.

환경변수를 나중에 고쳤다면 **Deployments → 맨 위 배포의 ⋯ → Redeploy**를 눌러야 반영됩니다.

내 도메인을 쓰려면 Vercel 프로젝트의 **Settings → Domains**에서 연결합니다. 도메인을 바꾸면 5단계의 주소 등록도 같이 바꿔야 합니다.

## 5단계. 로그인 설정과 관리자 지정

로그인은 비밀번호 없이 메일로 받은 링크를 누르는 방식입니다. 링크가 우리 앱으로 돌아오도록 주소를 등록해야 합니다.

1. Supabase → **Authentication → URL Configuration**을 엽니다.
2. **Site URL**에 4단계에서 받은 주소를 넣습니다. 예: `https://이름.vercel.app`
3. **Redirect URLs**에 두 줄을 추가하고 저장합니다.
    - `https://이름.vercel.app/auth/callback`
    - `http://localhost:3000/auth/callback` (내 컴퓨터에서 시험할 때)
4. 배포 주소의 **내 정보 → 로그인**에서 운영용 이메일로 한 번 로그인합니다. 메일이 안 보이면 스팸함을 확인합니다.
5. 내 컴퓨터의 `.env.local`에서 `ADMIN_BOOTSTRAP_EMAIL=` 뒤에 그 이메일을 적고 아래를 다시 실행합니다. "관리자 승격 완료"가 나오면 됩니다. 초기 데이터는 중복으로 들어가지 않습니다.

```bash
npm run seed
```

6. 앱에서 로그아웃했다가 다시 로그인하면 **내 정보**에 관리자 메뉴가 보입니다.

Supabase 기본 메일은 시간당 보낼 수 있는 수가 적습니다. 회원을 받기 전에 **Authentication → Emails → SMTP Settings**에서 자체 메일 발송 서비스를 연결해야 합니다. 정확한 한도는 Supabase 문서에서 확인합니다.

## 운영하면서 할 일

관리자로 로그인한 뒤 `/admin` 주소에서 처리합니다. 관리자가 바꾼 내용은 모두 감사로그에 남습니다.

| 화면 | 할 일 | 주기 |
| --- | --- | --- |
| 대시보드 | 처리할 신고·문의 건수 확인 | 매일 |
| 문서 버전 | 약관을 고칠 때 새 버전 등록 후 게시 | 변경 시 |
| 기능 플래그 | 결제·광고 등 스위치. 다음 장 참고 | 거의 안 만짐 |
| 감사로그 | 누가 무엇을 바꿨는지 확인 | 매주 |
| 콘텐츠·연락처·시설 | 안전 앱을 켰을 때만 사용 | 켠 뒤 |

화면이 없어 Supabase의 **Table Editor**에서 직접 입력하는 것도 있습니다.

- 상품 등록·수정은 `products` 표에서 합니다. 스마트스토어 링크는 `external_url` 칸에, 사진 경로는 `image_url` 칸에 넣습니다.
- 상품 사진 파일은 코드의 `public/products` 폴더에 상품코드 이름(예: `nlt-0039.jpg`)으로 넣고 GitHub에 올립니다.
- 시험 결과는 `product_lots` 표에 넣습니다. 시험일과 시험기관을 함께 넣어야 "통과"로 바꿀 수 있습니다.
- 출시 알림 신청자는 `waitlist` 표에서 확인합니다. 판매를 열면 알림 메일을 한 번 보내고 목록을 지웁니다. 화면에서 그렇게 약속했습니다.

회원의 반려동물 정보, 건강 기록, 문서는 관리자 화면에서 볼 수 없게 막혀 있습니다. Supabase 대시보드에서는 보이므로, 대시보드에 들어갈 수 있는 사람을 최소로 둡니다.

## 함부로 켜면 안 되는 스위치

법적 책임이 따르는 기능 여섯 가지는 모두 꺼진 상태로 넘겨드립니다. `/admin/flags`에서 사유를 적어야 켜지고, 켠 기록이 남습니다.

| 스위치 | 켜면 열리는 것 | 켜기 전에 끝내야 할 것 |
| --- | --- | --- |
| `paymentsEnabled` | 앱 안 결제 | 사업자등록, 통신판매업 신고, 결제대행사 계약·심사, 환불 정책 게시, 결제 연동 개발 |
| `partnerSubscriptionsEnabled` | 파트너 유료 구독 | 위 결제 조건, 파트너 계약서 |
| `insuranceReferralEnabled` | 보험 연계 | 보험 모집 관련 인가나 적법한 제휴, 전문가 검토 |
| `preciseLocationStorageEnabled` | 정밀 위치 저장 | 위치정보 처리 구조 확정, 별도 동의 화면 |
| `publicReviewsEnabled` | 공개 후기 | 게시물 운영정책, 권리 침해 신고 창구 |
| `adsEnabled` | 광고 | 월 이용자 5천 명, 광고 표시 정책 게시 |

가게가 지키는 약속이 있습니다. 화면에 그렇게 적어 두었습니다.

- 가짜 마감, 꾸며 낸 후기, 근거 없는 "무독성·친환경" 표현을 쓰지 않습니다.
- 시험 결과가 나오기 전에는 "불검출·통과" 표시를 하지 않습니다.
- 먹는 제품이 아니라는 점과 맞지 않는 아이를 숨기지 않습니다.
- 모든 광고에 "광고" 표시를 붙입니다.

## 아직 안 만들어진 것과 문제 해결

아래 기능은 없거나 자리만 있습니다. 있는 것처럼 안내하지 않도록 주의합니다.

| 기능 | 지금 상태 |
| --- | --- |
| 구매 | 버튼이 "판매 준비 중"으로 표시됨. 스마트스토어 링크를 넣으면 "스마트스토어에서 구매"로 바뀜 |
| 앱 안 결제 | 화면과 잠금만 있고 결제대행사 연동은 없음 |
| 상품 사진 | 공급사 카탈로그 사진(저해상도). 2개 세트는 그림 아이콘 |
| 구매 후기 | 없음. "준비 중"으로 표시됨 |
| 상품·출시 알림 관리 화면 | 없음. Supabase 표 편집기로 확인·입력 |
| 비회원 주문 | 막혀 있음. 주문은 로그인 필요 |
| 안전 앱 기능 | 꺼 둠. 켜도 지도 표시·가족 초대·알림은 없음 |

자주 만나는 문제와 해결법입니다.

| 증상 | 원인과 해결 |
| --- | --- |
| 맨 위에 주황색 "예시 모드" 띠가 보임 | Supabase 주소와 키가 비어 있음. Vercel 환경변수를 확인하고 Redeploy |
| 상품이 예시 3건만 보임 | 초기 데이터가 옛 버전. `npm run seed`를 다시 실행 |
| 상품 사진이 안 보임 | `public/products` 폴더의 파일 이름과 `image_url` 값이 다름 |
| 메일 링크를 눌러도 로그인이 안 됨 | 5단계의 Redirect URLs에 `/auth/callback` 주소가 빠짐 |
| 로그인 메일이 안 옴 | 스팸함 확인. 여러 번 시도했다면 발송 한도에 걸린 것이니 잠시 뒤 다시 시도 |
| 탈퇴가 실패함 | `SUPABASE_SERVICE_ROLE_KEY`가 Vercel에 없음 |
| 관리자 메뉴가 안 보임 | 5단계의 관리자 지정을 다시 하고, 로그아웃 후 재로그인 |
| `npm run seed`가 키가 필요하다고 함 | `.env.local`에 Supabase 주소와 Secret key가 비어 있음 |
| Vercel 빌드 실패 | 내 컴퓨터에서 `npm run check`를 돌려 같은 오류가 나는지 확인 |

이 인수인계서의 2~5단계는 대시보드 메뉴 이름을 기준으로 썼습니다. Supabase와 Vercel은 메뉴 이름을 종종 바꾸므로, 다르게 보이면 비슷한 이름을 찾아 주세요. 기술 사항의 기준 문서는 코드의 `README.md`입니다.
