# Claude Code 실행용 마스터 프롬프트

## 대표님이 사용하는 방법

1. 이 파일과 `PETSAFE365_CLAUDE_HANDOFF.md`를 같은 프로젝트 폴더 최상단에 넣는다.
2. 그 폴더를 Claude Code에서 연다.
3. 아래 `붙여 넣을 프롬프트` 전체를 복사해 Claude Code에 보낸다.
4. Claude가 도중에 멈추면 이 문서 뒤의 `계속 진행 프롬프트`를 보낸다.

## 붙여 넣을 프롬프트

```text
너는 펫안심365(PETSAFE 365)의 수석 풀스택 엔지니어이자 제품 디자이너다.

프로젝트 루트의 PETSAFE365_CLAUDE_HANDOFF.md를 처음부터 끝까지 빠짐없이 읽고, 그 문서를 제품·기능·데이터·법무·디자인·완료 기준의 단일 기준으로 사용하라. 라이브 시연 사이트는 방향 참고일 뿐이며, 인수인계서와 충돌하면 인수인계서가 우선이다.

목표는 예쁜 정적 홈페이지가 아니라 회원가입, 반려동물 등록, 오늘 할 일, 기록, 긴급 도움, 지도, 신고, 인수공통감염병 콘텐츠, 관리자 기능이 실제로 작동하는 모바일 우선 운영형 플랫폼이다.

반드시 지킬 작업 규칙:

1. 먼저 현재 저장소를 조사하라. 파일 구조, package.json, 기존 라우트, 자산 경로, 환경변수, git 상태, 작동 기능과 오류를 확인하고 짧은 조사 결과를 제시한 다음 곧바로 구현을 시작하라.
2. 사용자의 기존 파일과 변경사항을 보존하라. 파일, 이미지, 문서, 라우트 경로를 임의로 삭제·교체·이름 변경하지 마라. 기존 자산 경로를 유지하라.
3. 기존 프로젝트가 없거나 소스가 불완전하면 새 Next.js + TypeScript 프로젝트를 만들되, 인수인계서의 라우트와 디자인을 따른다.
4. 사용자가 코드를 직접 고치게 하지 마라. 필요한 파일 생성·수정, 명령 실행, 오류 해결, 테스트는 네가 수행하라.
5. 먼저 Phase 0을 완료하고 이어서 Phase 1을 끝까지 구현하라. 단순 계획만 쓰고 멈추지 마라.
6. Supabase용 실제 스키마, 마이그레이션, 인덱스, RLS 정책을 작성하라. 인증키가 없으면 .env.example과 설정 안내를 만들고 로컬 개발용 명확한 예시 모드를 제공하되, 예시 데이터를 실제 정보처럼 표시하지 마라.
7. 모든 버튼은 실제로 동작해야 한다. 아직 구현하지 않은 기능은 숨기거나 비활성화하고 ‘준비 중’이라고 표시하라. 빈 링크와 가짜 성공 메시지를 금지한다.
8. 의료 진단·약·용량·치료 결정을 제시하지 마라. 보험상품 추천·순위·가입 권유를 만들지 마라. 인수인계서의 고정 면책 문구를 적용하라.
9. 병원·카페·공원·신고 연락처를 지어내지 마라. 외부 API 키가 없을 때는 실제 업체처럼 보이지 않는 ‘예시 데이터’만 사용하고, 출처·최근 확인일·검증 상태 필드를 구현하라.
10. 정밀 위치 권한은 사용자가 ‘내 주변 찾기’를 눌렀을 때만 요청하고 기본 저장하지 마라.
11. 결제, 보험 추천·모집, 정밀 위치 저장, 공개 후기는 법무 기능 플래그 기본값을 false로 두어라.
12. 모바일 360px부터 데스크톱까지 반응형으로 만들고 키보드, 포커스, 폼 라벨, 색 대비를 확인하라.
13. 각 기능을 구현한 뒤 관련 테스트를 실행하고 실패를 고쳐라. 마지막에는 lint, typecheck, unit/integration test, production build, Playwright 핵심 흐름을 가능한 범위에서 모두 실행하라.
14. 비밀키를 코드나 커밋에 넣지 마라. 서버 전용 키를 클라이언트에 노출하지 마라.
15. 미완료 기능을 완료라고 보고하지 마라.

이번 작업에서 반드시 완성할 Phase 1 범위:

- 이메일 매직링크 인증, 로그아웃, 탈퇴 경로
- 반려견·반려묘 여러 마리 CRUD와 전환
- 오늘 할 일 생성·완료·미루기·메모와 영구 저장
- 기본 건강 타임라인과 비공개 문서 업로드 구조
- 긴급 도움 화면, 병원 전화·가까운 병원 찾기 연결
- 공식 연락처 데이터 모델과 분실·발견·유기·학대 신고 허브
- SFTS, 공수병, 개 브루셀라증, 톡소포자충증의 CMS 구조와 검수 가능한 초기 콘텐츠
- 보험 상품 메타정보와 3단계 약관 확인 구조; 상품 추천과 가입 기능은 제외
- 법무·신뢰센터와 약관·개인정보·위치·저작권 페이지, 동의 버전 기록
- 관리자 최소 CMS와 감사로그
- 홈, 온보딩, 오늘, 우리 아이, 긴급, 지도 진입, 건강, 인수공통감염병, 보험, 기록, 신고, 법무 화면
- 로딩·빈 상태·오류·권한 거부 상태
- README, .env.example, Supabase migrations, 테스트, docs 문서

지도 공공데이터는 Phase 1에서 어댑터 인터페이스와 실패/빈 상태까지 만들고, 시간이 허용되면 Phase 2의 Kakao 지도와 전국 동물병원 데이터 수집기까지 이어서 구현하라. API 키가 필요한 지점은 정확한 환경변수명과 발급처를 README에 기록하라.

작업 순서:
```

## 사이트가 겉모습만 있고 기능이 저장되지 않을 때: 기능화 프롬프트

```text
현재 화면은 프로토타입이다. 디자인을 다시 만드는 작업을 멈추고 실제 데이터 흐름을 구현하라.

다음 네 가지를 먼저 끝내라.
1. Supabase migrations와 RLS
2. 실제 인증 세션
3. 반려동물 CRUD
4. 오늘 할 일 CRUD와 새로고침·재로그인 후 상태 유지

각 화면에서 하드코딩된 상태와 localStorage 의존을 찾아 실제 DB 저장으로 교체하라. 단, 로그인 전 체험모드는 ‘예시 데이터’라고 명확히 표시하고 운영 데이터와 분리하라.

다른 사용자의 pet_id를 URL에 넣어도 접근할 수 없는지 통합 테스트를 작성하라. 완료 후 코드 변경 파일, DB 정책, 테스트 결과를 보고하고 인수인계서의 다음 미완료 기능으로 계속 진행하라.
```

## 지도·카페·공원까지 이어서 개발할 때: Phase 2 프롬프트

```text
PETSAFE365_CLAUDE_HANDOFF.md의 Phase 2를 구현하라. 먼저 Phase 1의 lint, typecheck, tests, production build가 통과하는지 확인하고 회귀가 있으면 고쳐라.

Kakao Map SDK/Local API, 전국 동물병원 인허가 데이터, 동물약국·보호센터·미용·위탁·장묘·운송 데이터, 한국관광공사 반려동물 동반여행 데이터를 위한 공급자별 어댑터를 만들어라. 원본 테이블과 정규화된 facilities를 분리하고, source_system + source_id upsert, EPSG:5174→WGS84 좌표변환, 폐업·휴업 이력, 마지막 동기화 시각, 중복병합 후보를 구현하라.

카페·공원 상세에는 실내/실외, 크기 제한, 이동장, 목줄, 예방접종 증명, 추가요금, 최근 확인일, 방문 전 전화 확인을 표시하라. 24시간·응급·동반 가능 여부를 추정하지 말고 확인되지 않았으면 ‘미확인’으로 표시하라.

API 키가 없으면 실제 업체를 지어내지 말고, 명확히 표시된 예시 fixture와 importer dry-run 테스트를 제공하라. 위치 권한은 버튼을 누를 때만 요청하고 정밀 위치를 저장하지 마라.

수집기 단위 테스트, 중복 upsert 통합 테스트, 위치 거부 E2E, 지도 빈 상태와 API 실패 상태를 검증하고 결과를 보고하라.
```

## 배포 직전 검증 프롬프트

```text
새 기능을 추가하지 말고 펫안심365의 배포 준비 상태를 검증하라.

1. git diff와 변경 파일을 검토해 사용자 파일·자산 경로가 훼손되지 않았는지 확인
2. 환경변수 누락과 비밀키 노출 검사
3. Supabase migration과 RLS 검사, 교차 사용자 접근 차단 테스트
4. lint, typecheck, unit/integration tests, production build, Playwright 핵심 흐름 실행
5. 모바일 360/390px, 태블릿, 데스크톱 레이아웃과 키보드 접근성 검사
6. 빈 링크·작동하지 않는 버튼·가짜 성공 메시지·실제처럼 보이는 예시 데이터 검사
7. 의료 진단 오인, 보험 추천 오인, 미확인 24시간 병원, 광고 미표시, 출처·검토일 누락 검사
8. 약관 버전 동의, 탈퇴·삭제, 파일 비공개 접근, 감사로그 검사
9. paymentsEnabled, partnerSubscriptionsEnabled, insuranceReferralEnabled, preciseLocationStorageEnabled, publicReviewsEnabled가 기본 false인지 확인

발견한 문제는 안전한 범위에서 직접 고치고 전체 검사를 다시 실행하라. 최종적으로 ‘통과’, ‘키 입력 후 통과 가능’, ‘법률/운영 결정 필요’, ‘미완료’ 네 범주로 보고하라. 미완료를 완료로 표현하지 마라.
```

## 클로드가 자꾸 파일 경로를 바꿀 때: 경로 보호 프롬프트

```text
즉시 파일명·폴더·자산 경로 변경을 멈춰라. 기존 경로는 외부 참조와 사용자 작업이 연결된 계약이다.

현재 git diff와 참조 검색을 실행해 네가 바꾼 경로를 모두 확인하라. 사용자가 명시적으로 요청하지 않은 rename, move, delete를 원래 경로로 복구하되 사용자 변경사항은 덮어쓰지 마라. 이후에는 기존 경로를 유지한 채 import와 코드만 최소 수정하라.

복구 후 깨진 import, route, asset URL을 검사하고 build와 관련 테스트를 실행하라. 어떤 경로를 복구했고 왜 깨졌는지 짧게 보고한 다음 원래 개발 작업을 계속하라.
```
