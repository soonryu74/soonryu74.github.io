기관 공표·지속가능성 기획안 (v1, 2026-10-04)

소유자 방향: “내가 그냥 무료로 만드는 이 앱 … 이걸 가장 잘 사용할 수 있는 기관 또는 단체 이름으로 공표하고 지속 가능성 있게 하는 게 좋을 듯해.”

1. 결론 먼저

  • 개인이 만든 무료 도구가 오래 쓰이려면 ① 매년 자료를 갱신할 책임자, ② 공신력을 빌려 줄 이름, ③ 개인이 손을 떼도 돌아가는 구조가 필요하다. 셋을 한 기관이 맡으면 가장 좋다.
  • 순서는 공동 공표 → 공동 운영 → 이관 3단계. 처음부터 넘기지 않고, 협약으로 이름을 함께 올린 뒤 운영 책임을 나눈다.
  • 1순위 후보 유형은 지역보건의료계획·통합건강증진사업을 지원하는 기관과 시도 공공보건의료지원단이다. 이 앱의 쓰임새(보건소별 현황 분석 → 우선 검토 항목 → 예방·관리 자료)가 이들 업무와 바로 맞물린다.
  • 협약(또는 서면 승인) 전에는 어떤 기관 이름·로고도 화면·문서에 쓰지 않는다. 이 문서의 기관명은 「검토할 후보 유형」일 뿐, 접촉하거나 합의한 사실이 아니다.
  • 지금 할 수 있는 준비: 라이선스 결정, 갱신 절차서, 저장소 분리 준비, 1쪽 제안서. 비용은 도메인 연 비용뿐이라 재정 부담이 거의 없다는 것이 가장 큰 설득 포인트다.

2. 누가 가장 잘 쓰나 — 후보 유형

이 앱이 이미 하는 일: 258개 보건소(지역사회건강조사 조사 단위)·시군구별 171개 지표의 위치·추세·격차, 「우선 검토 항목」, 예방·관리 지식베이스, 자료원·한계 공개, 영문 소개.

후보 유형 실재 기관 예 이 앱의 쓰임새 적합한 이유 접촉 경로 장점 유의점
A. 지역보건·건강증진사업 지원 기관 한국건강증진개발원 통합건강증진사업 계획·평가 지원 시 보건소별 현황 자료, 우수사례 연결 앱이 이미 우수사례집(KHEPI)·사업 영역을 연결 지역사업 지원 부서 공개 연락처, 세미나·포럼 전국 보건소와 연결, 공신력 큼 공공기관 절차(외부 저작물 수용 검토)에 시간
B. 시도 공공보건의료지원단 각 시도 공공보건의료지원단 시도 내 시군구·보건소 비교, 지역보건의료계획 현황 분석 시도 단위 분석이 본업, 한 시도에서 시작해 확산 가능 지원단 홈페이지 연락처, 시도 보건정책과 작게 시작(한 시도) 가능, 실사용 피드백 빠름 시도마다 이름을 나누면 전국판 정체성 흐려짐 → 「운영 협력」으로만
C. 지역사회건강조사 수행 체계 시도별 책임대학, 질병관리청 권역 질병대응센터 조사 결과 환류·해석 교육, 보건소 담당자 교육 자료 앱 지표의 중심이 지역사회건강조사, 구조가 수도권질병대응센터 CIAT를 참조 책임대학 연구진, 센터 공개 연락처 자료 해석 전문성, 매년 조사 일정과 갱신 일정이 일치 공식 통계 기관과의 혼동 방지(「공식 통계 아님」 문구 유지)
D. 관련 학회 한국건강형평성학회, 대한예방의학회, 한국보건교육건강증진학회 등 학술대회 시연, 교육용 도구, 외부 검토 연결 건강격차·지역보건이 학회 주제와 일치, 검토자 풀 학회 사무국, 학술대회 발표 중립성, 검토 의견을 받기 쉬움 운영 인력·예산이 적어 「갱신 책임」은 맡기 어려움 → 자문·검토 역할로

권장 조합: 운영·갱신은 A 또는 B, 검토·자문은 C·D. 한 곳에 모두 맡기기보다 「운영 협력 1곳 + 검토 기록 여러 건」이 현실적이다.

3. 공표 방식 3단계

단계 화면 표기(예시 — 협약 후에만) 하는 일 전제
① 공동 공표 크레딧 줄 「운영 협력: ○○ · 개발: 지음웍스」 기관이 이름을 함께 올리고 의견 창구·홍보 협력 협약서 또는 명칭 사용 승인 문서
② 공동 운영 「운영: ○○ · 개발: 지음웍스」 + 편집위원회 명단(동의자) 연 1회 자료 갱신 책임, 지표 추가·변경 심의, 외부 검토 요청 갱신 절차서 인수, 담당자 지정
③ 이관 「운영: ○○」(개발 기록은 연혁에 유지) 저장소를 기관 GitHub 조직으로 이전, 도메인 health-profile.kr 이전 라이선스 확정, 저장소 분리 완료
  • 각 단계에서 「공식」「인증」「공인」은 쓰지 않는다. 기관이 공식 서비스로 채택하면 그 기관의 표기 규정을 따른다.
  • 기관 로고는 사용 승인 문서가 있을 때만, 정해진 크기·색으로.

4. 지속가능성 장치

4.1 비용 구조

| 항목 | 현재 | 비고 | |—|—|—| | 호스팅 | GitHub Pages — 무료 | 정적 단일 HTML, 서버·DB 없음 | | 도메인 | health-profile.kr — 연 비용만 | 이관 시 기관 명의로 이전 | | API | KOSIS 공유서비스 — 무료(인증키) | 키는 저장소에 넣지 않음(.env) | | 인력 | 연 1회 갱신 수일 + 수시 수정 | 절차서로 줄임 |

| 시기 | 자료 | 스크립트 | |—|—|—| | 지역사회건강조사 결과 공표 후(통상 상반기) | 지역사회건강조사 지표 | kosis_fetch_core.py → build_dataset.py | | 사망원인통계 공표 후(통상 가을) | 사망률 | kosis_fetch_mort.py → build_mort.py | | 생명표·건강수명 자료 갱신 후 | 건강수명 | kosis_fetch_hle.py → build_hle.py → validate_hle.py | | 검진 통계 갱신 후 | 암검진·일반검진 | kosis_fetch_cancer.py·kosis_fetch_checkup.py → build_cancer.py·build_checkup.py | | 인구총조사(5년 주기) | 지역박탈지수 | kosis_fetch_census.py → build_deprivation.py | | 매 갱신 후 | 자료원·참고문헌·점검 | build_coverage.py → kosis_validate_all.py → build_dashboard.py → scripts/qa/equity_e2e.mjs |

정확한 공표 시기는 해마다 KOSIS·질병관리청 공표 일정으로 확인한다(docs/데이터_최신성_점검_v1.md). 이 표를 바탕으로 단계별 명령을 적은 「갱신 절차서」를 따로 만든다(다음 작업).

4.3 라이선스(소유자 결정 사항 — 아직 파일 추가 안 함)

  • 권고: 코드 MIT 또는 Apache-2.0, 문서·화면 문구 CC BY 4.0. 기관이 받아 고쳐 쓰고 이름을 넘겨받을 수 있으려면 라이선스가 먼저 정해져야 한다.
  • MIT는 가장 단순, Apache-2.0은 특허 조항이 있어 기관 법무 검토에 유리한 경우가 있다.
  • 결정 전까지 LICENSE 파일을 넣지 않는다(기본은 저작권 보유).

4.4 원자료 이용 조건

  • KOSIS: 출처 표시 조건으로 이용. 화면 각 수치에 원표 링크가 있다.
  • KHEPI 우수사례집 등 공공누리 제4유형 자료: 이름·쪽 번호만 연결(본문 복제 없음) — 지금 방식 유지.
  • 김동현 교수 DB 유래 지표: 원 xlsx는 저장소에 없음(비공개). 이관·공동 운영 전에 제공자에게 이용·재배포 범위를 서면으로 확인해야 한다.
  • 예방·관리 지식베이스(AI 수집·요약): 원문 링크·수집일 표시, 기관 이관 시 검수 책임 주체를 정한다.

4.5 「한 사람에게만 의존」 줄이기

  • 인수인계 문서: CLAUDE.md(현재 상태·결정 기록), docs/ 방법론 약 30건, 사용설명서(75쪽)·활용법(100쪽)·소개 영상.
  • 저장소 분리: 지금은 개인 사이트 저장소(soonryu74.github.io)의 한 폴더다. 이관하려면 health-dashboard/ 이력만 떼어 별도 저장소로 만든다(git subtree split 등). 거울 저장소(health-profile)는 빌드 산출물만 있다.
  • 테스트: npm test(계산 엔진 단위 시험), scripts/qa/equity_e2e.mjs(화면 회귀) — 받는 쪽이 고쳐도 깨짐을 바로 알 수 있다.

5. 제안 꾸러미

5.1 1쪽 제안서(문안)

지역 건강프로파일 대시보드(health-profile.kr) 운영 협력 제안

  • 무엇: 258개 보건소·시군구의 171개 건강지표를 전국 중앙값 대비 위치·추세·격차로 보여 주고, 지역마다 「먼저 검토할 항목」과 근거 자료를 연결하는 무료 웹 도구입니다. 로그인·개인정보 없음.
  • 현황: 개인(지음웍스)이 무료로 개발·공개 중. 정적 사이트라 운영비는 도메인 연 비용뿐입니다.
  • 제안: 귀 기관과 「운영 협력」으로 이름을 함께 올리고, 연 1회 자료 갱신과 지표 검토를 함께 맡아 주실 수 있는지 논의드리고 싶습니다.
  • 한계: 공식 통계가 아니며, 사업 투입 자료가 없어 성과 평가·인과 판단에는 쓰지 않습니다.
  • 시연: 아래 5.3 경로, 10분.

숫자(지표 수·지역 수·연도)는 보낼 때 화면의 값으로 다시 확인한다. 사용자 수·효과 등 확인되지 않은 실적은 쓰지 않는다.

5.2 협약(MOU) 체크리스트

  • 명칭·로고 사용 범위와 표기 위치(크레딧 줄·영문 소개)
  • 역할: 운영 협력 / 공동 운영 / 이관 중 어느 단계인지, 책임 범위(자료 갱신, 문의 응대, 검토)
  • 자료 갱신 주기·담당자
  • 개인정보 처리 없음 확인(로그인·입력·수집 없음)
  • 원자료 이용 조건(4.4) 확인, 김동현 DB 재배포 동의
  • 라이선스·저작권 귀속(코드·문서)
  • 비용(도메인)·명의
  • 면책 문구(공식 통계 아님, 의사결정 보조)
  • 해지·이름 삭제 절차, 이관 시 저장소·도메인 처리
  • 개발자 크레딧 유지 방식

5.3 시연 경로(10분)

  1. 홈 → ③ 「내 지역 건강격차 빠르게 보기」에서 지역 검색
  2. 지역 프로파일 맨 위 「우리 지역 우선 검토 항목」 → 「계산 방법」, ⓘ 지표 정보, 근거 자료
  3. 홈 ② 「258곳 전체 순위 · 2008년부터 재생」 → 지표 분석 순위·추세·격차
  4. 핫스팟 「복합 취약 신호」
  5. 자료원 탭 → 외부 검토 기록, 한계 공개
  6. 영문 소개 health-profile.kr/solve

6. 지킬 선

  • 협약·서면 승인 전 기관명·로고 표기 금지(화면·문서·제안서 공개본 모두).
  • 「공식」「인증」「공인」「승인」 표현 금지.
  • 사용자 수·정책 효과·파트너 등 확인되지 않은 실적을 쓰지 않는다.
  • 외부 검토 기록과 기관 협력은 따로 표시한다(개인 검토가 기관 보증처럼 읽히지 않게).

7. 결정이 필요한 것(소유자)

  1. 라이선스: 코드 MIT vs Apache-2.0, 문서 CC BY 4.0 여부.
  2. 첫 접촉 후보 유형: A(건강증진 지원 기관) vs B(한 시도 지원단부터).
  3. 이관까지 갈지, 「운영 협력」 단계에서 멈출지.
  4. 김동현 교수께 DB 유래 지표의 이용·재배포 범위 확인 요청 시점.
  5. 저장소 분리 시점(협약 전 미리 vs 이관 확정 후).
