## Q0. 앵커: 카카오 이모티콘 제작 규격 (사이즈·개수·용량)

### Takeaway
공식 가이드 페이지(emoticonstudio.kakao.com)는 JS 렌더링이라 본 조사에서 본문을 직접 긁지 못했다. 제3자(숨고·크몽 등)가 반복 인용하는 규격은 "멈춰있는 32종 360×360 PNG 150KB 이하 / 움직이는 24종(PNG 21+GIF 3) 360×360 2MB 이하 24프레임 이하 / 큰이모티콘 16종(PNG 13+GIF 3) 540×540·540×300·300×540 2MB 이하"이며, 2025-11-26 개편으로 "제작 단계와 규격이 간소화"됐다고만 발표되어 **제출 직전 반드시 공식 가이드에서 재확인**해야 한다.

### Cited Findings
- 멈춰있는 이모티콘: 총 32종(PNG, 투명 배경), 360×360px, 개당 150KB 이하, 75dpi — [숨고 안내(제3자)](https://soomgo.com/questions/3402)
- 움직이는 이모티콘: 총 24종(PNG 21종 + GIF 3종), 360×360px, 개당 2MB 이하, 72dpi, "24개 이미지 중 3개의 이미지는 24프레임 이하의 GIF 제작 요망" — [숨고 안내(제3자)](https://soomgo.com/questions/3402)
- 큰이모티콘: 총 16종(PNG 13종 + GIF 3종), 540×540 / 540×300 / 300×540px 중 선택, 개당 2MB 이하, 72dpi — [숨고 안내(제3자)](https://soomgo.com/a.%EA%B2%BD%EA%B8%B0-%EC%96%91%ED%8F%89%EA%B5%B0/%EC%BA%90%EB%A6%AD%ED%84%B0-%EC%9D%B4%EB%AA%A8%ED%8B%B0%EC%BD%98-%EC%A0%9C%EC%9E%91)
- 2025-11-26 카카오 이모티콘 스튜디오 전면 개편: 파일 일괄 업로드·순서 편집·미리보기, 임시 저장, 제출 후 24시간 내 취소, "제작 단계와 규격도 간소화", 대시보드·알림·'내 작업실' 메뉴, 미니 이모티콘 정식 도입 — [카카오 보도자료](https://www.kakaocorp.com/page/detail/11821?lang=ENG); [파이낸셜뉴스](https://www.fnnews.com/news/202511260957056157); [전자신문](https://www.etnews.com/20251126000203)
- 카카오 이모티콘 공식 브런치(2025-12-01): "제안에 필요한 항목을 더 간단하게 줄이고, 제작 단계도 축소했어요", 제출 전 채팅방 미리보기 제공. 구체 규격 수치는 글에 없음 — [brunch @kakaoemoticon](https://brunch.co.kr/@kakaoemoticon/111)

### Inferences
- 자동화 스크립트는 "360×360 PNG, 150KB(정지)/2MB(움직임) 상한, GIF ≤24프레임, 큰이모티콘 540 계열" 세 프로파일을 변수로 두고 짜면 규격이 미세 변경되어도 숫자만 바꾸면 된다.
- 제3자 자료가 정지형 75dpi / 움직이는형 72dpi로 엇갈리는데, PNG는 dpi 메타데이터가 심사에 영향을 주지 않을 가능성이 높지만 확인 불가이므로 72로 통일 저장하는 것이 무난하다.

### Gaps
- emoticonstudio.kakao.com 공식 가이드 본문(2025-11 개편 이후 최신 규격 수치)을 직접 확인하지 못했다. 보도자료의 "규격 간소화"가 무엇을 바꿨는지(예: 프레임 수·용량) 1차 출처 없음.

## Q2. 캐릭터 일관성 기법 (참조 이미지·캐릭터 시트·프롬프트 템플릿·시드·그리드)

### Takeaway
2026년 주류 방법은 "①캐릭터 시트(정면·측면·3/4 + 색상 코드) 1장을 먼저 확정 → ②이를 참조 이미지로 매번 업로드 → ③4×4 또는 3×3 표정 그리드로 한 번에 생성 → ④분할"이다. Nano Banana 2/Pro와 gpt-image-2는 참조 이미지 업로드 방식, Midjourney는 `--oref`(1장) + `--ow`로 강도 조절, Ideogram은 Character Reference 1장 방식이다.

## Q3. 투명 배경: 생성기 알파 출력 여부와 배경 제거 도구

### Takeaway
진짜 알파 PNG를 내는 생성기는 gpt-image-2 API(`background: "transparent"`, 프리뷰)뿐이고, Nano Banana 계열은 불투명 출력, Midjourney도 투명 미지원(공식 확인 못함)이다. 따라서 **흰 배경(또는 캐릭터에 없는 단색 배경)으로 생성 → rembg(무료·로컬·MIT) 일괄 처리 → Photopea/Krita에서 가장자리 손보기**를 표준 파이프라인으로 둔다.

### Cited Findings
- gpt-image-2 투명: `background: "transparent"`, png/webp만, 프리뷰(종료일·가용성 약속 없음), 알파 품질·가장자리 처리는 문서화 안 됨 — [ecorpit](https://ecorpit.com/gpt-image-2-transparent-background-preview-no-token-table-2026/)
- Nano Banana 2 출력 "항상 불투명", 투명도 벤치마크 0.0/5 — [moda.app](https://moda.app/resources/models/nano-banana-2); [IMG.LY](https://img.ly/ai-benchmarks/models/nano-banana-2.md)
- rembg(MIT 라이선스): 설치 `pip install "rembg[cpu,cli]"`(NVIDIA는 `[gpu,cli]`), Python 3.11 이상 3.14 미만. CLI 단일 `rembg i in.png out.png`, 폴더 일괄 `rembg p 입력폴더 출력폴더`, 감시 모드 `-w`, 모델 지정 `-m`. 모델: `u2net`, `u2netp`, `isnet-anime`(애니 캐릭터), `isnet-general-use`, `birefnet-general(-lite)`, 기본 `bria-rmbg`(약 1.02GB, **RMBG-2.0 가중치는 BRIA 라이선스로 상업 이용 시 유료 계약 필요**). 엣지 옵션: `-dc`(색 번짐 제거, 저렴), `-a`(알파 매팅, 느리고 수렴 실패 가능), `-vm`(ViTMatte, 추가 110MB+ 다운로드). Python API `from rembg import remove, new_session` — [GitHub danielgatis/rembg](https://github.com/danielgatis/rembg)
- Ideogram 배경 제거 API $0.01/장 — [eesel(제3자)](https://eesel.ai/blog/ideogram-pricing)
- remove.bg 가격은 출처마다 상이(무료/€3 종량/Lite €8.1~$9/월 40크레딧/Pro $29~39/월 200크레딧), 2026-07-20 요금제 1개 삭제 기록 — [Capterra](https://www.capterra.com/p/10014638/RemoveBG/pricing/); [toolradar](https://toolradar.com/tools/remove-bg/pricing); [costbench](https://costbench.com/changelog/remove-bg-plan-removed-2026-07/)

### Inferences
- 상업 판매가 목적이므로 rembg 기본 모델 `bria-rmbg`는 피하고 `-m isnet-anime` 또는 `-m birefnet-general`을 명시하는 것이 라이선스상 안전(각 모델 가중치 라이선스 별도 확인 권고는 README 자체 문구).
- 32장×150KB 제한이면 remove.bg 유료(크레딧 40~200개)도 가능하지만, 재생성·재시도까지 감안하면 무료 rembg 로컬이 경제적.
- 흰 배경 생성 시 캐릭터 자체가 흰색(예: 흰 고양이)이면 분리가 어려우므로 생성 단계에서 "연두색/마젠타 단색 배경"을 지정하고 제거하는 편이 낫다(실무 추론).

### Gaps
- Midjourney V7의 투명 배경 공식 지원 여부 1차 출처 미확인(일반적으로 미지원으로 알려짐).
- Canva 배경 제거(Pro 기능)의 2026년 한국 요금 미확인. Photoshop 2026 요금(Adobe) 미조사.

## Q6. 자동화: 리사이즈·배경 제거·용량 검사·파일명·패키징 스크립트 (Mac / Windows)

### Takeaway
Python 3.11~3.13 + Pillow + rembg 하나로 "그리드 분할 → 배경 제거 → 360/540 리사이즈 → 150KB/2MB 검사 → 01~32 번호 매기기 → GIF ≤24프레임 조립"을 한 번에 돌릴 수 있다. 아래는 조사 결과(rembg README, 제3자 규격)를 반영한 **스크립트 개요**이며 명령 구문은 Mac(zsh)·Windows(PowerShell)를 나란히 적었다. (스크립트 자체는 본 조사자가 작성한 초안이며 실제 실행 검증은 하지 않았다.)

### Cited Findings
- rembg 설치·CLI·Python API·모델·엣지 옵션 — [GitHub rembg](https://github.com/danielgatis/rembg) (Q3 참고)
- Pillow APNG/GIF 저장(`save_all=True`, `append_images`, `duration`, `loop`, `disposal`) — [Pillow 공식 문서: Image file formats](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html) (본 세션에서 직접 fetch하지 않음, 표준 문서 URL)
- ImageMagick 7 명령어는 `magick` 단일 실행파일 — [ImageMagick 공식 문서](https://imagemagick.org/script/command-line-processing.php) (본 세션에서 직접 fetch하지 않음)
- ffmpeg로 영상에서 프레임 PNG 추출 권장 — [Sorceress](https://sorceress.games/blog/pick-an-ai-animation-image-generator-frame-loop-test)
- 규격 상수(360×360, 150KB, 2MB, 24프레임, 540계열) — [숨고(제3자)](https://soomgo.com/questions/3402)

### 설치 (한 번만)

| 단계 | Mac (Terminal, zsh) | Windows (PowerShell) |
|---|---|---|
| Python 설치 | `brew install python@3.12` (Homebrew 필요) 또는 python.org 설치 | python.org에서 3.12 설치(“Add python.exe to PATH” 체크) 또는 `winget install Python.Python.3.12` |
| 가상환경 | `python3 -m venv ~/emoji-env && source ~/emoji-env/bin/activate` | `py -3.12 -m venv $HOME\emoji-env; & $HOME\emoji-env\Scripts\Activate.ps1` (실행 정책 오류 시 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`) |

### 핵심 스크립트 개요 (`make_emoticon.py`, Mac/Win 공통)
```python
# python -I make_emoticon.py  --  Pillow + rembg
from pathlib import Path
from PIL import Image
from rembg import remove, new_session

SIZE_STILL = 360        # 멈춰있는/움직이는 이모티콘 (제3자 규격)
SIZE_BIG   = 540        # 큰이모티콘 (540x540 / 540x300 / 300x540)
LIMIT_STILL = 150 * 1024          # 150KB
LIMIT_ANIM  = 2 * 1024 * 1024     # 2MB
MAX_FRAMES  = 24
ROOT = Path(__file__).parent
SESSION = new_session("isnet-anime")   # bria-rmbg(기본)는 상업용 유료 라이선스 → 회피

def split_grid(src, rows=4, cols=4, out_dir=ROOT/"01_split", margin=0):
    """4x4 표정 그리드 한 장을 16장으로 자른다."""
    im = Image.open(src).convert("RGBA")
    w, h = im.size; cw, ch = w // cols, h // rows
    out_dir.mkdir(exist_ok=True)
    n = 0
    for r in range(rows):
        for c in range(cols):
            box = (c*cw+margin, r*ch+margin, (c+1)*cw-margin, (r+1)*ch-margin)
            n += 1
            im.crop(box).save(out_dir / f"{src.stem}_{n:02d}.png")

def remove_bg(in_dir=ROOT/"01_split", out_dir=ROOT/"02_nobg"):
    out_dir.mkdir(exist_ok=True)
    for p in sorted(in_dir.glob("*.png")):
        with Image.open(p) as im:
            remove(im, session=SESSION).save(out_dir / p.name)   # 모델 1회 로드

def fit_square(im, size):
    """캐릭터를 정사각형 투명 캔버스 중앙에 맞춘다(비율 유지, 여백 8%)."""
    im = im.convert("RGBA"); bbox = im.getbbox()
    if bbox: im = im.crop(bbox)
    im.thumbnail((int(size*0.92), int(size*0.92)), Image.LANCZOS)
    canvas = Image.new("RGBA", (size, size), (0, 0, 0, 0))
    canvas.paste(im, ((size-im.width)//2, (size-im.height)//2), im)
    return canvas

def finalize(in_dir=ROOT/"02_nobg", out_dir=ROOT/"03_final", size=SIZE_STILL, prefix=""):
    out_dir.mkdir(exist_ok=True)
    for i, p in enumerate(sorted(in_dir.glob("*.png")), start=1):
        dst = out_dir / f"{prefix}{i:02d}.png"           # 01.png ~ 32.png
        canvas = fit_square(Image.open(p), size)
        canvas.save(dst, optimize=True)
        if dst.stat().st_size > LIMIT_STILL:              # 150KB 초과 → 팔레트 감량
            canvas.quantize(colors=128, method=Image.Quantize.FASTOCTREE).save(dst, optimize=True)
        print(f"{dst.name}: {dst.stat().st_size/1024:.1f} KB")

def build_gif(frame_dir, out_path, fps=12, size=SIZE_STILL):
    frames = [fit_square(Image.open(p), size) for p in sorted(Path(frame_dir).glob("*.png"))][:MAX_FRAMES]
    # GIF는 1비트 투명만 지원 → 반투명 픽셀을 완전 투명/불투명으로 정리
    pal = []
    for f in frames:
        a = f.getchannel("A").point(lambda v: 255 if v > 127 else 0)
        f.putalpha(a); pal.append(f.convert("P", palette=Image.ADAPTIVE, colors=255))
    pal[0].save(out_path, save_all=True, append_images=pal[1:], duration=int(1000/fps),
                loop=0, disposal=2, transparency=0, optimize=False)
    assert Path(out_path).stat().st_size <= LIMIT_ANIM, "2MB 초과"
    print(out_path, len(frames), "frames")

def check(out_dir=ROOT/"03_final", expect=32, size=SIZE_STILL, limit=LIMIT_STILL):
    files = sorted(out_dir.glob("*.png")); bad = []
    for p in files:
        with Image.open(p) as im:
            if im.size != (size, size) or im.mode != "RGBA": bad.append((p.name, im.size, im.mode))
        if p.stat().st_size > limit: bad.append((p.name, "size", p.stat().st_size))
    print(f"{len(files)}/{expect} files, problems: {bad}")

if __name__ == "__main__":
    for g in (ROOT/"00_raw").glob("grid_*.png"): split_grid(g)
    remove_bg(); finalize(); check()
    for d in sorted((ROOT/"04_anim_frames").glob("anim*")):
        build_gif(d, ROOT/"05_gif"/f"{d.name}.gif")
```
