Care Gap 탐지 방법

CareGap은 LLM에게 판단을 맡기지 않는다. 판단은 공개된 규칙 파일과 결정적(deterministic) 계산으로만 한다.

사용자 입력(프로필·걱정·이용 서비스·일정)
      │  app/src/engine/facts.ts — 일정 → 분 단위(7×1440) 덮임표 → '사실(facts)' 계산
      ▼
사실 30여 개 (예: time.nightAloneHours = 105, med.coveredDays = 0)
      │  app/src/engine/evaluate.ts — 규칙(all/any 조건 트리) 평가 + 조건별 근거 기록
      ▼
11개 영역 × {needs_confirmation 확인 필요 | confirmed_by_input 입력으로 확인됨 | covered_or_no_gap_detected 현재 입력상 공백 발견 안 됨} + 설명

1. 일정 → 시간 계산

  • 일정은 요일·시작·끝·종류. 끝이 시작보다 이르면 다음 날로 이어지는 일정(예: 일 22:00–07:00 → 일 22–24 + 월 00–07).
  • 각 종류는 service_types.json에 presence(그 시간에 사람이 곁에 있는가) 와 functions(맡는 돌봄 기능) 로 정의.
종류 presence 기능
방문요양 예 식사·위생·이동
방문간호 예 복약
방문목욕 예 위생
주야간보호 예 식사·위생·이동·인지·어울림
가족돌봄·방문 예 식사·이동·병원동행
병원동행 예 병원·이동
인지 프로그램 / 복지관 예 인지·어울림 / 어울림
식사지원(배달) 아니오 식사
복약확인 아니오 복약
병원 진료(일정) 아니오 — (동행 여부는 따로 판단)
응급안전서비스 아니오(상시 장비) 응급

2. 시간 창(설계값)

| 창 | 값 | 이유 | |—|—|—| | 저녁·야간 | 18:00–09:00 (주 105시간) | 방문형 서비스가 대부분 낮에 끝나는 현실 반영, 요구사항 예시와 일치 | | 낮 | 09:00–18:00 (주 63시간) | 나머지 | | 끼니 | 아침 07–09, 점심 11:30–13:30, 저녁 17:30–19:30 | 일반적 식사 시간대. 식사 기능 일정과 30분 이상 겹치면 그 끼니는 덮인 것으로 봄 | | 가족 부담 | 주 20시간 이상 또는 가족만 돌보는 요일 3일 이상 | 설계값(임상 기준 아님). 향후 사용자 연구로 조정 |

“혼자 계신 시간”은 혼자 사신다고 입력한 경우에만 계산한다(동거 가족이 있으면 0).

3. 규칙 (27개, 11개 영역)

| 영역 | 확인 필요 조건(요약) | 입력으로 확인됨 조건 | |—|—|—| | 식사 | 식사 거름 걱정 ∧ 덮이지 않은 끼니 > 0 | 걱정 ∧ 21끼 모두 덮임 | | 복약 | 복약 잊음 ∧ (복약확인 선택했지만 시간 없음 / 복약 일정 0일 / 1~6일) | 걱정 ∧ 7일 모두 | | 이동 | 이동 어려움 ∧ 독거 ∧ 사람이 오지 않는 요일 > 0 | 걱정 ∧ 그런 요일 0 | | 개인위생 | 이동 어려움 ∧ 위생 지원 요일 0 | 걱정 ∧ 위생 지원 있음 | | 병원 이동 | 동행 없는 진료 일정 > 0 ∧ (독거 ∨ 이동 어려움 ∨ 낙상) / 잦은 병원 ∧ 진료·동행 계획 없음 | 진료 일정 모두 동행 있음 | | 인지·기억 | 기억력 걱정 ∧ 인지 관련 일정 0 | 걱정 ∧ 일정 있음 | | 낙상 안전 | 최근 낙상 ∧ 낮 혼자 시간 > 0 | 낙상 ∧ 낮 혼자 시간 0 | | 야간 안전 | 최근 낙상 ∧ 야간 혼자 시간 > 0 / 밤 걱정 ∧ 야간 미덮임 > 0 | (낙상 ∨ 밤 걱정) ∧ 야간 미덮임 0 | | 응급대응 | 응급 걱정 ∧ 응급안전서비스 없음 / 독거 ∧ 낙상 ∧ 서비스 없음 | 응급안전서비스 이용 | | 사회적 교류 | 고립 걱정 ∧ 어울림 일정 0 | 걱정 ∧ 일정 있음 | | 가족 돌봄 부담 | 가족 시간 ≥ 20 / 가족만 돌보는 요일 ≥ 3 | — |

원칙: 사용자가 입력하지 않은 걱정은 공백으로 만들지 않는다(테스트 CASE 3). 걱정이 없는 영역은 “현재 입력상 공백 발견 안 됨”.

4. 결과 표현 원칙

  • “위험 n개” 대신 “확인이 필요한 돌봄 영역 n개”.
  • “낙상 고위험군입니다” 같은 단정 금지 — 자동 테스트가 규칙 문구에서 고위험, 위험군, 진단합니다, 예측합니다, 판정합니다, 처방합니다, 추천합니다를 검사한다.
  • 상태는 색 + 기호(!, ✓, –) + 글자로 동시에 표시.

5. 설명(Explainability)

각 결과의 “왜 이 결과가 나왔나요?”는 실제로 일치한 규칙의 조건별 값을 그대로 보여준다.

최근 넘어진 적이 있다 = 예
저녁·야간(18:00–09:00) 혼자 계신 시간 = 주 105시간
        ↓  night.fall_alone (두 조건 모두 충족)
야간 안전 확인 필요

일치한 규칙이 없으면 규칙별로 어떤 조건이 충족되지 않았는지 보여준다.

6. AI의 역할(선택 기능)

자연어 → 걱정 체크 후보만 만든다. 사용자가 “맞아요”를 눌러야 반영된다. 기본은 브라우저 안 키워드 규칙(engine/nlp.ts)이며, VITE_AI_ENDPOINT(사용자 소유 서버리스 프록시)가 있을 때만 외부 AI를 쓴다. AI는 판정에 관여하지 않는다.

7. 규칙 바꾸는 법

app/src/data/care_gap_rules.json만 고치면 된다. npm test의 무결성 테스트가 없는 사실(fact)·영역 참조, 금지 표현을 잡아낸다.

8. 규칙 메타데이터 (MASTER SPEC §8)

규칙마다 다음을 가진다(자동 테스트로 누락 검사): id(고정 ID) · version · when(입력 조건 트리) · domain · result(상태) · reason(한국어 설명 템플릿) · serviceCategories(알아볼 서비스 범주, 안내 목록 ID와 일치 검사) · rationale(근거·설계 메모). 규칙 파일 전체 버전: 2026-10-05.2.

9. 결과 카드 구성

영역 · 상태(색+기호+글자) · 설명 · “왜 이 결과가 나왔나요?” · 현재 관련 일정(영역 기능과 관련된 등록 일정, 없으면 “등록된 관련 일정 없음”) · 확인해 볼 것 · 관련 서비스 찾아보기.

10. 참고 정보

‘참고 정보’(예: 고혈압·당뇨)는 화면에 보관만 하고 규칙에 쓰지 않는다. 값이 바뀌어도 결과가 같다는 것을 자동 테스트로 확인한다.
